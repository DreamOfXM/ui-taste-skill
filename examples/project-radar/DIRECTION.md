# 产品雷达：公开浏览页实测

本轮用户反馈：旧版和 r12 都更像统计表，缺乏对外产品的完成度。这里验证一条完整的“发现 → 理解 → 查看证据 → 收藏”路径，不替换原项目或更改数据采集逻辑。

## 用户与边界

从没见过采集后台、希望寻找商业机会的独立开发者。首要任务是理解一个产品解决什么问题、可能怎样变现、有哪些关注线索及待验证项，再判断是否值得深入研究。保留“赚钱项目雷达”的目的，不把对外展示误解成转型为泛化产品目录。保留原始项目、证据来源和采集时间；支付入口不等于交易，星标不等于客户，种子列表位置不用于证明需求。

这次面向陌生访客，与 r12 的“本人晨盘一次读完”不同。旧墨白约定属于前一个表面；本独立实验使用炭黑/米白主题及少量青绿色视觉素材，仍保持证据语义清楚。不改原站 token，不宣称用户已认可本方案。

## 内容和视觉决定

把“项目”作为主角：名称、完整中文用途、为什么值得研究、证据和未知项。首屏精选 Shaders，因为原记录同时有清楚的技术用途、GitHub 关注和支付入口；这不是收益排名或赚钱承诺。

主屏依次为商业线索的价值介绍、一个完整项目及商业线索筛选入口、少量按用途选取的项目，再进入可搜索的全量目录。详情分别呈现公开关注、最近两次指标记录、支付/定价/广告/打赏机制与待验证项，避免只保留支付标签。数据覆盖统计移至方法说明。原有复杂赛道榜、商店榜和复访模块不在这条原型路径范围内，不宣称已完成整站迁移。

视觉主张：让项目的用途先被看见。Shaders 用自绘曲线表达实时图形的主题，明确标作概念示意，不冒充产品截图；其余对象用文字与各自的功能符号识别，不为每条记录捏造图片。标题、说明、证据采用不同密度，避免整页等权卡片。

交互：搜索、收费路径筛选、来源分类、分页、项目详情、来源跳转、浏览器收藏、明暗主题。收藏只保存在当前浏览器；演示真实数据快照日期，不能说“实时”。
