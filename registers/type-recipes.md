# 排印配方货架（type recipes）

**选读：定排印时取一套配方。** 这是第三维：字体、行距、字距、线的性格。与之正交的第四维是 `surface-recipes.md`（表面材质），两者一起交给用户选；本文件只管文字与节奏，不碰任何色值。

## 为什么会有这个文件

0.2.3 及之前，六个 register 都只描述「线 / 圆角 / 密度 / 色块」，`tokens/scale.md` 给的是**唯一一套**间距与行高表，`SKILL.md` 又写「同一维度只允许一条有效行」、多稿规则把「换圆角」判为表面轴。三处叠加的后果是：**不管什么产品、什么场合，产出的都是同一副脸**——系统无衬线、等宽数字、0/2px 圆角、1px 通高线、1.6 行高、38/24/16/14/12/11 六档字号。整齐、干净、可辩护，但没有美感。

用户原话：「感觉是挺整齐挺干净，但是没有美感……每次做出的页面都是一样的感觉，都是棱角分明……我们要的不是棱角分明，而是在什么场合、什么产品，它应该展示什么样的文字。至少要有组合或者选择。」

**根因不是选错了寄存器，是排印这一维根本不在取值记录里。** 字体族没有一行、行距没有一行、字距没有一行、线的性格没有一行。没有行的维度，模型只能拿默认值填，然后被「一致性」纪律锁死。

## 三条判据

1. **一页只用一套配方。** 混两套字体系统、两种行距节奏，正是 AI 味的来源；一致性纪律仍然成立。
2. **跨场合必须允许换配方。** 「单页内同一维度只允许一条有效行」不等于「一个 skill 一辈子只准有一种排印」。换配方要写进工作记录，依据是 brief 字段一（受众×场合）、字段二（任务时长）、字段四（信任物类型），不是「换个字体试试」。
3. **每条配方标注证据级别。** R2 = DOM 实测可复核；R1 = 截图只支撑定性；R0 = 通用排印知识，**未实测，属假设，不得伪装成结论**。数值只从 R2 来。

## 场合 → 配方映射（先查这张表，再选）

| brief 字段一 / 二 / 四 | 配方 | 关键理由 |
|---|---|---|
| 带戒心的技术受众 · 20 秒扫读 · 信任物是可核对的数据 | **P1 图纸** | 数字要逐位对齐，线要比留白更明确 |
| 长阅读 · 观点/品牌叙事 · 信任物是文字本身 | **P2 书卷** | 栏宽与行距决定能不能读下去，不是字号 |
| 消费级 · 低压力 · 信任物是氛围与完整度 | **P3 柔光** | 面代替线，曲率统一，减少审视感 |
| 开发者后台 · 高密度 · 信任物是原始记录 | **P4 终端** | 等宽与 1.4 行距换密度，牺牲长文可读性 |
| 转化/活动 · 情绪驱动 · 信任物是社会证明 | **P5 暖商业** | 字距与圆角换亲和力，与「讲事实」冲突 |
| 作品集/宣言 · 注意力争夺 · 信任物是作者态度 | **P6 粗野** | 字号跳跃、无中间档，代价是可扫读差 |

**冲突时以「品类」为先，受众×任务时长用来在同一品类内部选子型。** 0.2.5 写的「不以产品品类为准」已在 0.2.6 撤销：品类默认家族（`category-prototypes.md`）先给定字体族、字号阶梯、行距与字重，本表负责把这些落到一套可执行的排印参数上。同一个磁盘工具，官网给极客看用 P1（C1a 深色仪表），写给普通用户的介绍长文用 P2（C1b 浅色平台）——**品类没变，变的是子型**；从工具页换成美妆页，字体族与字重必须整套换掉（美妆 400 字重 + 衬线标题 + 0 圆角），不是把 P1 的 16px 套过去。

## 六套配方

### P1 · 图纸 / 仪表（instrument）

| 维度 | 取值 |
|---|---|
| 字体族 | 中文 `-apple-system, "PingFang SC", "Noto Sans SC"`；数字 `"SF Mono", ui-monospace` + `tabular-nums` |
| 字号节奏 | 38 / 24 / 16 / 14 / 12 / 11（≤6 档） |
| 行距 | display 1.10 / 正文 1.60 / 标签 1.40 |
| 字距 | 中文 0；标签 `.04em` |
| 线 / 面 | **1px 通高实线**承担分块；面积极少，不用阴影 |
| 曲率 | 0 / 2 |
| 密度 | 高 |

- **适用**：开发者工具、监控面板、需要「可核对」的产品。
- **不适用**：情感安抚、儿童、消费级转化、长文阅读。
- **换来**：数字逐位可比、边界不含糊、20 秒能扫完。
- **放弃**：亲密感与柔和；中文全篇无衬线会显得方正、冷。
- **证据**：R2（Linear 1px 通高竖线 551px、列宽 336×4、padding `0 32`；DiskWise 现任官网 `PingFang SC`、radius 0px、页高 5401）。

### P2 · 书卷 / 编辑（editorial-type）

| 维度 | 取值 |
|---|---|
| 字体族 | 标题 `"Songti SC", "Noto Serif SC", Georgia, serif`；正文系统无衬线（**中文衬线只用于标题与引文，不用于正文**） |
| 字号节奏 | 40 / 24 / 16 / 13（标题与正文 ≥3:1） |
| 行距 | 正文 **1.80–1.90** / 标题 1.25 / 引文 1.75 |
| 字距 | 中文 `.02em`；西文标题 `-.01em` |
| 线 / 面 | 0.5–1px 细线 + 大留白；单栏 30–36 中文字 |
| 曲率 | 0 / 2 |
| 密度 | 低 |

- **适用**：长文、观点型落地页、文档、品牌叙事、需要「可信」而非「亲切」。
- **不适用**：20 秒扫读任务、高密度后台、移动端单手。
- **换来**：文字本身有气质，长时间阅读不累；标题有笔形，不再「方方正正」。
- **放弃**：转化速度（CTA 会被推到第二屏）、扫读效率；中文衬线在低分屏上易糊。
- **证据**：R0（中文排印通用知识，**未做 DOM 实测，属假设**）+ `registers/editorial.md` 行高 1.65 与栏宽 60–72 字符。注意本配方把行高提到 1.80–1.90，与 register 的 1.65 **不一致时以本配方为准并记录**。

### P3 · 柔光 / 产品（soft-product-type）

| 维度 | 取值 |
|---|---|
| 字体族 | 系统无衬线全站；字重 400 起，不用 600 做长标题 |
| 字号节奏 | 44 / 26 / 16 / 14（4 档） |
| 行距 | 正文 1.55 / 标题 1.20 |
| 字距 | 西文 `-.01em`，中文 0（中文负字距会糊） |
| 线 / 面 | **用面（底色差、柔和阴影）代替线**；一页只用一档曲率 |
| 曲率 | 12 或 16（全站唯一一档）+ 999 |
| 密度 | 中 |

- **适用**：消费级、低压力、需要情感安抚、成品展示为主。
- **不适用**：数据核对、高密度表格、「讲事实」的极客受众。
- **换来**：不审视、不紧绷，截图与界面能融成一张图。
- **放弃**：精度感；数字不显眼，可核对性下降。
- **证据**：R2（Ramp 价格卡 radius 8px、推荐档 border 3px vs 1px、padding `40px 32px`）；12/16 一档来自 `registers/soft-product.md`，属 R0 未实测。

### P4 · 终端 / 高密度（console-type）

| 维度 | 取值 |
|---|---|
| 字体族 | 等宽全站 `"SF Mono", ui-monospace, Menlo, monospace`（中文回退 `PingFang SC`） |
| 字号节奏 | 20 / 14 / 12（3 档） |
| 行距 | 1.40 全站统一 |
| 字距 | 0 |
| 线 / 面 | 1px 斑马纹 **或** 1px 分隔线，二选一不并用 |
| 曲率 | 0 |
| 密度 | 极高 |

- **适用**：日志、后台、CLI 产品、开发者原始记录。
- **不适用**：中文长文（等宽中文极难读）、营销页、消费级。
- **换来**：一屏信息量最大、字符列对齐。
- **放弃**：阅读舒适度与品牌气质。
- **证据**：R0（`registers/dense-console.md` 的手法，无 DOM 实测支撑，属假设）。

### P5 · 暖商业（warm-commerce-type）

| 维度 | 取值 |
|---|---|
| 字体族 | 系统无衬线；标题可用圆体类（`"Yuanti SC"` 等）但需实测可用性 |
| 字号节奏 | 42 / 24 / 16 / 14 |
| 行距 | 1.65 |
| 字距 | 中文 `.01em`（略松，不糊） |
| 线 / 面 | 暖色面 + 细线，允许少量装饰 |
| 曲率 | 8 / 12 + 999 |
| 密度 | 中 |

- **适用**：转化页、活动页、社会证明驱动、消费决策。
- **不适用**：带戒心的技术受众（促销语气与讲事实冲突）、可核对数据。
- **换来**：亲和力、行动意愿。
- **放弃**：可信度密度；与技术受众的「别忽悠我」直接冲突。
- **证据**：R0（`registers/warm-commerce.md`，未实测，属假设）。**0.2.3 的 DiskWise 演示曾把「限时 8 折」写进基线再减掉，那是虚构；本配方不等于允许虚构促销内容。**

### P6 · 粗野（brutalist-type）

| 维度 | 取值 |
|---|---|
| 字体族 | 系统默认或极常见无衬线 |
| 字号节奏 | 48 → 14，**无中间档** |
| 行距 | 1.15（紧凑） |
| 字距 | 不做调整 |
| 线 / 面 | 粗黑实线、大色块 |
| 曲率 | 0 |
| 密度 | 中 |

- **适用**：作品集、宣言型页面、需要抢注意力。
- **不适用**：可读性优先、信息层级复杂的页面。
- **换来**：记忆点强、态度明确。
- **放弃**：可扫读性与温和度。
- **证据**：R0（`registers/brutalist.md`，未实测，属假设）。

## 与 register / pattern / scale 的分工

| 文件 | 管什么 | 不管什么 |
|---|---|---|
| `registers/<一个>.md` | 调性的标志手法与禁忌（线、色块、密度倾向） | 具体字体族、行距数值 |
| **`registers/type-recipes.md`（本文件）** | **字体族 / 行距 / 字距 / 线的性格 / 曲率 / 密度，成组给出** | 信息顺序、文案 |
| `patterns/<一个>.md` | 信息顺序与每块职责 | 视觉取值 |
| `tokens/scale.md` | **所选配方内部**的格子（间距、字号档、圆角档） | 跨配方不通用 |

**刻度不是全站唯一一套。** `scale.md` 的行高表是 P1 的基准；选 P2 就用 P2 的 1.80–1.90，选 P4 就用 1.40，并把「为什么这套节奏适合本场合」写进工作记录。**用同一套刻度去套所有配方，等于没选配方。**

## 出口判据

- 组合卡里每套都要写 `P_`，且用户的选择（或明确授权自主）有留痕；「选定 P_」不由模型内部独立完成。
- 工作记录必须写「选定配方 P_」+ 一句场合依据 + 一条「没选 P_，因为…」。
- S3：`02-ledger.md` 必须至少有 4 行属于排印维度：**字体家族 / 行距节奏 / 字距 / 线的性格**（曲率与密度可并入），每行「依据」回指 brief 字段或 V 编号，「放弃」不得写「无」。
- 成稿的 `font-family`、`line-height`、`letter-spacing` 必须与取值记录逐行对得上；对不上就是孤岛。
- 独立看图提问——**「换成另一套配方，这个页面会不会更贴这个场合？」** 答不出来，说明配方是默认拿的，不是选的。

## 禁止

- ⛔ 把「系统无衬线 + 1.6 行高 + 0/2 圆角 + 1px 线」称为**中性 / 无风格 / 安全默认**。它有明确的性格（冷、方正、工程感），选它也要写代价。
- ⛔ 只换字体不改行距、字距、线型、曲率就宣称「换了一套配方」——那是换字体，不是换系统。
- ⛔ 把 R0 的通用排印知识写成「实测结论」。0.2.3 已经在参考准入上栽过一次（凭截图估数字），这里不许再栽。
- ⛔ 为了证明「减法有效」而虚构一个不存在的丑基线。基线只能是 incumbent 实测或明确标注的合成样例。
