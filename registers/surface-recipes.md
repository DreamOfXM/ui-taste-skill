# 表面配方货架（surface recipes）

S2 必读，G0 方向确认门用。**这是 0.2.5 补上的第四维：底色、卡面、墨色、线、纹理、明暗关系。**

## 为什么会有这个文件

0.2.4 之前，`tokens/scale.md:102` 把「中性色带一点色相」写成全站纪律，`references/decision-ledger.md:57` 又给出一条写死 `#FBFAF7` 的「有效行」示例；六个 register 和六套排印配方全文没有任何色值。三处叠加的后果是：**换什么产品、换什么调性、换什么排印，底纹都是暖白**。

用户原话：「我们统一用的底纹，用的网页都属于奶油色底色……应该根据具体的项目、根据具体的要做的页面它是什么样子的……整个 UI 设计的过程中，我们并没有任何一个点跟用户确认，或者说是提供有几套组合。这就造成了模型直接定死了一个提供给用户。」

更硬的证据在 `diskwise-023/refs/probe-2026-11-10.json`：两条 R2 实测参考的底色分别是 `rgb(13,16,22)` 和 `rgb(7,8,10)`，**都是深底**；而 0.2.3 交付的三份页面全是暖白。U5 节点甚至明写「这是有争议的一步……本版接受」——即模型知道有争议、写下了代价、然后自己替用户接受了。

**根因不是选错了颜色，是「表面材质」这一维既没有货架、也没有出口给用户。** 0.2.4 修的是排印，没修这个。完整归因见 `diskwise-023/design/06-surface-audit.md`。

## 四条判据

1. **一页只用一套表面配方。** 混两种明暗系统 = 白补丁。只换底色不改墨色、卡面、线、纹理，是 AI 味最强的形态：05 留白诊断的消融 E2 只把 CSS 变量换回深色，产品浅色截图立刻变成贴上去的异物。
2. **跨项目必须换得动。** 「单页内同一维度只允许一条有效行」不等于「一个 skill 一辈子只准有一种底纹」。换配方的依据是 brief 字段一（受众×场合）、字段四（信任物）、字段七（品牌约束），不是「换个颜色试试」。
3. **表面必须成组落地。** 底面 / 卡面 / 墨色 / 次文字 / 线 / 纹理 / 明暗差，七项一起换。只改 `#paper` 不算换配方。
4. **每条配方标证据级别。** R2 = DOM 实测；R1 = 截图只支撑定性；R0 = 通用材质知识，**未实测、属假设，不得伪装成结论**。数值只从 R2 来，其余标 R0。
5. **底面溯源，不从品类名推断（0.3.1 补）。** 品类（C1–C9）给的是**版式、排印、按钮、密度**的默认家族，**不是底色的许可证**。底色的唯一硬依据是**产品自己的界面**。判完品类后必须做三件事：① 打开一张产品界面截图；② 采样三点——界面底、卡面/面板、主色，把十六进制写进 brief 字段零；③ 页面底面与「界面底」同族（`ΔL ≤ 6%`、色相差 ≤ 12°），**或者**在账本里写明为什么故意反差（例如产品界面全白、页面要深色以衬托截图）。

   **反例（真实发生）：** 0.3.0 把 DiskWise 判成 C1a「深色仪表」，取 `#08090A`。同一份 brief 的字段三 C10 明写「界面底色 `#F4F4F8`–`#F5F6F9` 浅冷白」，字段六 V5 明写「**产品界面浅色 → 配浅底**」。两条都在，却都没被读。用户第一句质问是「背景为什么用纯黑色」。根因不是审美分歧，是**判型看的是 incumbent 的营销选择，而不是产品本身**。C1a 这个子型的定义就是「深色界面」，DiskWise 属于 C1 但不是 a。

6. **深色不许是中性黑（0.3.1 补）。** 深色底必须带色相，`S ≥ 20%`（HSL 饱和度）。中性黑（S < 10%）在屏幕上没有底色偏差，**无法产生纵深**——所有元素像贴在一个洞上，观感是终端或文档阅读器，不是产品。这是「纯黑显廉价」的机制。

   | 档 | 值 | S | 观感 | 适合 |
   |---|---|---|---|---|
   | 中性黑 | `#08090A` | 6% | 洞 | 终端、代码编辑器、命令行工具 |
   | 深蓝墨 | `#091019` / `#0C1219` / `#0D1016` | 45–64% | 有空气、有纵深 | 技术产品、仪表、AI 工具 |
   | 深墨绿 | `#0A1512` | 33% | 冷、克制 | 金融、数据 |
   | 深褐 | `#14100C` | 25% | 暖、纸感 | 出版、文化、餐饮 |

   色相取自产品现有色系（产品主色 → 同色相压到 L 5–9%），不是随手挑一个。原官网 `#091019` 与它的青 `#01A3DC` 是同色相（208° / 200°），所以整页统一。

   **但先问一句：产品界面是深还是浅？** 界面浅色（`#F4F4F8` 以上）+ 页面深色 = 截图必然成为白补丁，必须给它物理依据（窗口边框 + 投影 + 深底反射），否则就是 05 留白诊断里消融 E2 那个失败态。界面浅色 → 优先浅底，截图能直接融入（`ΔE < 1`），这是最省力也最像真产品的方案。


## 场合 → 配方映射（先查这张表，再选）

| brief 字段一 / 四 / 七 | 配方 | 关键理由 |
|---|---|---|
| 开发者工具 · 深夜或长时间盯屏 · 产品界面本身是暗色 | **S1 暗夜仪表** | 与产品截图同一世界，接缝消失；是本次唯一有 R2 实测的一套 |
| 工程评估 / 后台 · 要逐项核对数据 | **S2 冷白图纸** | 冷中性不暗示情绪，线与数字优先 |
| 长阅读 / 品牌叙事 · 信任物是文字本身 | **S3 暖纸书卷** | 暖白降低长文眩光；也就是 0.2.1–0.2.4 一直在用的那一套，**现在它只是六分之一** |
| 消费级 / 健康 / 低压力 · 信任物是氛围与完整度 | **S4 清透柔性** | 面代替线、低饱和冷绿灰，减少审视感 |
| 医疗 / 政务 / 表单 / 需要打印 | **S5 纯白临床** | 最高清晰度与打印一致，放弃材质感 |
| 作品集 / 发布会 / 宣言 · 注意力争夺 | **S6 品牌高饱和** | 大面积品牌色是记忆点，代价是可扫读与长文 |

**0.2.6 起：本表是「实现层」，不是「选择层」。** 先由 `category-prototypes.md` 判定品类（C1–C9）并取出该品类的默认家族，再用本表把底面/卡面/墨色/线落到具体手法。同一品类可以有两套手法（C1 深色仪表用 S1，C1 浅色平台用 S2），但**底面、曲率、密度必须跟品类走，不能跟配方走**。

**冲突时以「品类」为准，受众×场合只用来在同一品类内部选子型。** 0.2.5 写的「不以产品品类为准」是错的：它让模型可以跳过「这是什么产品」直接挑手法，结果九个品类都被渲染成同一套暖白。同一个磁盘工具，官网给极客看走 C1a + S1，写给普通用户的介绍长文可以走 C1b + S3，安装说明/表单走 S5——**品类不变，变的是子型与材质手法**；品类变了（比如从工具页变成电商详情页），底面和版式都要重新取，不是换个色。

### 口语词怎么落到组合（别把整包词当规格）

| 用户可能说的话 | 拆成三维的组合（A 表面 / B 排印 / C 调性） | 还能单独反对哪一维 |
|---|---|---|
| 「科技感」 | S1 暗夜仪表 + P1 图纸 + industrial | 可以只要暗底、不要等宽冷排印（改成 S1 + P2） |
| 「清新风」 | S4 清透柔性 + P3 柔光 + soft-product | 可以只要冷绿灰、不要大圆角（改成 S4 + P1） |
| 「专业、可信」 | S2 冷白图纸 + P1 图纸 + editorial | 可以只要共轴线、不要纯白（改成 S3 + P1） |
| 「跟我们官网一致」 | 先跑 R2 实测 incumbent 的 `bodyBg`，**照抄它的系统**，不选货架 | 品牌约束优先于货架（见 `direction-gate.md`） |

口语词的价值是**快速定位候选**，不是最终规格。G0 交给用户的是上表这样的组合卡，不是六个形容词。

## 六套配方

### S1 · 暗夜仪表（night-instrument）

| 维度 | 取值 |
|---|---|
| 底面 | `#0D1016`（温和深灰蓝，非纯黑）；同族可到 `#07080A` |
| 卡面 | 底面 + 6% 白（约 `rgba(255,255,255,.06)`）；**不用白卡片** |
| 墨色 / 次文字 | `#E8EAF0` / `oklch(.74 .014 256)` 一类的低饱和浅灰，不用纯白正文 |
| 线 | `rgba(255,255,255,.08–.12)`，1px；靠线分块，不靠阴影 |
| 纹理 | 无渐变、无玻璃拟态、无彩色光晕 |
| 明暗关系 | 底面与卡面 ≤8% 明度差；文字与底面 ≥4.5:1（F1 地板） |

- **适用**：开发者工具、监控、深色产品截图、夜间使用。
- **不适用**：打印、强光户外、以长文为主的说明书。
- **换来**：与暗色产品实物同一世界，截图无接缝；高饱和强调色只占小块即可成立。
- **放弃**：浅色纸质材料的亲和；浅色产品截图必须另行处理（做成真实取景或换素材），否则出现白补丁。
- **证据**：**R2**。`diskwise-023/refs/probe-2026-11-10.json`：现任官网 `bodyBg=rgb(13,16,22)`、`bodyLum=0.005`、页高 5401px；Raycast `bodyBg=rgb(7,8,10)`、`bodyLum=0.002`；官网表格行卡片实测 `oklab(0.215 … / 0.3)`、`border:0`、`radius:0px`、正文色 `oklch(0.74 0.014 256)`。**六套里只有这一套的底面数值来自实测。**

### S2 · 冷白图纸（cold-blueprint）

| 维度 | 取值 |
|---|---|
| 底面 | `#F7F8FA`（冷中性，色相偏蓝 2–3%） |
| 卡面 | `#FFFFFF`，与底面约 3% 明度差 |
| 墨色 / 次文字 | `#1B2430` / `#626A78`（须实测 ≥4.5:1） |
| 线 | `1px rgba(27,36,48,.12)`，通高共轴 |
| 纹理 | 无；可选极淡网格，但网格不得承担分块 |
| 明暗关系 | 层级靠线 + 字号，不靠面的堆叠 |

- **适用**：工程文档、后台、逐项核对、需要截屏发群讨论的场合。
- **不适用**：情绪安抚、消费级转化、需要温度的品牌叙事。
- **换来**：不暗示任何情绪，数字与线最清楚；打印与截图压缩后仍可读。
- **放弃**：温暖与亲和；浅底会放大留白，**必须同时定密度契约**（见 `decision-ledger.md`）。
- **证据**：**R0 假设**。色值为通用材质知识，未做外部 DOM 实测；`assets/grammar/reference-workbench.html` 的 `#f7f8fa` 属本 skill 自产样例，不构成外部证据。

### S3 · 暖纸书卷（warm-paper）

| 维度 | 取值 |
|---|---|
| 底面 | `#F7F4EE` / `#FBFAF7` 一族（2–4% 暖色相） |
| 卡面 | `#FFFDF9`，与底面 1.5–2.5% 明度差，边界靠细线而非阴影 |
| 墨色 / 次文字 | `#2B2A26` / `#5C6066` |
| 线 | `1px rgba(43,42,38,.14)`；细线在暖底上不显脏 |
| 纹理 | 无图像底纹；「纸质感」来自色相与明度差，不是噪点贴图 |
| 明暗关系 | 三级：底面 → 卡面 → 强调，最多三级 |

- **适用**：长阅读、品牌叙事、中文报告/阅读器、低刺激长时间浏览。
- **不适用**：深色产品截图、监控面板、需要冷峻中立的评估场合。
- **换来**：长文眩光低、中文标题不刺眼、1px 细线可见。
- **放弃**：纯白的「干净」第一印象；低色域屏可能偏黄；**与暗色产品截图不同世界**。
- **证据**：**R0 假设 + 自产实跑值**。`#FBFAF7` 出现在 0.2.1 定价页、`#F4F3EF` 出现在 0.2.3 DiskWise，都是本 skill 自己写的，不是外部实测；`probe` 里两条外部参考反而是深底。
- **边界**：`#F7F4EE` / `#FFFDF9` / `#9C5A3C` 是用户既定的**中文 HTML 阅读器**偏好，报告页、诊断页、md 镜像沿用它是合理的；**不得因为报告用了这套，就把成品也默认成这套**。

### S4 · 清透柔性（soft-clear）

| 维度 | 取值 |
|---|---|
| 底面 | `#F2F6F4`（低饱和冷绿灰） |
| 卡面 | `#FFFFFF`，**用面代替线**，8–12px 统一曲率 |
| 墨色 / 次文字 | `#26312E` / `#6C7A74` |
| 线 | 尽量少；必要时 `rgba(38,49,46,.08)` |
| 纹理 | 允许极淡的柔和阴影代替描边，但全页只能一档 |
| 明暗关系 | 三级离地高度：底面 → 卡片 → 浮层 |

- **适用**：消费级、健康、低压力浏览、以氛围与完整度建立信任。
- **不适用**：带戒心的技术受众、逐项核对、高密度后台。
- **换来**：减少审视感，图片与插画容易融进画面。
- **放弃**：可核对性；面与圆角会吃掉密度，长列表必须另找骨架。
- **证据**：**R0 假设**，未实测。

### S5 · 纯白临床（clinical-white）

| 维度 | 取值 |
|---|---|
| 底面 / 卡面 | 均 `#FFFFFF`，**不做明度差** |
| 墨色 / 次文字 | `#111827` / `#4B5563` |
| 线 | `1px #D8DDE5`，全部边界明说 |
| 纹理 | 无 |
| 明暗关系 | 只有两级：文字 / 底；层级完全靠字号、字重、线与间距 |

- **适用**：医疗、政务、表单、打印件、需要无障碍高对比的场合。
- **不适用**：品牌叙事、需要记忆点的营销页。
- **换来**：打印与屏幕一致、对比度余量最大、缩放不糊。
- **放弃**：材质与温度；没有任何「设计感」可以靠底色偷懒，全靠版式。
- **证据**：**R0 假设**，未实测；`#FFFFFF` 也是 `example/pricing-page/render/default.html` 的裸默认值，**选它必须写出与默认值不同的理由**，否则等于没选。

### S6 · 品牌高饱和（brand-saturated）

| 维度 | 取值 |
|---|---|
| 底面 | 品牌主色满铺（如 `#1B35C8`），或大面积品牌色块 + 小面积中性底 |
| 卡面 | 中性 `#FFFFFF` 或与底面同色相降明度一档 |
| 墨色 / 次文字 | 彩底上用白 / 近白，必须实测 ≥4.5:1（F1） |
| 线 | 少线多面；若用线，取同色相高亮 |
| 纹理 | 允许大面积色块与裁切图片，**禁渐变球、禁彩色阴影** |
| 明暗关系 | 高对比、强第一落点，一页只留一个主色块 |

- **适用**：作品集、发布会、活动页、宣言式首页。
- **不适用**：长文、表单、需要逐项核对或反复使用的界面。
- **换来**：记忆点与「这是谁」一眼可辨，截屏传播不依赖文案。
- **放弃**：可扫读、长停留舒适度、状态色的可用余量（强调色已被底色占用）。
- **证据**：**R0 假设**，未实测。

## 与排印 / 调性 / 刻度的分工

| 维度 | 文件 | 管什么 | 不许碰什么 |
|---|---|---|---|
| A 表面材质 | 本文件 `S1–S6` | 底色、卡面、墨色、线、纹理、明暗关系 | 不碰字体、不碰区块顺序 |
| B 排印系统 | `type-recipes.md` `P1–P6` | 字族、行距、字距、线的性格、曲率、密度 | 不碰色值 |
| C 调性手法 | `registers/<一个>.md` | 结构外露 / 离地高度 / 禁忌 | 不碰色值、不碰区块顺序 |
| D 骨架顺序 | `patterns/<一个>.md` | 区块顺序、每块职责 | 不碰视觉 |
| 刻度 | `tokens/scale.md` | **所选配方内部**的格子 | 不是全站唯一一套 |

四个维度正交，所以 6 × 6 × 6 × 5 = 1080 种组合只需 1 + 1 + 6 + 5 = 13 个文件。但**正交不等于随便搭**：组合成立要在 `00-direction.md` 写清「受众×场合 → 为什么这三个值一起成立」，并在账本里逐行落值。

`tokens/scale.md` 的颜色纪律只管「一个色相 / 对比度实测 / 材质做法在配方内部一致」，**不再规定全站必须暖色相**。

## 地板约束（所有配方都受这条管）

`craft-floor.md F1` 的对比度是地板，不参与取舍。换表面配方后必须重新算一遍：暗底上的低饱和浅灰、彩底上的白字、纯白上的 `#9CA3AF`，都是最容易翻车的地方。**特别注意「彩底 + 白卡」**：正文在彩底上是白字，但白卡内部的 code 块、输入框、图片说明必须换回深色，否则整块文字消失（`方向确认门-六套组合.html` 的 S6 预览就是按这条处理的）。**任何配方不得以「更有氛围」为由降低对比度。**

## 出口判据

- `00-direction.md` 里写了选定 `S_` 编号 + 「没选谁、为什么」+ 证据级别。
- 账本里「表面配方」一行写明选定编号，且底面 / 卡面 / 墨色 / 线 / 纹理**成组出现**。
- 若选中的是 S3，必须额外写一句「不是因为它是默认」。
- 若 incumbent 的品牌色/明暗已成立且评级通过，按 `direction-gate.md` 走「照抄 incumbent 系统」，不选货架。

## 禁止
