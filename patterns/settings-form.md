# pattern: settings-form（设置表单）

## 区块顺序

1. 分组标签（左栏导航或顶部 tab）
2. 分组标题 + 一句说明这组改的是什么
3. 字段（标签 + 控件 + 辅助说明）
4. 组内保存 / 全局保存
5. 危险操作区（放最底部，独立分隔）

## 每块职责

- **2 的说明必须写"改了会怎样"**，不是复述标题。"通知设置 → 选择你希望收到的邮件类型"是废话；"关闭后，账户变动仍会发送"是信息。
- **3 的辅助说明位置固定**（控件下方，不是右侧）。右侧说明在窄屏会挤掉控件。
- **4 必须回答"什么时候生效"**：即时生效、点保存生效、还是下次登录生效。三种情况必须显式说明，否则用户不敢改。
- **5 必须视觉隔离**：独立分隔线 + 留白 + 非主色按钮。与常规设置混在一起是灾难。

## 常见塌陷点

- **所有字段等宽等距**：不同类型（开关/文本/下拉/多选）的字段应该有不同的垂直节奏。全部 16px 间距会让长表单显得"爬不完"。
- **保存按钮固定在页面底部**：长表单里用户改完中间一项，看不到保存按钮，以为自动保存了。
- **禁用状态的字段没有说明原因**：灰色不可改，但不告诉用户"为什么"和"怎么才能改"。
- **危险操作只用红色文字**：需要"确认对话框 + 输入名称确认"这种真正的阻断，红色文字不构成阻断。

## 必须回答的问题

- 有多少字段？>12 个必须分组，>30 个必须分页或分 tab。
- 哪些字段是"改了就不可逆"的？它们需要额外的确认层。
- 用户改错了一个字段，能不能只回退这一个？还是必须整体重填？

## 与其他 pattern 的组合

- `soft-product`：默认组合，字段浮在卡片上，分组用间距而非线
- `dense-console`：左栏导航 + 紧凑行高，适合字段极多的后台
- `editorial`：单栏窄宽度（≤640px），适合账户/个人资料类
