# pattern: dashboard（仪表盘）

## 区块顺序

1. 全局筛选/时间范围（永远是第一行的左上，位置固定）
2. 3–5 个关键指标卡（数字 + 变化 + 时间范围）
3. 一个主图表（占据最大面积，回答"整体趋势"）
4. 1–2 个辅助图表或明细表（回答"哪里出的问题"）
5. 可选的"异常/待办"区

## 每块职责

- **1 的位置必须固定**。仪表盘的用户会形成肌肉记忆，筛选器位置变化等于让他每次重新找。
- **2 的数字必须带参照**：同比/环比/目标值，三者至少一个。孤立的数字没有信息量。
- **3 只能有一个**。两个同等大小的图表，用户不知道先看哪个，等于没有重点。
- **5 是这一页真正的价值所在**：仪表盘不是"看数据"，是"发现问题"。没有异常区，用户看完还是不知道要做什么。

## 常见塌陷点

- **指标卡用不同颜色**：五个卡五种颜色，每个都在喊。应该只有一个卡有强调色（当前最需要关注的）。
- **图表用默认库配色**：ECharts/Chart.js 的默认色板一眼可辨。至少改主色，且轴线、网格线降到最低可见度。
- **Y 轴不从 0 开始但不标注**：这是数据可视化的实质错误，会误导判断。要么从 0，要么用截断标记明确说明。
- **空数据时整块消失**：区块消失会让布局跳动。应该保留占位并说明"暂无数据"（见 states-matrix S7）。

## 必须回答的问题

- 用户每天打开这一页几次？如果 >3 次，第一屏必须直接给"变化"，不是"总量"。
- 数据更新频率是多少？实时数据必须有"最后更新时间"，否则用户不知道该不该信。
- 这一页支持什么决策？答不出具体动作，说明指标选错了。

## 与其他 pattern 的组合

- `dense-console`：默认组合，密度高
- `industrial`：图表用细线、无填充、网格外露
- `soft-product`：卡片浮起、图表圆角，适合低频查看的管理层视图
