# pattern: table-list（数据列表）

## 区块顺序

1. 标题 + 记录总数
2. 工具栏：搜索、筛选、排序、批量操作、主操作（新建）
3. 表头（可排序的列要有指示）
4. 行
5. 分页 / 无限滚动终点

## 每块职责

- **1 的总数必须显示**。用户需要知道"我面对的是 12 条还是 12 万条"，这决定他用搜索还是用翻页。
- **2 的搜索框必须最左**，主操作（新建）最右。批量操作仅在选中后出现，不要常驻。
- **3 的列宽策略要明写**：固定宽 / 内容自适应 / 比例分布。混合使用必须有理由。
- **4 的行高决定密度**：32/36/44 三档，对应"扫读/常规/触摸"。超过 48 就不该用表格，该用卡片列表。

## 常见塌陷点

- **每行都是卡片**：列表项加圆角 + 阴影 + 间距，一屏只能放 5 条。表格的意义是密度，卡片化等于放弃这个优势。
- **操作列用图标无标签**：编辑/删除/更多三个图标，用户每次都要辨认。除非这三个操作出现频率极高，否则用文字。
- **删除没有撤销**：直接删除 + 弹窗确认，不如"删除后 5 秒内可撤销"。前者打断流程，后者不打断。
- **排序状态不明显**：点了表头没变化，或变化太细微。排序指示必须同时有图标和文字变化。
- **空结果与初始状态混同**：搜索无结果和一条记录都没有，应该是两种不同的空态（见 states-matrix S7）。

## 必须回答的问题

- 一屏要放多少条？由这个数字倒推行高，而不是先定行高。
- 用户主要用搜索还是用浏览？搜索为主 → 搜索框要突出；浏览为主 → 筛选和排序要突出。
- 有没有"必须横向滚动"的列？如果有，第一列必须 sticky。

## 与其他 pattern 的组合

- `dense-console`：默认组合，行高 32–36，斑马纹或线分隔
- `industrial`：全边框网格，等宽数字，适合监控/日志
- `editorial`：只保留 3 列，行高大（56+），接近"目录"而非"表格"
