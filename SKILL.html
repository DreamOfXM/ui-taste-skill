7# UI Taste
8 
9## 定位
10 
11这个 skill 不生产"更好看的默认值"，它生产**可被辩护的选择**。
12 
13判断标准不是"像不像专业设计"，是"每一处取值能不能说出换来了什么、放弃了什么"。
14 
15**但先说一件比取值更前面的事：页面不好看，多数时候不是取值错了，是主次错了。** 一段文字用什么字号没法单独判断好坏，要看它在页面里排第几。所以 0.3.0 把「内容优先级」提到排颜色之前——先定 P0/P1/P2/P3，再谈字体、曲率、底色。**没有位次，所有视觉参数都没有比较基准**，只能落到"都还行"的中位数，也就是用户说的"顶多不丑"。
16 
17方向不由模型单方面定：开放设计必须在动笔前把 **5–6 套互不相同的方向**摆给用户（见 G0 方向确认门），并且每套都真的画出来。能被辩护 ≠ 有权替用户决定。
18 
19因此开放设计必须出多版：只有一版时，"更好"这句话没有比较对象，是空话；只出两版时，用户往往两版都不满意却没别的选择。默认 **5–6 版关键屏**，理由与成本见「交付形态」一节。
20 
21**诚实契约：保证下限，不保证上限。** 验收清单、状态矩阵、账本都是**否定式检验**（找缺陷；0.2.5 新增的第八/九问分别查流程合法性与空白用途，同样不蕴含"好"）；全过只能证明"不坏"，证明不了"好"。好是构图、张力、材料、记忆点这类**关系属性**，没有任何 checklist 能蕴含它——所以"规则全过"和"用户说好"之间永远有一道缝。本 skill 的承诺因此是：下限可靠（不残、不丑、连贯、内容真实），上限靠参考天花板与闭环反馈**提高概率**，不承诺"保证产出好 UI"（那是不可证伪的空话）。要让上限收敛，必须把裁判放进环内：渲染后与天花板并排比 + **盲看回读**（见验收契约第二层），而不是让生产者自评自证。**关系属性不能数，但能取证**——取证靠一个没继承你理由的独立实例，不靠再加一条数字门。
22 
23**0.3.0 补一条：否定式检验永远到不了上限，因为它只能排除，不能产生。** 0.2.x 六轮实跑的共同结果是"顶多不丑"——每一版都过了地板，但没有一版有主次。所以 0.3.0 加了一个**肯定式的强制产出**：首屏只允许一个 P0，且它必须是"反常、具体、不可能被编造"的那个事实（见 `references/content-architecture.md`）。这不是再加一条 checklist，是要求流程**必须先产生一个东西**，才允许往下走。

25## 高级感是什么，以及它怎么验收
26 
27**高级感 = 页面自己立的规矩站得住 + 破规矩的地方破得有理由。** 这条判据改了三件事：
28 
291. **规矩指成稿画面，不是账本。** 账本是我写的，页面是读者看的，两者可以完全对不上。验收对象只有一个：渲染出来的页面。读者能不能**只看画面**就说出"这页自己的规矩是什么"，是规矩存不存在的唯一证据。说不出 → 这页没有规矩，高级感免谈。
302. **破例可以多处，不设数量门。** 一处也行，五处也行。判据不是几处，是**每一处的理由能不能只看画面就说出来**。理由必须指向页面上的具体内容或文案：「这个数字是全页唯一的结论」成立，因为文案真这么说；「为了有层次」不成立，画面上找不到依据。**需要设计者开口解释才成立的破例，就是失败的破例。**
313. **整体感不能数，只能取证。** 它是 UI 与文字搭配出来的关系属性。把十一问扩成十二问、再加一个数字阈值，只会重复同一个错误——门全在能测的那一半，好坏全在测不到的那一半。取证方式是**盲看回读**：换一个没看过设计理由的独立实例，只给它任务、约束和同视口截图，问三句（规矩是什么 / 哪几处破了 / 每处为什么该破），记原话。答不上来就是不过，回去改。规程见 `references/readback.md`。
32 
33**所以验收分三层，各管各的，不互相代替：**
34 
35| 层 | 管什么 | 怎么判 | 判不了什么 |
36|---|---|---|---|
37| 十一问 + 状态矩阵 | **地板**：防塌 | 数元素、跑探针，逐版各一遍 | 判不了好坏。全过只说明"没塌" |
38| **回读门** | **整体感**：规矩与破例 | 独立实例盲看三问，记原话 | 只判失败（无规矩 / 破例读不出 / 全守规矩），判不了优秀 |
39| 同视口并排二选一 | **优劣** | 匿名打乱，问"你愿意装哪个" | 结论归用户，不是模型 |
40 
41**盲看的是另一个模型实例，不是用户。** 用户只在最后拍一次板，不参与每轮验收。生产者自评不能单独作为审美结论——继承了你的理由，它就继承了你的辩护。

43## 先分流，再决定走多远
44 
45| 任务 | 路径 |
46|---|---|
47| 用户给了原稿或已认可方向 | 原稿即规格。单稿忠实深化，不另立主张、不强凑多版；账本只记与原稿的偏差和理由 |
48| 对象已有上线页面 / 现有界面 | S1 先整页打开并评级（连贯/投入/完整/真实材料）。评级成立 → **校准**：保留其产品身份与最好关系，只修真实缺陷，不另立相反调性；评级不成立才走开放重做。**校准须从 incumbent 源码/实测提取字级、字重、留白节奏与材料取景并沿用**（原稿即规格包含排印与留白）；自有 tokens 只是开放设计的默认值，不得把 incumbent 更大的字级/更宽的留白压回自有刻度。**换算留白先看 incumbent 的 nav 定位模型**：fixed/overlay nav 的 hero padding 已含 nav 高度，若自己的 nav 在正常流，照抄该 padding 会把 nav 高度再叠一次（顶部空带翻倍）；应对齐"内容距视口顶的总距离"，不照抄 padding 字面值 |
49| 局部精修（改一个控件、一处间距） | 只重填受影响的账本行，跑相关地板与状态检查；不重跑五阶段，不借机翻新整页 |
50| 开放新设计、整体重做、"不好看但说不清" | 先过上一行的 incumbent 评级门，再完整六阶段（含 S1.5 内容优先级）、**5–6 版关键屏对照** |
51 
52只有会改变任务方向或不可逆的问题才问用户；已获自主授权时写明必要假设继续，交付时列出假设。**视觉方向（明暗系统 / 底纹 / 排印配方 / 调性）恰恰是会改变任务方向的问题**——它决定素材能不能用、品牌身份是否延续、对比度怎么算、留白读不读得出来。0.2.4 把它误归为「可自行假设的细节」，是奶油色铺满所有产物的直接原因之一。因此开放设计必须走 **G0 方向确认门**（`references/direction-gate.md`）：先给 5–6 套方向，再由用户挑、只换一维、或授权全画完再看。其余细节仍按「写明假设继续」处理，不要什么都问。

54## 十四条硬纪律
55 
56**⛔ 开放设计不只出一版。** 一版没有对照，用户无法判断优劣；交一版等于把选择权扔回用户，却没给依据。**默认交付 5–6 版关键屏**——少于 5 版挑不出真正的偏好，多于 6 版是噪声。原稿还原与局部精修按分流走，不受此条约束。
57 
58**⛔ 账本不许有空代价。** "放弃"列写不出内容的行，判定为抄默认值——作废重填，不许留着。
59 
60**⛔ 不许事后美化。** 成稿之后改颜色、加阴影、贴渐变来"提升质感"，属于无依据修补。要改就回到 S2 或 S3 改账本，再重写受影响的区块。理由：整页的一致性来自账本，账本外的改动会成为孤岛。第十一问不过时按这条回 S3 记账本再补能量——纪律禁止的是绕过账本，不是禁止补能量。
61 
62**⛔ 否定式全过不等于交付。** 第 1/4/5 问是破坏式测试（去阴影、数档数、换灰），它们的共同最优解是"手段最少、材质最平、颜色最省"。只跑这三问，认真执行的产物必然比不假思索的基线更素——实测同一份冻结输入，不加载本技能的生成把强调用在标题着色、开关、表头标签和按钮上；加载本技能并跑完十问的稿只剩一个彩色按钮、38px 标题，用户的评价是"基线那一组更好看"。**"不可批评"比"好看"容易达成，所以必须有一道数字门拦住"向下限收敛"**：S5 第十一问查强调级落点（≥3 处且分布在 ≥2 个顶层区块，只数饱和度 ≥0.40、绝对彩度 ≥0.18 的颜色，正文灰不算）、字号跨度（≥2.6）、材质类数（≥2 类且各有职责）、**体积载体（投影 / 渐变 / 含渐变或滤镜的图像，三者至少一类）**、以及一句能指到账本或配方出处的"为什么是它"。**单色 path 图标与平涂矢量不算体积**——2026-11-11 实测：加载本技能的三稿里两稿 `box-shadow: 0`，靠 15 个单色小图标和 2 个平涂瓶子通过旧版"含图像至少一类"，用户三组全选基线，原话是"到处是线框和死板""线条呆板、老登味重"。补能量的依据是所选配方与品类默认家族，先进账本再落地。**这道门是地板，不是美感判据**：它拦得住"平"，拦不出"好"。阈值标定自同一份定价页、同一视口 838×1060 的三稿，换品类换视口必须现测，不得当通用美感阈值或排名依据。好由下一条的回读门取证。数字每次都要现测（`python3 scripts/probe-energy.py <页面.html>`，只要 python3 标准库加本机 Chrome）。
63 
64**⛔ 破例必须写理由，理由必须能从画面上读出来。** G0 每套方向除了"借了哪个类型"，还要列**破例清单**：破了哪条规矩、破在哪个元素、为什么该破。**破例可以多处，不设数量上限**；但每一处的理由只准指向页面上的具体内容或文案，不准写"为了层次 / 为了高级 / 为了呼吸感"。S5 由独立实例盲看回读（`references/readback.md`），读不出理由的破例判不过，回 G0 重立主张或回 S3 改承载元素——**不是回 S4 加装饰**。理由：十一问全在数元素属性，而好坏是关系属性；0.3.1 六版实跑都过了门却都塌回同一个大数字，因为**没有任何一问回读 G0 那句主张**。写了没人验，等于没写。
65 
66**⛔ 禁忌只能来自受众×场合冲突，不能来自"像 AI/像模板"。** 把产品自身已成立的身份（配色/版式/组件习惯）写进禁忌，等于自废最强资产。registers 与禁忌是**镜头不是禁令**；唯一硬地板是工艺：对比、溢出、状态、层级、真实内容。某手法"好不好"由连贯+投入+产品契合判定，记进账本并写代价，不由预先黑名单判定。理由：暗色 cyan、feature 卡、stat band 在套路页里是 AI 味，在一个连贯投入的产品里是身份；禁手法本身会把好产品一起禁掉。
67 
68 
69**⛔ 排印不许停在默认。** 字体族、行距节奏、字距、线的性格、曲率、密度这六项，必须在 S2 从 `registers/type-recipes.md` 选**一整套配方**，并在 S3 逐行落账本。把「系统无衬线 + 1.6 行高 + 0/2 圆角 + 1px 通高线」当成「中性默认值」直接开写，等于没做选择——这套东西有明确性格（冷、方正、工程感），只适合一部分场合。理由：0.2.3 及之前所有产物共用一副脸，整齐干净但没有美感，根因是排印这一维根本不在账本里。一页只用一套（混搭仍是 AI 味），跨场合与跨版本必须换得动——**同一版内部混搭是 AI 味，5–6 版之间不换配方才是真的没得选**。
70 
71**⛔ 方向不许由模型单方面定死。** 开放设计在 S2 之前必须过 G0：把 5–6 套方向摆给用户，每套写明换来 / 放弃 / 证据级别，由用户挑、只换其中一维、或明确说「你定，全画完再看」（**默认后者**——方向没定死时，让用户先看成品比先看菜单更容易判断）。落盘 `design/00-direction.md`，S5 第八问回读。理由：0.2.4 及之前，底色由 `tokens/scale.md` 的全站纪律 + 账本模板示例值直接给定，`SKILL.md` 又抑制提问、多稿规则排除表面轴、交付时用户才第一次看到方向，于是「暖白纸」被当成无需询问的默认值铺满所有产物；而两条 R2 参考实测都是深底。**别把「清新风 / 科技感」这类整包形容词当选项**——它们是三个正交维度的捆包，用户没法只反对其中一项。
72 
73**⛔ 内容先于品类，品类先于风格。** S1 判完品类之后、**G0 方向门之前**，必须先过 **S1.5 内容优先级**（`references/content-architecture.md`）：把全部内容排成 P0/P1/P2/P3，**全页只有一个 P0**，桌面首屏信息单元 ≤7、移动 ≤5，并写出删除清单（删了什么 / 为什么敢删 / 移到哪）。没排位次就去问方向，方向卡只能比颜色，用户也只能凭顺眼挑——那正是 0.2.5 的问题。没排位次就进 S2，后面所有字号、面积、对比、留白的决定都失去比较基准，只能落到"都还行"的中位数。理由：0.2.6 实跑过了地板检查、九问过四条，用户评价仍是「顶多不丑，多惊艳没有」——不是配色错了，是页面没有一处敢比别处大。P0 的找法是找「**反常 + 具体 + 不可能被编造**」的那一个事实，不是问「哪个功能最重要」——那个问法只会得到功能清单，因为每个功能都重要。
74 
75**⛔ 底面从产品界面采样，不从品类名推断；深色不许是中性黑。** 品类只给**版式、排印、按钮、密度**的默认家族，**底色的唯一硬依据是产品自己的界面**。S1 必须打开一张产品界面截图，采样三点（界面底 / 卡面 / 主色）写进 brief 字段零；页面底面与「界面底」同族（`ΔL ≤ 6%`、色相差 ≤ 12°），**或者**在账本里写明为什么故意反差。深色底 `S ≥ 20%`，色相取自产品现有色系。理由：0.3.0 把 DiskWise 判成 C1a「深色仪表」取了 `#08090A`（S 6%，中性黑），而同一份 brief 的字段三 C10 写着「界面底色 `#F4F4F8` 浅冷白」、字段六 V5 写着「产品界面浅色 → 配浅底」——两条都在，一条没读，用户第一句就是「背景为什么用纯黑色」。机制上，中性黑没有底色偏差，产生不了纵深，所有元素像贴在一个洞上，观感是终端不是产品。判型的依据是**产品本身**，不是 incumbent 的营销选择：官网是深色，不代表产品是深色。
76 
77**⛔ 品类先于风格，版式与排印由品类决定。** S1 必须先从 `registers/category-prototypes.md` 判定品类（C1–C9），取得该品类的**默认家族**：卡面 / 墨色 / 字体 / 字号 / 行距 / 按钮形状与字重 / 曲率 / 线宽 / 版心 / 密度 / 首屏图文比，**十一项一起**（「底面」不在此列，按上一条从产品界面采样；品类表给的底面只能当 G0 甲案候选值，不能当结论）。不许跳过品类直接选「风格」，也不许把「科技感」当品类。理由：0.2.5 把表面做成六套抽象配方，还写了「以受众×场合为准，不以产品品类为准」——这句话是错的。品类是用户 1 秒能回答的客观事实，也是唯一有统计规律可实测的东西：美妆全行业 `border-radius: 0`（Glossier / Rare Beauty / 花西子实测），母婴按钮圆角 ≥12px（BabyBjörn 32 / Pampers 12），电商正文 12px（淘宝实测），开发工具 H1 字距 -0.02~-0.06em（Linear / Vercel 实测）。同一个纯白底，C2 电商是 12px 密排 + 8 圆角 + 图为主，C9 消费电子是 17px + pill + 996 版心——**底色相同、品类不同，页面必须长得完全不一样**。不走这一步，换多少种颜色都还是同一套模板。
78 
79**⛔ 品类默认家族是一个包，包里有承重项；承重项缺席时整包换，不许只撤承重项留下骨架。** S1 抄下十二项默认家族时，必须同时圈出**承重项**——那一项撤掉，其余项就失去成立条件。C4 美妆的承重项是「满幅产品/肌肤影像」：`r0 + 无卡面 + 无阴影 + 400 字重` 这套指纹只有在影像承担视觉重量时才读作画廊，影像换成小尺寸平涂矢量，同一套指纹立刻读作检验报告。C5 母婴的承重项是「场景图 + 大圆角软卡」，撤掉图留下细线硬框就读作规格表。**brief 禁止承重项时（例如不许外链照片），S1 必须写明替代物并让它承担同等重量**（内联 SVG 的渐变玻璃体积、满幅色域、真实材质渲染都算），S5 回读替代物有没有真的落地。**不许把「放弃欲望层 / 放弃安全感 / 放弃品类正统性」写进账本当作合格代价**——那等于承认这一版不再像这个品类。理由：2026-11-11 三组实测，加载本技能的美妆稿在账本里逐条写明「放弃 ≥8 张大图的欲望铺陈」「放弃圆角的亲和」「欲望层与美的第一印象弱于甲案」，然后合格交付；用户三组全选不加载技能的基线。**能写出代价 ≠ 代价可以付。**
80 
81**⛔ P0 是内容位次的第一，不是像素面积的第一。** 第十问要求 P0 是首屏视觉权重最大的**那一块内容**，不是要求它压过产品图、产品名或品类身份。品类把视觉重量交给影像时，P0 可以是影像旁最大的一块文字，与影像共同构成首屏主体；**把产品名降成行内小字、把产品挤出首屏、把购买按钮缩成小色块来给 P0 让位，判不过**。首屏元素 ≤7 / 移动 ≤5 是**上限不是目标**：删到 5 个但删出两栏死白，第九问照样不过。理由：同一轮实测里，母婴稿为了把三边读数顶成最大，左栏留出两段各约 150px 的无内容带（探针实测该栏填充率 0.35），用户原话"大量的空白导致不舒适感，数据展示不突出"；美妆稿把产品名从品类默认的 28–36px 压到 24px 行内小字，用户原话"重点突出"给了基线而不是它。
82 
83**⛔ 过程语言不进产物。** 页面是给买家/用户看的，不是给执行者看的。成稿里不许出现 skill 的流程词：方向甲乙丙丁 / 关键屏 / 回读门 / 账本 / 破例 / 行高 48 / 保留 1px 描边 / 本版接受 / 练习用虚构页面。brief 明确要求保留的标记（如补货时间写 `[待补]`）除外。S4 出口跑一遍 `grep -nE '方向[甲乙丙丁戊己]|关键屏|回读|账本|破例|行高|描边|练习用虚构' <页面.html>`，命中就删，删完重拍截图。理由：2026-11-11 实测，美妆稿把「交付说明：本次只画 1 版关键屏（方向丁 · 第三方检验报告）。第二层回读门待独立盲看执行。」印在购物页首屏下方，母婴稿导航栏写着「练习用虚构页面」。**账本写得再诚实，印到页面上就是缺陷。**

101## 交付形态：5–6 版都合规，且明显不一样
102 
103**约束是修稿指令，不是淘汰器。** 十一问里每一条「不过」都自带修法：落点不够就把强调色加到更多区块、没有文字着色就给承担论断的数字着色、跨度不够就拉开 display 与正文、材质单一就补投影或图像。所以「不过」的正确反应是**改这一版，改到过**，不是把它划掉、更不是只交一版绿的。过门是每一版的入场券，不是终点。
104 
105**默认交付 5–6 版关键屏**（首屏 + 本产品最难的那一屏），同一份内容事实、同一视口、每版地板全过，用户从中挑一版展开成整页。理由：一版只能证明"能做出来"，用户真正需要的是**在几个真的不同的东西之间做选择**；而 5–6 是上限——再多就挤在一起，变成噪声。少于 5 版不算交付。
106 
107**方差必须在开画之前就被规定死，否则一定塌回同一版。** 三条防塌缩：
108 
1091. **先写主张与破例，再画。** 每版一句「借了 ___ 这个已存在的类型，它自带的规矩是 ___」，再列破例清单：破在哪 / 破了哪条规矩 / 为什么该破，**可以多处**。句子互相不一样，画面才可能不一样；主张或破例理由写不出来的那版直接作废，不用画。**破例理由是这一版最容易被实现默认值磨平的东西**——S5 回读门专门查它有没有活到成稿里。
1102. **三轴里有两轴不同才算两版**：构图（什么东西占住哪块视野）、材料（底面/线/面/光的关系）、对象表达（把产品说成什么东西——工具、仪表、清单、杂志）。只有配色、只有底面明暗、只有字号的，判为同一版。
1113. **灰度缩略图并排测试**：把 5–6 版首屏各截一张缩略图、去掉颜色并排看。**去掉颜色还分得清，差异才成立**；一灰就糊成一片，说明做的是同一版换色。
112 
113**排序不交给数字。** `probe-energy.py` 只判每版有没有踩到地板；哪版更好，由并排看图和独立评审决定。门槛数字高不等于值得选——实跑里出现过「16 处强调落点全是 1px 描边」过了门，而判「不过」的那版材质更多。

152

201## 多版规则
202 
2035–6 版的差异必须落在**构图 / 材料 / 对象表达**三轴里的至少两轴上。只有配色、只有底面明暗、只有字号的，判为同一版——重做，不算一版。
204 
205| 轴 | 变了是什么样子 | 举例 |
206|---|---|---|
207| **构图** | 什么东西占住哪块视野变了 | A 让产品界面截图占满首屏右 2/3；B 把首屏让给一句断言 + 一条状态时间轴，截图退到第二屏 |
208| **材料** | 底面 / 卡面 / 线 / 光 / 纹理的关系变了，且是整包换一套配方（七项一起） | A 走 S2 冷白图纸（1px 通高线 + 无卡面 + 等宽数字）；B 走 S4 清透柔性（大圆角卡 + 柔投影 + 几乎不用细线） |
209| **对象表达** | 把产品说成另一种东西，读者用它的方式就变了 | A 说成**仪表**（读数、状态、阈值）；B 说成**清单**（勾选项、步骤、完成态）；C 说成**杂志**（一篇有观点的稿子 + 侧栏事实卡） |
210 
211- 合格：三轴里两轴不同（构图 + 对象表达，或材料 + 构图）。
212- 不合格：v1 深蓝底 / v2 墨绿底 / v3 紫底——这是色卡，不是三版。
213- 不合格：只把按钮圆角从 6 换到 16、其余一切不动——只换数值没换系统。
214 
215**验证不靠自我声明**：把每版首屏截图去色、压成同宽缩略图并排看。**去色后看不出区别，就是同一版。** 命令见 `references/direction-set.md`。
216 
217**为什么改了这条**：0.2.5 原文是「两稿必须在同一根轴上取值相反」，针对的是旧交付形态——两稿共用 G0 锁定的方向，只剩结构一维可动。实测暴露的副作用正是这里：方向一旦锁死，版与版之间只能差在栏目顺序上，用户并排看不出区别，评价回到"都一样"。所以这次让**方向本身进对照**，材质与对象表达都是合法轴。
218 
219**旧规则里那句洞见保留**：⛔ 不许让「哪版更好」变成「哪个颜色顺眼」——判同三轴是这条洞见的可执行版本，不是它的对立面。判同靠去色并排，不靠数颜色。

221## 验收契约（所有路径共用，只立一次）
222 
223**功能底线先于三层**：核心任务链实际走通、内容真实完整、无安全问题。三层全过不能替代功能验证。
224 
225### 第一层 · 地板（十一问 + 状态矩阵，逐版各一遍）
226 
227- **首屏只有一个 P0（第十问）**：数首屏元素（桌面 ≤7 / 移动 ≤5）；「这一屏我只要你 ___」能一句话填完；`01-content.md` 的 P0、`01-thesis.md` 的主张、截图里视觉权重最大的那块，三者是同一个事实。它要求页面必须有一处明显比别处大。**但 P0 是内容位次的第一，不是像素面积的第一**：产品名、产品图、购买入口属于品类身份，不许为了给 P0 让位被降成行内小字或挤出首屏；元素数是上限不是目标，删出死白照样不过第九问。
228- **有没有塌到下限（第十一问）**：强调级落点 ≥3 处且 ≥2 个顶层区块、其中文字着色至少 1 处且落在承担论断的数字或标签上、字号跨度 ≥2.6、材质 ≥2 类且各有职责、**体积载体 ≥1 类（投影 / 渐变 / 含渐变或滤镜的图像；单色图标与平涂矢量不算）**、"为什么是它"能指到账本或配方出处。**这是防塌门，不是美感门**：第 1/4/5 问的通过形态和"最平的解"长得一模一样，第十一问把那个解拦下来；拦下来之后页面只是"不平"，**不等于"好"**。阈值标定自一份定价页、一个视口的三稿，换品类换视口必须现测，不得当排名依据。
229- **方向确认门回读（第八问）**：`00-direction.md` 有 5–6 套方向、任意两套三轴里有两轴不同、每套有主张与破例清单、用户选择是原话或明确授权。**门的职责是拦，不是选**：某版不过判据，按判据对应的修法改那一版到过为止，不许因为不过就删掉整版。「用户没回」不许写成「用户认可」；未确认方向要标在已知短板里。
230- **空白有没有任务（第九问）**：内容量 × 版心、两栏配重、每块空白的用途。跑 `probe-energy.py` 的 ④ 首屏空洞段，它按栏报告最长空横带与填充率（整块横扫量不出两栏布局里单栏的死白）。**填充率 <0.50 的栏，每一块都要能说出「这块空白在干什么」**；说不出回 S3 改密度契约，不是回 S4 加装饰。数字只把空洞摆到眼前，判好坏仍靠回读与用户。
231- **品类承重项回读（第八问附带）**：S1 圈出的承重项在成稿里还在不在；brief 禁止它时，替代物有没有真的承担同等重量。十二项默认家族逐项与成稿比对，**身份四项（首屏图文比 / 卡面 / 曲率 / 线）偏离 ≥2 项判不过**，回 G0 换方向。
232- **过程语言不进产物（功能底线，不占问数）**：成稿里不许出现 skill 的流程词——方向 / 关键屏 / 回读 / 账本 / 破例 / 行高 / 描边 / 臂 / 本版接受 / 练习用虚构页面。brief 明确要求保留的标记（如 `[待补]`）除外。跑 `grep -nE '方向[甲乙丙丁戊己]|关键屏|回读|账本|破例|行高|描边|练习用虚构' <页面.html>`，命中就删。理由：2026-11-11 实测，美妆稿把「交付说明：本次只画 1 版关键屏（方向丁）…第二层回读门待独立盲看执行」印在购物页上，母婴稿导航栏写着「练习用虚构页面」。这些是给执行者看的话，不是给买家看的话。
233- **闸门是地板，不是排名**：十一问与三探针只回答"这一版有没有塌"，不回答"哪一版最好"。不过就改到过——**没有任何一版因为不过门而被删除**，也没有任何一版因为数字最高而被自动选中。

235### 第二层 · 整体感（回读门，逐版各一遍，必做）
236 
237- **盲看**：换一个独立实例（子代理，不是用户），只交任务、约束、同视口截图（含真实文案，字号要读得清）。**不交账本、不交主张句、不交破例清单、不交你的任何设计理由。**

243### 第三层 · 优劣（同视口并排二选一）
244 
245- **与天花板并排比（有参考/校准必做）**：把成品与 incumbent/参考在**同视口**渲染截图并排对照，差异逐条归因到关系（顶部空带、字级、字重、取景、层级），而不是归因到"规则没写"。对着规则自检不算验收。校准继承的是**产生取值的系统**，不是源码字面值：对齐靠测量渲染结果（如内容距视口顶的总距离、nav 是 fixed 还是正常流），不靠抄 padding。
246- **匿名 + 打乱 + 二选一**：版号换成甲/乙/丙…并打乱，第二轮换一种打乱。只问「第一眼落到哪版 / 你愿意装哪版 / 哪两版是同一个东西」，**不问分数**，探针数字这轮不参与。
247- **结论归用户**：评审者的偏好是证据，不是授权。让某一版胜出的必须是用户看着画面的选择；报告里写"几人各选哪版、理由原话"，不写"综合评分最高者为 v3"。

2580. **内容优先级 + 方向确认（在写页面之前，不是交付时）**：`design/01-content.md`（**P0 是什么、首屏几个元素、砍了什么**）+ `design/00-direction.md`（5–6 套方向清单，每套写「借了 ___ 这个已存在的类型，它自带的规矩是 ___」+ **破例清单**：破在哪 / 破了哪条 / 为什么该破，可以多处）。这一步是提问，不是交付物；用户在这里决定"给我看什么"，也可以直接说"全画完再给我看"——默认走后者。**交付时第一句话就要说 P0 是哪个事实**，不要藏在文档里——如果用户不理解为什么是它，后面所有排版都白做。
2591. `design/v1.html` … `design/v6.html` —— 每版一屏能独立打开的真实页面（首屏 + 本产品最难那一屏），不是截图
2602. `design/compare.html` —— 5–6 版**同视口**截图并排，一屏看全；每张下面写这版的主张、换来、放弃，不写分数不写排名（排名是用户的事）
2613. `design/02-ledger.md` —— 决策账本：共用的事实一页 + 每版各一列取值；「放弃」列必须有主语
2624. `design/03-critique.md` —— 逐版三层验收：地板（每版各跑一次探针，输出原样贴入）+ **回读门（独立实例的三问原话照录，不打分）** + 并排二选一结果，含已知短板（方向未确认时必须写在这里）
2635. 一段话：这几版分别把产品说成了什么东西、各自代价是什么、我看不出哪版最好及为什么看不出；若用户说过「你定」，把模型补的方向性假设单列出来
