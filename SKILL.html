4description: 为界面做有主张的视觉设计，产出可对比的多稿实现与逐条写明依据和代价的决策账本。**先排内容优先级（P0/P1/P2/P3，首屏只有一个 P0），再判产品品类（开发工具/电商/服饰 DTC/美妆/母婴/内容社区/金融/食品/消费电子），按品类取版式与排印默认家族、底面另从产品界面截图采样，再给 ≥3 套组合请用户确认**，不替用户定死说什么、先说什么、底色与版式。当用户要求设计/重做页面、落地页、仪表盘、表单、定价页，或说 UI 不好看/没质感/像 AI 做的/不惊艳、内容没有主次、底纹都一样、按钮/字体/排版不对、要几个方案时使用；给了视觉原稿则忠实还原，局部精修只改受影响处。Use when designing or redesigning web UI, when the UI looks generic, AI-made or merely "not ugly", or when the user asks for content hierarchy, category-appropriate surface and typography with explicit trade-offs. Not for backend logic or non-visual bug fixes.

6 
7# UI Taste
8 
9## 定位
10 
11这个 skill 不生产"更好看的默认值"，它生产**可被辩护的选择**。
12 
13判断标准不是"像不像专业设计"，是"每一处取值能不能说出换来了什么、放弃了什么"。
14 
15**但先说一件比取值更前面的事：页面不好看，多数时候不是取值错了，是主次错了。** 一段文字用什么字号没法单独判断好坏，要看它在页面里排第几。所以 0.3.0 把「内容优先级」提到排颜色之前——先定 P0/P1/P2/P3，再谈字体、曲率、底色。**没有位次，所有视觉参数都没有比较基准**，只能落到"都还行"的中位数，也就是用户说的"顶多不丑"。
16 
17方向不由模型单方面定：开放设计必须在动笔前把**至少三套可选组合**摆给用户（见 G0 方向确认门）。能被辩护 ≠ 有权替用户决定。
18 
19因此开放设计必须出多稿：只有一稿时，"更好"这句话没有比较对象，是空话。
20 
21**诚实契约：保证下限，不保证上限。** 验收清单、状态矩阵、账本都是**否定式检验**（找缺陷；0.2.5 新增的第八/九问分别查流程合法性与空白用途，同样不蕴含"好"）；全过只能证明"不坏"，证明不了"好"。好是构图、张力、材料、记忆点这类**关系属性**，没有任何 checklist 能蕴含它——所以"规则全过"和"用户说好"之间永远有一道缝。本 skill 的承诺因此是：下限可靠（不残、不丑、连贯、内容真实），上限靠参考天花板与闭环反馈**提高概率**，不承诺"保证产出好 UI"（那是不可证伪的空话）。要让上限收敛，必须把裁判放进环内：渲染后与天花板并排比 + 独立看图（见验收契约），而不是让生产者自评自证。
22 
23**0.3.0 补一条：否定式检验永远到不了上限，因为它只能排除，不能产生。** 0.2.x 六轮实跑的共同结果是"顶多不丑"——每一版都过了地板，但没有一版有主次。所以 0.3.0 加了一个**肯定式的强制产出**：首屏只允许一个 P0，且它必须是"反常、具体、不可能被编造"的那个事实（见 `references/content-architecture.md`）。这不是再加一条 checklist，是要求流程**必须先产生一个东西**，才允许往下走。
24 
25## 先分流，再决定走多远
26 
27| 任务 | 路径 |
28|---|---|
29| 用户给了原稿或已认可方向 | 原稿即规格。单稿忠实深化，不另立主张、不强凑两稿；账本只记与原稿的偏差和理由 |
30| 对象已有上线页面 / 现有界面 | S1 先整页打开并评级（连贯/投入/完整/真实材料）。评级成立 → **校准**：保留其产品身份与最好关系，只修真实缺陷，不另立相反调性；评级不成立才走开放重做。**校准须从 incumbent 源码/实测提取字级、字重、留白节奏与材料取景并沿用**（原稿即规格包含排印与留白）；自有 tokens 只是开放设计的默认值，不得把 incumbent 更大的字级/更宽的留白压回自有刻度。**换算留白先看 incumbent 的 nav 定位模型**：fixed/overlay nav 的 hero padding 已含 nav 高度，若自己的 nav 在正常流，照抄该 padding 会把 nav 高度再叠一次（顶部空带翻倍）；应对齐"内容距视口顶的总距离"，不照抄 padding 字面值 |
31| 局部精修（改一个控件、一处间距） | 只重填受影响的账本行，跑相关地板与状态检查；不重跑五阶段，不借机翻新整页 |
32| 开放新设计、整体重做、"不好看但说不清" | 先过上一行的 incumbent 评级门，再完整六阶段（含 S1.5 内容优先级）、两稿对照 |
33 
34只有会改变任务方向或不可逆的问题才问用户；已获自主授权时写明必要假设继续，交付时列出假设。**视觉方向（明暗系统 / 底纹 / 排印配方 / 调性）恰恰是会改变任务方向的问题**——它决定素材能不能用、品牌身份是否延续、对比度怎么算、留白读不读得出来。0.2.4 把它误归为「可自行假设的细节」，是奶油色铺满所有产物的直接原因之一。因此开放设计必须走 **G0 方向确认门**（`references/direction-gate.md`）：先给 ≥3 套组合，再由用户选或明确授权自主。其余细节仍按「写明假设继续」处理，不要什么都问。
35 
36## 九条硬纪律
37 
38**⛔ 开放设计不出一稿。** 单稿没有对照，无法判断优劣；交单稿等于把选择权扔回用户，却没给依据。原稿还原与局部精修按分流走，不受此条约束。
39 
40**⛔ 账本不许有空代价。** "放弃"列写不出内容的行，判定为抄默认值——作废重填，不许留着。
41 
42**⛔ 不许事后美化。** 成稿之后改颜色、加阴影、贴渐变来"提升质感"，属于无依据修补。要改就回到 S2 或 S3 改账本，再重写受影响的区块。理由：整页的一致性来自账本，账本外的改动会成为孤岛。
43 
44**⛔ 禁忌只能来自受众×场合冲突，不能来自"像 AI/像模板"。** 把产品自身已成立的身份（配色/版式/组件习惯）写进禁忌，等于自废最强资产。registers 与禁忌是**镜头不是禁令**；唯一硬地板是工艺：对比、溢出、状态、层级、真实内容。某手法"好不好"由连贯+投入+产品契合判定，记进账本并写代价，不由预先黑名单判定。理由：暗色 cyan、feature 卡、stat band 在套路页里是 AI 味，在一个连贯投入的产品里是身份；禁手法本身会把好产品一起禁掉。
45 
46 
47**⛔ 排印不许停在默认。** 字体族、行距节奏、字距、线的性格、曲率、密度这六项，必须在 S2 从 `registers/type-recipes.md` 选**一整套配方**，并在 S3 逐行落账本。把「系统无衬线 + 1.6 行高 + 0/2 圆角 + 1px 通高线」当成「中性默认值」直接开写，等于没做选择——这套东西有明确性格（冷、方正、工程感），只适合一部分场合。理由：0.2.3 及之前所有产物共用一副脸，整齐干净但没有美感，根因是排印这一维根本不在账本里。一页只用一套（混搭仍是 AI 味），跨场合必须换得动。
48 
49**⛔ 方向不许由模型单方面定死。** 开放设计在 S2 之前必须过 G0：把 ≥3 套组合卡交给用户，每套写明换来 / 放弃 / 证据级别，由用户选一套、只换其中一维、或明确说「你定」。落盘 `design/00-direction.md`，S5 第八问回读。理由：0.2.4 及之前，底色由 `tokens/scale.md` 的全站纪律 + 账本模板示例值直接给定，`SKILL.md` 又抑制提问、多稿规则排除表面轴、交付时用户才第一次看到方向，于是「暖白纸」被当成无需询问的默认值铺满所有产物；而两条 R2 参考实测都是深底。**别把「清新风 / 科技感」这类整包形容词当选项**——它们是三个正交维度的捆包，用户没法只反对其中一项。
50 
51**⛔ 内容先于品类，品类先于风格。** S1 判完品类之后、**G0 方向门之前**，必须先过 **S1.5 内容优先级**（`references/content-architecture.md`）：把全部内容排成 P0/P1/P2/P3，**全页只有一个 P0**，桌面首屏信息单元 ≤7、移动 ≤5，并写出删除清单（删了什么 / 为什么敢删 / 移到哪）。没排位次就去问方向，方向卡只能比颜色，用户也只能凭顺眼挑——那正是 0.2.5 的问题。没排位次就进 S2，后面所有字号、面积、对比、留白的决定都失去比较基准，只能落到"都还行"的中位数。理由：0.2.6 实跑过了地板检查、九问过四条，用户评价仍是「顶多不丑，多惊艳没有」——不是配色错了，是页面没有一处敢比别处大。P0 的找法是找「**反常 + 具体 + 不可能被编造**」的那一个事实，不是问「哪个功能最重要」——那个问法只会得到功能清单，因为每个功能都重要。
52 
53**⛔ 底面从产品界面采样，不从品类名推断；深色不许是中性黑。** 品类只给**版式、排印、按钮、密度**的默认家族，**底色的唯一硬依据是产品自己的界面**。S1 必须打开一张产品界面截图，采样三点（界面底 / 卡面 / 主色）写进 brief 字段零；页面底面与「界面底」同族（`ΔL ≤ 6%`、色相差 ≤ 12°），**或者**在账本里写明为什么故意反差。深色底 `S ≥ 20%`，色相取自产品现有色系。理由：0.3.0 把 DiskWise 判成 C1a「深色仪表」取了 `#08090A`（S 6%，中性黑），而同一份 brief 的字段三 C10 写着「界面底色 `#F4F4F8` 浅冷白」、字段六 V5 写着「产品界面浅色 → 配浅底」——两条都在，一条没读，用户第一句就是「背景为什么用纯黑色」。机制上，中性黑没有底色偏差，产生不了纵深，所有元素像贴在一个洞上，观感是终端不是产品。判型的依据是**产品本身**，不是 incumbent 的营销选择：官网是深色，不代表产品是深色。
54 
55**⛔ 品类先于风格，版式与排印由品类决定。** S1 必须先从 `registers/category-prototypes.md` 判定品类（C1–C9），取得该品类的**默认家族**：卡面 / 墨色 / 字体 / 字号 / 行距 / 按钮形状与字重 / 曲率 / 线宽 / 版心 / 密度 / 首屏图文比，**十一项一起**（「底面」不在此列，按上一条从产品界面采样；品类表给的底面只能当 G0 甲案候选值，不能当结论）。不许跳过品类直接选「风格」，也不许把「科技感」当品类。理由：0.2.5 把表面做成六套抽象配方，还写了「以受众×场合为准，不以产品品类为准」——这句话是错的。品类是用户 1 秒能回答的客观事实，也是唯一有统计规律可实测的东西：美妆全行业 `border-radius: 0`（Glossier / Rare Beauty / 花西子实测），母婴按钮圆角 ≥12px（BabyBjörn 32 / Pampers 12），电商正文 12px（淘宝实测），开发工具 H1 字距 -0.02~-0.06em（Linear / Vercel 实测）。同一个纯白底，C2 电商是 12px 密排 + 8 圆角 + 图为主，C9 消费电子是 17px + pill + 996 版心——**底色相同、品类不同，页面必须长得完全不一样**。不走这一步，换多少种颜色都还是同一套模板。

57## 六个阶段（+ G0 闸门）
58 
59S1 读约束 → **S1.5 内容优先级** → G0 方向确认门 → S2 立论 → S3 记账 → S4 成稿 → S5 验收
60 
61| 阶段 | 动作 | 落盘产物 | 出口判据 |
62|---|---|---|---|
63| S1 读约束 | 把 brief 拆成七个字段，**判定品类（C1–C9）并取出该品类的默认家族**，实际打开视觉输入看并**测量** | `design/00-brief.md` | 前五字段全有值；「不能做的」≥3 条；字段七（视觉方向偏好 / 品牌约束）已填或明写缺失；**品类已判定，写明依据（哪一条 brief 事实 + 该品类哪条实测支撑），并已抄下十一项默认家族**；**已打开产品界面截图、采样三点（界面底 / 卡面 / 主色）写下十六进制**，并说明页面底面与「界面底」同族还是故意反差；视觉输入已看过、观察带证据级别（R2/R3 才允许写数字）、并有覆盖缺口说明，或明写缺失。缺关键项才问用户，其余写明假设继续 |
64| **S1.5 内容优先级** | 写主来路与第一疑问；把全部内容排成 P0/P1/P2/P3；写删除清单（删了什么 / 为什么敢删 / 移到哪）；逐屏定唯一动作；**逐个点数首屏元素** | `design/01-content.md` | **全页只有 1 个 P0**，且能填进「这一屏我只要你 ___」；首屏元素桌面 ≤7 / 移动 ≤5，是数出来的不是估的；删除清单 ≥3 条且三字段齐全；每屏有唯一动作，无"过渡屏"；P0 与字段二唯一任务是**同一件事**；P0 是「反常 + 具体 + 不可能被编造」的事实，不是功能名 |
65| **G0 方向确认门** | 以 S1 的品类默认家族为甲案，再给 ≥2 套**同品类内的合法变体或跨品类借用**为乙、丙案；每套写底面/按钮/字体/密度四项具体值 + 换来 / 放弃 / 证据级别；**并各配一句"这个 P0 放进这套材质长什么样"**；请用户选、只换一维、或明确授权自主 | `design/00-direction.md` | 候选 ≥3 套；甲案必须等于 S1 的品类默认家族（不许偷偷换掉）；每套四项具体值齐备；**每套都已说明与 `01-content.md` 的 P0 是否兼容**；「用户选择」栏是用户原话或明确授权；已写「选定品类 + 哪套 + 没选谁、为什么」；跳过提问时写明方向来源。校准 / 原稿还原 / 局部精修可跳过提问，但**不跳过记录** |
66| S2 立论 | 从 `01-content.md` 的 P0 推出一句话主张 + 三条承诺 + 一条放弃 + 锁定 G0 选定的品类、表面、排印与文案组织 | `design/01-thesis.md` | 主张**指得出它由哪个 P0 推出**（P0 是"给他看什么"，主张是"我为什么这样给他看"）；主张可被反驳；三条承诺每条绑一个可检验物；放弃有具体主语；已写「品类 C_ / 表面 S_ / 排印 P_」的依据与一条「没选谁、为什么」；**已写该品类的栏目顺序，并说明有无偏离**；**底面能指到 S1 采样的某一个具体色值，或写明反差理由** |
67| S3 记账 | 逐项决定取值，填六列 | `design/02-ledger.md` | ≥8 行有效行；「放弃」列无空值；≥2 行与默认值不同；**表面配方编号、方向确认状态、密度契约**三维必填 |
68| S4 成稿 | 写 2 稿（必要时 3 稿） | `design/pass-a.html`、`pass-b.html` | 两稿在同一根轴上取值相反，不是同稿换配色；两稿共用 G0 选定的表面配方；产品页必须出现产品真实界面/截图，页面完整（导航/证据/获取/FAQ/页脚）与必要动效，不止一个 hero |
69| S5 验收 | 十问 + 状态矩阵点检 | `design/03-critique.md` | 十问全答；矩阵逐格打勾或写「本页无此态」；第八问回读 `00-direction.md`、第十问回读 `01-content.md`；不通过项退回对应阶段 |
70 
71**产物必须落盘**。落盘不是为了存档，是为了让下一步有东西可读、让出错时能定位到是哪一步错了。没落盘的判断等于没做。

87## 参考准入（S1 必做）
88 
89**不能靠"挑得准"保证参考可靠，只能靠"复核得了"。** 一条没量过的观察，会被补全成看起来很精确的假数字——本 skill 自己犯过：三张真实定价页的六条观察，次日 DOM 实测四处被推翻，其中"列间距 ≈ 行距 2.4 倍"是凭空生成的（实测列间距为 0）。

91三条硬要求：
92 
931. **数值必须有出处。** 字号、间距、列宽、对比度一律用 `scripts/probe.mjs` 从 DOM 读；测不了的写「未测」，不许估。截图（R1）只能支撑定性描述，不能产生数字。
942. **每条观察写得出条件，否则不算观察。** 格式是「关系 + 在什么条件下成立 + 代价」。写不出条件的，本质是偏好陈述，不能进账本。
953. **标覆盖缺口。** 三张参考全是 SaaS/英文/营销页时，必须写明"中文排版、高密度后台、消费级、移动端本次缺失"，并把相关决定标为"无参考支撑，属假设"。承认缺失比假装覆盖安全。
96 
97**不问"是不是 AI 产的"**——从像素判断不了，问了也得不到可执行结论。改问"这个取值背后有没有可陈述的条件"：有条件的值得学，没条件的哪怕出自名家也只是抄了个数字。

103## 内容优先级准入（S1.5 必做）
104 
105**「顶多不丑」不是工艺问题，是主次问题。** 0.2.6 实跑把十条内容事实平均铺开，地板全过、九问过四条，用户评价仍是「顶多不丑，多惊艳没有」。因为页面上没有一处敢比别处大——**平均分配注意力 = 没有重点**，而重点不是靠字号临时拉出来的，是在排颜色之前就定好的位次。
106 
107四条要求：
108 
1091. **全页只有一个 P0。** 找法不是问"哪个功能最重要"（会得到功能清单，因为每个都重要），是问"**哪个事实最反常、最具体、最不可能被编造**"。三者交集极窄，通常只有一个；找到它，钩子、信任物、记忆点一次解决。DiskWise 的答案是「**没量到 11.6 GB**」——所有清理软件都说精准识别，只有它承认有一部分量不到。
1102. **首屏元素逐个点数**，桌面 ≤7、移动 ≤5。这是 0.3.0 最硬的一条可数判据：超了说明还没排优先级，只是把 P2 挪进了首屏。
1113. **删除清单必须写"移到哪"**。只写"删了"会变成丢内容；写不出"移到哪"的删除，通常是因为它本来就不该存在。
1124. **每屏有唯一动作**（继续滚 / 点主 CTA / 复制命令 / 看对比）。一屏没有动作，就是填充。
113 
114**边界**：内容少不是问题，平均铺才是。三条内容时不要拉长文案凑满，要把 P0 放大到占首屏主体——一条内容占七成屏读作"有主张"，三条各占三分之一读作"没做完"。这条直接解释了「空洞」。
115 
116P0 排不出来，或 P0 与 S1 字段二的唯一任务不是同一件事，**不许进 G0**——方向卡会变成纯色卡比顺眼，又退回 0.2.5。

118## 排印准入（S2 必做）
119 
120**整齐干净不等于有美感。** 0.2.3 及之前，字体族、行距、字距、线的性格在账本里没有对应行，模型只能用默认值填，再被一致性纪律锁死，于是所有页面长成同一副脸：系统无衬线 + 等宽数字 + 0/2px 圆角 + 1px 通高线 + 1.6 行高。这是机制缺陷，不是审美偏好问题。
121 
122三条要求：
123 
1241. **按场合选一整套配方**，不按品类、不按"好看"：`registers/type-recipes.md` 的六套（图纸 / 书卷 / 柔光 / 终端 / 暖商业 / 粗野）各绑定受众 × 任务时长 × 信任物类型。同一产品在不同场合可以换配方。
1252. **六项成组落地**：字体族 / 行距节奏 / 字距 / 线的性格 / 曲率 / 密度。只换字体不改其余五项 = 换字体，不是换系统。
1263. **标证据级别**：R2 实测可写数值；R0 通用排印知识必须写「未实测，属假设」。不允许把没量过的行距说成实测结论。
127 
128`tokens/scale.md` 的刻度是**所选配方内部**的格子，不是全站唯一一套；选 P2 就用 P2 的 1.80–1.90 行距，选 P4 就用 1.40，别拿 P1 的行高表去套所有页。

131 
132**「整齐的暖白」不是中性，是一种有性格的材料。** 0.2.4 及之前，`tokens/scale.md` 把「中性色带一点色相」写成全站纪律、`decision-ledger.md` 的示例行直接给了 `#FBFAF7`、六个 register 与六套排印配方全文无色值，三个叠加的结果是：无论什么项目，底纹都是暖白。而 `probe-2026-11-10.json` 里两条 R2 实测参考的 `bodyBg` 是 `rgb(13,16,22)` 和 `rgb(7,8,10)`——**都是深底**，模型却在 U5 自己写下「本版接受」把深色身份换掉。完整取证见 `diskwise-023/design/06-surface-audit.md`。

143## 记账规则
144 
145六列：`# | 决定 | 取值 | 依据 | 换来 | 放弃`
146 
147四条判定，逐行过：
148 
1491. **依据必须指向上游编号**——`T1`/`T2`/`T3`（thesis 的三条承诺）、`R2`（register 第 2 条手法）、`C1`（brief 的内容事实）、`V1`（brief 字段六里实际看过的视觉观察，须带证据级别）。写"感觉更好""更现代""更协调"一律视为空。
1502. **换来必须是用户可感知的结果**——对齐、层级、可扫读、可印刷、加载更快、手指不误触。不能写"更高级"。
1513. **放弃必须有主语**——放弃了什么具体体验，说得出代价。写"无"的行作废。
1524. **单页内**同一维度只允许一条有效行——出现两个圆角体系、三种间距节奏，必须合并，或明写"为何并存"。**但这条只约束一页，不约束跨场合**：不同受众 / 任务时长可以选不同配方，只要账本写清选择依据。把「一套排印走天下」称为体系，是把默认值包装成决策。
1535. **0.2.5 新增三维必填**：`表面配方编号 S_`（并逐一落地七项成组值）、`方向确认状态`（指向 `00-direction.md` 的用户原话或授权）、`密度契约`（字数 → 版心上限、两栏内容高度差上限、每块空白的用途、section 最小填充率）。前两维修的是「方向由谁定」，第三维修的是上一轮留白诊断里「内容腰斩后没有任何一步有权决定版心」的洞。
154 
155第 3 条是整个 skill 的分水岭。**能说出代价的选择才是选择，说不出的是默认值。**

157## 多稿规则
158 
159两稿必须在**同一根轴**上取值相反，轴来自 thesis 的某一条承诺。
160 
161- 合格：A 用「能力对齐表」承载档位差异，B 用「三列叙事卡」承载差异（结构轴相反）
162- 合格：A 把价格放到视觉第一层，B 把能力差异放到第一层、价格退到第二层（层级轴相反）
163- 不合格：A 蓝 B 绿（表面轴）
164- 不合格：A 圆角 4px B 圆角 12px（只换数值、没换系统，仍是表面轴）
165- 合格（0.2.4 新增）：A 用 P1 图纸（1.6 行距 / 1px 通高线 / 等宽数字）、B 用 P2 书卷（1.85 行距 / 衬线标题 / 细线大留白），**且能说清哪套更贴 brief 的受众×任务时长**——这是排印轴，不是表面轴
166 
167原因：表面轴的两稿证明不了哪个决策更好，只能证明哪个配色更顺眼。那不是 taste，是偏好。
168 
169**0.2.5 边界说明**：这条排除的是「把换色当成两稿的对照轴」，不是「颜色不许让用户选」。方向选择已前移到 G0 由用户完成，是两稿共同的地基。**不要往多稿规则里加「至少一稿换底色」**——那会让两稿退化成色卡，并让「哪稿更好」变成「哪个颜色顺眼」。两条 rule 各管一段：G0 管「方向谁定」，多稿规则管「决策怎么比」。

171## 验收契约（所有路径共用，只立一次）
172 
173- **功能底线先于审美**：核心任务链实际走通、内容真实完整、无安全问题。十问全过不能替代功能验证。
174- **首屏只有一个 P0（S5 第十问）**：数首屏元素（桌面 ≤7 / 移动 ≤5）；「这一屏我只要你 ___」能一句话填完；`01-content.md` 的 P0、`01-thesis.md` 的主张、截图里视觉权重最大的那块，三者是同一个事实。这是十问里**唯一肯定式**的一问——它要求页面必须有一处明显比别处大，而不只是"没有缺陷"。
175- **方向确认门回读（S5 第八问）**：`00-direction.md` 有 ≥3 套候选、用户选择是原话或明确授权、成品与选定 `S_` 成组一致。「用户没回」不许写成「用户认可」；未确认方向要标在已知短板里。
176- **空白有没有任务（S5 第九问）**：内容量 × 版心、两栏配重、每块空白的用途。上限检查不只查缺陷，也查「空洞」这类关系问题。
177- **截图对应当前源码**：目标视口、真实内容；改过代码就重拍，不用旧图证明新版。
178- **与天花板并排比（渲染后，有参考/校准必做）**：把成品与 incumbent/参考在**同视口**渲染截图并排对照，差异逐条归因到关系（顶部空带、字级、字重、取景、层级），而不是归因到"规则没写"。对着规则自检不算验收。校准继承的是**产生取值的系统**，不是源码字面值：对齐靠测量渲染结果（如内容距视口顶的总距离、nav 是 fixed 还是正常流），不靠抄 padding。
179- **独立看图（必做）**：有独立读图执行者时，只交任务、约束与截图，暂不给设计理由；没有就按同一流程自看并**标明"非独立"**。生产者自评不能单独作为审美结论。
180- **三分报告**：功能验证、执行者审美判断、用户认可分开写。未运行的不写通过；用户没说的话不写成用户认可。
