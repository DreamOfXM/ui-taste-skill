# 2.0 设计决定

用户确认：优化现有入口，通过 Git 维护；保留参考、实拍、偏好积累，重写生成流程及判据引用。此次不改其他共享 skill，不发布远端仓库。

## 问题与方案

旧入口把较多篇幅用于工具调用和失败历史，通用审美裁决依赖特定出版风格的数值，且将信息架构排除在覆盖范围外。新版在同一名称下提供自足的设计工作流，工具变为按需辅助。

- 主文件负责意图、方向、迭代和交付，细节分到 generation/review/tooling。
- 方向探索可联合改变结构与视觉；收敛后控制范围。取消固定三骨架和每轮必须换脸。
- 信息组织与核心操作纳入评审，保留平台差异与真实状态验证。
- 不修改共享 BEAUTY_RUBRIC 或第三方 skill；在本入口撤销其通用裁决权，避免影响其他项目。
- 保留三个画板模板作为可选初览工具，不把它当原尺寸验收。
- 移除与 UI 路由无关且含未完成模板的 market-discovery 文档；原文在 baseline 标签可恢复。

## Git 与安装

独立仓库保留原始快照及 `baseline-v1.1.1` 标签；重构单独提交并标记 2.0。
原安装目录位于本次会话只读范围，因此先完成可写仓库；切换工具默认预览，显式运行才备份旧目录并链接到仓库。既有 Qoder 符号链接无需重建。

## 验证边界

检查格式、相对引用、元数据、版本差异和安装/回滚行为；用具体场景检查指令是否导向合理决策。文档检查不证明审美提升。
实际效果需要后续用同一个真实任务对照旧/新版，保持内容、功能与视口一致，由用户比较并完成核心操作。本次没有指定要重做的产品，不虚构视觉效果对比。
