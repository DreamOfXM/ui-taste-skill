43## 用法
44 
45选中技能，给出页面、受众和必须保留的事实：
46 
47```text
48用 ui-taste-skill 重做这个定价页：三档，中间档推荐，给工程团队评估。
49保留现有文案与价格事实，缺的信息标 [待补]，不要编。
50```
51 
52第一次应拿到 **5–6 套方向清单**——每套写清借了哪个已存在的类型、**那个类型自带的规矩是什么**、**破例清单**（破在哪 / 破了哪条规矩 / 为什么该破，可以多处，理由必须指向页面上的具体内容或文案）、底面/按钮/字体/密度四个具体值、各自换来什么放弃什么——而不是一个整页。规则要求任意两套之间**构图、材料、对象表达三轴里有两轴不同**：只有配色不同的算同一套，去色并排看不出差别的不算交付。你可以现在挑一套、只反对其中一维，也可以说「都画出来我再挑」（默认走这条）。回答写进 `design/00-direction.md`，交付时按它验收。

88## 流程
89 
90| 阶段 | 干什么 | 落盘 |
91|---|---|---|
92| S1 读约束 | 七个字段、判品类 C1–C9、采样产品界面底色 | `00-brief.md` |
93| S1.5 内容优先级 | 排 P0/P1/P2/P3，全页一个 P0，点数首屏元素 | `01-content.md` |
94| G0 方向确认门 | 甲案 = 品类默认家族，再加 4–5 套互不相同的方向 | `00-direction.md` |
95| S2 立论 | 主张、三条承诺、一条放弃（全版本共用） | `01-thesis.md` |
96| S3 记账 | 六列：决定 / 取值 / 依据 / 换来 / 放弃；跨版取值按版本分列 | `02-ledger.md` |
97| S4 成稿 | 5–6 版关键屏：首屏 + 本产品最难那一屏，同内容同视口 | `v1.html` … `v6.html`、`compare.html` |
98| S5 验收 | **三层逐版各跑一遍**：① 地板 = 十一问 + 状态矩阵；② 整体感 = 回读门（独立实例盲看三问）；③ 优劣 = 同视口匿名并排二选一。不过的改到过，不删版 | `03-critique.md` |
99 
100S1.5 排在 G0 之前：没排位次就问方向，组合卡只能比颜色，你只能凭顺眼挑。**每一步的产物是下一步的唯一合法输入**——页面不对，先看 S5 哪一问不过，那一问指向哪个阶段，那个阶段的产物里必有一行是错的；一次性生成只能整页重写，且说不清哪里错。

104## 边界
105 
106- **保证下限，不保证上限。** 十一问、状态矩阵、账本都是**地板**：全过只证明「这页没塌」，不证明「好看」。第十问管大小、第十一问管能量（强调落点、字号跨度、材质类数），它们把「往下限收敛」变成有数字的门槛，但**数字拦得住「平」，拦不出「好」**——阈值标定自一份定价页、一个视口的三稿（n=3），不是通用美感阈值，换品类换视口要现测。整体感由**回读门**取证：换一个没看过账本与主张的独立实例盲看画面，回答「这页自己的规矩是什么 / 哪几处不合这规矩 / 每处为什么该破」，原话照录，读不出就是不过。它同样只判失败，判不了优秀；优秀靠同视口并排二选一，结论归你。不承诺任何模型必然产出好看界面。
107- **破例可以多处，判据不是数量。** 高级感 = 页面自己立的规矩站得住 + 破规矩的地方破得有理由。规矩指**成稿画面**，不是账本；破例一处也行五处也行，但**每一处的理由必须能只看画面就说出来**——指向具体内容或文案（「这个数字是全页唯一的结论」）合格，「为了有层次」不合格。需要设计者开口解释才成立的破例，就是失败的破例。
108- **不自动判分。** 十一问和矩阵是清单不是脚本；唯一例外是第十一问的落点 / 跨度 / 材质可由 `scripts/probe-energy.py` 实测，但它量不出「为什么是它」那一半。**回读门更不可能脚本化**——它要一个没继承你理由的独立实例真看画面，产出是原话记录不是分数；没有独立执行者时只能自看并标明「非独立」，那不构成整体感结论。G0 是自然语言契约，没有 schema 校验，模型伪造一份「用户确认」机制识别不了；P0 是否真的「不可能被编造」也只能人眼复核。
109- **它会问你。** 开放设计动笔前必须过 G0。无人值守时按「写明假设继续」执行，并把补上的假设单列在交付里。
110- **它不替你排序。** 地板只回答「这一版有没有塌」，回读门只回答「这一版有没有自己的道理」，都不回答「哪版最好」。5–6 版全部合规之后，谁胜出由你看着画面选；数字最高的那版未必是你想要的（实跑里出现过强调落点 16 处全是 1px 描边的版本，门过了，画面比不过门的另一版平）。
111- **不做组件库。** 只生成这一页需要的，不产出通用 Button / Card。
112- **上下文预算不低。** 上面那 19 个文件一次实跑都要读，客户端上下文吃紧时先算这笔账；预算不够时的正确做法是 6 版收到 5 版，不是跳过探针或回读门。
113- **取证脚本要本机 Chrome。** 五个 `scripts/probe*` 里三个用 headless Chrome 读 DOM 拿实测值（R2 级）：能量门槛 `probe-energy.py`、图片是否真的加载 `probe-assets.py`、命令与长 URL 是否溢出 `probe-overflow.py`。找不到浏览器就退回人工测量并如实标明；两个 `.mjs` 需要 Node，三个 `.py` 只需 python3 标准库，都无 npm 依赖。
114- **面向网页。** 交付物是 HTML/CSS。原生 App 与 macOS/iOS 控件工艺在 0.3.x 没有对应模块，需在目标平台另行验收。
115- `skills` 安装器支持某个客户端，不等于本技能已在该客户端验证过。
116- **与另外两类 design skill 的分工**：约束类管下限防丑，货架类管选项广度，这个管取舍与方向归属——回答「这些约束下你为什么这么选、付了什么」，并在动笔前把选择权还给你。
