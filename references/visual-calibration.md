# 从优秀画面提取美感，而非复制皮肤

## 选能提高目标的参照

用户本次指定原稿与项目认可画面决定必须尊重的视觉方向；开放任务则主动寻找任务、平台、内容密度匹配的高水准作品。再从排印、出版、展陈、数据图形等邻近领域寻找可迁移关系，而非把一个陌生品牌完整贴到产品上。

参考必须有你实际看见的优点：构图有力量、字块与留白有节奏、材料经过选择、细节成套且真实内容依然优美。品牌知名、流行风格、获奖标签或一张漂亮缩略图不自动证明适合本任务。操作软件看工作页、详情和状态；营销首屏只能证明展示表现，不能证明内部工作体验。

每个候选方向选一个主参考，必要时加一个有明确职责的补充参考。探索不同方向不等于把多张图的导航、按钮和背景拼在同一页。内置[视觉示范](visual-examples.md)用于理解关系，不是质量上限；没有外部参照就明确依据有限，但继续认真设计，不自动降为普通模板。

## 同时提取意图与规格

| 实际看见什么 | 交给实现什么 |
|---|---|
| 第一眼的落点及周围留白 | 核心对象、视觉重量、位置与安静区；说明为何有吸引力 |
| 不同区域的节奏 | 目标视口、共同轴线、边距、区域宽度/比例，以及密到疏如何过渡 |
| 标题、字样、正文形成的形状 | 字面大小、轻重、行数、行长和段落密度；不只抄font-size |
| 颜色的面积与关系 | 哪处成为色彩场，哪处只表达动作或状态；明暗和饱和度怎样衬托内容 |
| 图片或图形的具体品质 | 主体、裁切、清晰度、光线/色调与排版关系，所需素材及来源权限 |
| 边缘、表面和控件 | 哪些边界靠位置/色差/线条建立；圆角、图标、浮层如何归属同一语言 |
| 对象变化前后 | 位置、焦点、状态、反馈与动效；没观察操作就不推断时序 |

能从源码或规格测量就记录实际值；只从截图判断的尺寸标为估计。先形成足够实现关键屏的视觉执行包，不造巨型token表。最值得保留的是产生美感的关系，不一定是特定颜色或字体名。

## 再适配真实内容

用当前语言、长标题、足量记录与选中状态替换参考内容。先保留主要构图和视觉重量，再校准字块、素材与密度，最后处理表面细节。用户自己的明确原稿优先忠实还原；其它作品借组织语法，不复制商标、专有插画、文案或品牌身份。

参考里的大图在本项目没有对应材料，不要把空卡片放到原位置：获得合适素材，或重新安排仍有表现力的构图。参考只有三条记录而产品有三十条时，重估列表和滚动，不能删掉内容维持截图。中文字形和英文的字面、断行与密度不同，必须实际试排。

在参考与实现之间，最常丢失的不是色值，而是主角的尺度、字块的宽度、图片的裁切和空白所在的位置；先修这些大关系，再磨小细节。

## 把一处参考关系追到实际组件

不要只写“参考了某产品”。保留三处关键映射，每处记“参考区域 → 当前组件/选择器 → 要保留的关系 → 当前帧偏差”。这是实现约束，不是自动测量证明。参考来自截图时，数字只是初估。

例如参考的目录紧凑、对象预览舒展，而当前实现却把两侧都做成等宽卡片：

1. 标出目录、对象预览与操作三块，先画同尺度区域分配。保留本项目全部对象与操作，不复制参考内容。
2. 在当前组件中只改变列比与包围关系，让主对象取得空间；暂不换字体、颜色和素材，避免无法知道什么改动起作用。
3. 运行同一对象的前后帧，裁出相同区域检查：预览是否真的变大，列表是否仍可读，控件是否跟对象走，而非只是多了一块空白。
4. 如果无改善，检查素材或对象本身是否值得放大；必要时换主关系，不强迫实际内容服务参考。

这只是推演，不冒充一组已经跑过的效果数据。实际项目必须留下自己那组前后帧；局部裁图只用于诊断，最终同时看完整屏，避免局部变美、整体失衡。

## 合格但普通时，用正向实验提高画面

| 已有画面 | 可试的成套提升 | 观察什么 |
|---|---|---|
| 全部规整却没有主角 | 让最有内容价值的对象拥有更强尺度或位置，其余围绕共同轴线退后 | 视线是否更明确，核心内容是否值得看 |
| 留白很多却显得空 | 收紧对象内部，把空白集中到字样/材料周围，形成密疏段落 | 空白是否衬托内容而非稀释任务 |
| 只有一张好图，界面像默认模板 | 用图片的裁切、色彩与形态重新确定字块、表面和控件语法 | 内容与界面是否终于属于同一作品 |
| 文字都可读但无韵律 | 重排最长标题的断行、段落宽度、轻重和注释关系 | 文字是否有形、有停顿而不失阅读效率 |
| 工作页正确却僵硬 | 调整列表与当前对象的密度对比、次级表面和选中反馈 | 精密感是否来自整体关系，而非把字变小 |
| 静态好看，操作后散掉 | 稳定选中对象的身份、焦点和局部结构，设计一次进入与返回 | 用户是否能追踪对象，视觉语法是否延续 |

每次选择最影响整体的一个层级改变，不把实验变成统一配方。深浅、饱和度、装饰数量不是美感排名；比较“原关系 → 新关系 → 实际结果”，不是比较谁更符合风格禁令。

## 已实际查看的研究入口

以下仅记录2026-10-28维护时观察的有限范围，执行新任务仍需打开当前图，不假设页面没变。第三方图片未打包分发，离线示范也不冒充这些产品。

- [Linear 官方 UI 改版文章](https://linear.app/now/how-we-redesigned-the-linear-ui)：看[工作页](https://webassets.linear.app/images/ornj730p/production/2ef6f0599f502940b18eae2c37a1fbd9ee09be25-2352x1380.png)与[对齐示意](https://webassets.linear.app/images/ornj730p/production/11d896d9d6ec5b3e1e2ae8ad6601a6765aac742f-2352x2808.png)。细分的近黑表面、紧凑侧栏、宽工作区与稳定的图标/文字轴线共同产生精密感；不能把截图灰字直接当对比度规范，也不以静态图声称交互已验证。
- [Cosmos 当前入口](https://www.cosmos.so)：维护时实际打开的是居中大字、字句内小图与搜索框组成的入口；图像参与句子的意义，工具直接进入构图。值得借鉴的是文字、材料与动作的整合，不是把居中Hero复制给软件；未据此验证其登录后收藏界面。
- [项目雷达旧稿](../examples/project-radar/evidence/before-desktop.png)：既往认可的是当时整体画面与场景，不把深绿、曲线或三列推荐卡泛化成用户永久皮肤。

复查用同内容、同视口、同状态的当前截图。记录最重要的两三处位置与关系；图像不能读取或来源失效就说明证据缺口，不拿文字解释补造“已看过”的事实。
