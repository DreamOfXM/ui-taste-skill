# 生成引擎 —— 从描述到高保真稿（防换皮协议）

> 方法论来源：JimLiu/baoyu-design（MIT）对 Anthropic Claude Design 技能的本地重打包，
> 2026-09-26 蒸馏进本链。本文件只管"怎么生成"；审美判据真源在 design-inspiration，
> 机器闸门见 SKILL.md §二，两者都不在本文重复。

## 一、生成流程（每个新项目都是全新开始）

1. **问透再动手**：范围、视觉方向、要几个变体、要新颖还是惯例。参考对质量影响最大——
   本链固定从 `vault/refs{,_beauty}/` 取 ≥2 张真图作上下文，冷描述生成必然回落训练集均值。
2. **读账**：项目 `DESIGN.md`、`choices.log`（有则必读——上轮毙了什么、为什么，这轮别重犯）。
3. **变体画板**：≥3 个结构互异骨架放**同一画板并排**（每个变体一个 artboard，可全屏聚焦对比），
   不是 3 个散落文件——并排才比得出结构差异，散文件必然看着都行。
   模板：`~/.agents/skills/ui-design-router/assets/variant-board.html`（URL 参数 `?a=…&b=…&c=…`）。
4. **活体验证**：localhost 起服务预览（**禁 file://**，多文件原型会静默加载失败）、
   控制台零错、截图过目，然后才交付。预览 URL 是交付物的一部分。
5. **状态落账**：`design-state.json` 记 `approved` / `changes-requested`。

## 二、结构发散（"每次换皮"的解药，强制）

- 结构轮必须产出 **≥3 个结构互异骨架**，来自组织轴菜单（design-inspiration「结构轮」）的**不同轴**。
- **结构互异的判据**：阅读顺序不同 + 区块语法不同（开头/主体/收尾怎么组织）。
  只把同样的块换个排列 = 没有发散，重做。
- **未过结构轮（锚定 + 盲评选出骨架），禁止进皮肤轮**。直接开始改颜色/字体/圆角 =
  本轮还没开始。
- 变体意图四分法：用户要"新方案"时先问清——新结构、新视觉、新动效、新文案是四件不同的事，
  别混着做。

## 三、工艺硬规则（工程级下限，闸门之外的第二层地板）

**排版**：移动端点击目标 ≥44px；正文 `text-wrap: pretty`；CJK 混排用 Latin 优先字体栈 +
行高 1.7–1.8 + `lang` 标签。

**色彩**：优先品牌/设计系统色；要扩用 oklch 调和推导，不凭空造色；文字对比度 4.5:1（大字 3:1）；
文字压在强调色/照片上必须全不透明。

**布局**：flex/grid + gap，不走 inline flow（对后续编辑更鲁棒）；流式页用 `max-width` +
`minmax(0,1fr)`、不定死高度；固定画布（幻灯/海报类）保持像素尺寸、自实现 scale 缩放。

**工程**：CDN 依赖必须 pinned 版本 + integrity hash；CSS 变量做主题，inline style 只留动态值；
同名样式对象禁止出现在多个并排模块里。

## 四、反 AI 感与反填充

- 生成时直接绕开（检测另有 impeccable，两层保险）：滥用渐变背景、emoji 装饰、
  「圆角 + 左边框强调色」容器、烂大街字体（Inter / Roboto / Arial / Fraunces）。
- **永不填充**：不拿占位文字凑版面。"空"是布局问题，不是编内容的问题；想加内容先问，不单方面加。
- **一千个否定换一个肯定**：每个元素都要配得上自己的存在。
- 不模仿在世艺术家的标志性风格；不删除必要的署名。

## 五、迭代纪律

- 用户指着具体元素提意见时，按该元素的 DOM 祖先链定位源码，**打最小补丁**——
  不因为重写更省事就重建。
- 聚焦编辑时冻结结构/文案/交互，只动被点名的部分。
