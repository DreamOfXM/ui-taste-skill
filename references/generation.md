# 从产品任务到完整设计方向

新设计、整体改版或方向探索时阅读。交付目标是一个有明确取舍、能实际使用的界面，不是完成固定数量的画板。

## 1. 先判断这一屏在做什么

读真实内容、现有流程和平台约束，找出首要任务、次要任务、必要状态与最大理解成本。每一屏应有可说清的作用；不是每一屏都要有一个大按钮或视觉高潮。

| 场景 | 设计重心 | 易走偏的地方 |
|---|---|---|
| 营销/品牌页 | 理解价值、相信证据、采取下一步；主视觉、叙事顺序和素材质量协同 | 用巨型标题和装饰填补产品信息不足 |
| 高频工具/后台 | 找对象、判断状态、完成操作、持续工作；信息密度与反馈优先 | 为显高级扩大留白、隐藏常用操作、强塞 Hero |
| 内容/阅读 | 清楚进入正文、持续阅读、定位和回访；文字与图像的节奏 | 每段都变卡片，或把某种杂志风格当通用审美 |
| 原生 App | 平台导航、手势、输入、系统区域与状态连续性 | 把手机网页缩成 App；只有静态首屏，没有返回与输入体验 |

信息架构先解决“什么同时可见、什么分步出现、什么需要一直保留”。低频不自动等于隐藏：结合查找成本、风险和频率决定。关键解释在用户需要的时刻出现，不能为了整洁把必要信息全塞问号。

## 2. 校准品味，拆解参考

优先使用用户已经认可的画面和已有反馈。确实缺方向时，可用一组差异明确的图让用户指出喜欢的部分；能继续推进的工作不必等待非关键偏好。

为主要设计问题选少量真正相关的参考。至少看过其实际图像后才能引用视觉判断；只有网址或读过 CSS 不算看过设计。工具和 App 参考应覆盖相关内页或交互状态，不能只看宣传首屏。

每张参考提炼具体决定：

- **借什么**：信息分组、阅读顺序、文字比例、密度、图像构图或反馈方式。
- **为什么**：与本项目的人、任务、内容、平台有什么共同点。
- **如何转化**：换成本项目真实内容后，哪些比例和结构需要调整。
- **不借什么**：不匹配的商业叙事、平台组件、品牌资产和装饰。

参考不是拼贴素材清单。综合时保留一致的视觉逻辑，不把不同站点的导航、卡片、标题直接拼在一起。参考无法取得时使用已有材料继续，注明方向依据有限，不伪造“已看图”。

对偏好保留因果和范围：“喜欢紧凑工具页里清晰的行分组”，比“喜欢白底”更有用。尚未确认的假设和执行者意见不写成用户已认可。

## 3. 提出能改变最终画面的主张

将体验词变成决定。以清理工具为例，“安心、可控”可以落实为：空间类别可理解、清理对象和范围清晰、结果可追踪；画面主角可以是这些核心对象，动效帮助理解状态变化。不要借此给所有清理工具规定同一布局。

每个方向回答：

1. 用户先看哪里，然后做什么？
2. 核心对象用什么方式呈现，为什么适合当前内容？
3. 排印、色彩、素材和交互如何支持同一种体验？
4. 它牺牲什么，在哪种情况下不如另一个方向？

“专业蓝 / 高级黑 / 温暖白”只是配色名，不构成方向。方向差异可以来自组织方式、阅读节奏、视觉表达或关键交互，不强迫每个方向都改信息架构。

不确定时，先用同一份真实核心内容制作少量完整的关键屏样稿。重要的是能看出取舍，避免把全部预算花在三套完整产品上。已有方向明确则直接深化。

多方案在相同视口、相同内容和相同状态下比较，保留原尺寸查看入口，避免窄栏缩放导致误判。现有 [variant-board.html](../assets/variant-board.html) 仅适合三方案初览；它的并排窄窗不能作为桌面布局验收，需另开目标视口。两方案不必为了使用模板凑第三版。

## 4. 将方向落实到细节

若用户要求先选稿，此阶段仅在候选原型中按需表达关键操作，等其选定后再实现正式产品。实施时先做关键屏与一个核心操作，尽早真实渲染，再逐步扩展；形成能解释当前设计的排印、间距、颜色和组件约定，不先造一整套用不到的 token。

- **排印**：按实际语言、字体和阅读距离校正字阶、行长、行距与断行。中文和英文分开观察；负字距、细字重、大标题都不是默认答案。用最终文案检验，长标题不能靠截掉关键内容过关。
- **空间**：用邻近和留白表达关系；相似关系保持一致，允许内容或视觉对齐需要的例外。检查画面重心、边缘对齐、疏密变化，而不只统计间距取值数量。
- **色彩与材质**：明确背景、内容、操作和状态各自的职责。保留必要语义，不为减少颜色数量损害理解。阴影、边框、渐变和纹理只有在帮助层级或产品表达时才值得使用。
- **素材与文案**：主图、截图、图标和文字共同构图。使用真实、获准或清楚标示的示例素材；没有合适素材时重新组织画面，不编造社会证明或塞无关插图。
- **交互与动效**：让用户知道动作是否发生、当前在哪里、下一步能做什么。动效帮助连续性和反馈，尊重减少动态的偏好；不为展示技术延迟常用操作。

“一个值得记住的地方”可以是清楚呈现核心对象、恰当的图像叙事、精确排印或舒服的操作反馈。它不一定是静态截图里的特效，也不必每屏复制。

## 5. 收敛

按 [review.md](review.md) 查看真实画面和完成关键任务。每轮先修影响最大的具体问题；写清看到什么、改变什么、预期改善什么，再复看受影响的状态。

局部修改冻结无关范围；方向失效时允许回到概念重新组织。不要为了“反雷同”在已经认可的方向上反复换脸。美感尚未达到预期时，先找具体原因，不自动加装饰或再装一个 skill。
