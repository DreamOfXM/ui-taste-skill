# 通用品味基础：好在哪里，怎样做到

这里教的是正向目标，不是禁令。只读与当前画面弱点匹配的一节，读完回到真实内容试排。所有数值都注明视口、语言与材料，是**试排起点**，不是风格门槛；换字体、换语言、换平台后必须重测。

每节按同一顺序写：值得追求的画面 → 实际截图里成立的关系 → 变量怎样互相牵动 → 可试初值 → 另一个同样好的方案 → 迁移 → 失效边界。看到"初值"先问它服务哪个关系，再决定抄不抄。

本文件的截图与初值来自**实现演示**级样例（分级与准入见[示范索引](visual-examples.md#参考质量分级与准入)）：它们证明关系可落地，是下限与试排起点，不是"好品味"的唯一答案或上限。当前全库没有经用户认可的标杆；把任一截图抄成标准答案，恰恰违背这里教的关系推导。

## 1. 注意与构图

**值得追求的画面**：一眼能说出这屏在让人看什么，其余区域安静地支撑它。重心可以是一个大对象、一片密集数据或一段有形标题，不等于巨大标题。

**实际画面**：[索引桌面](../assets/reference-evidence/workbench-desktop.png)与[字间工作面](../assets/reference-evidence/studio-instrument-desktop.png)。前者 1440 宽时深色导航 216、右侧详情 320，中间约 904 的工作面承担全部对象；后者目录 326，右侧试样面约 1024，单个字样放到约 110px。两屏都没有把标题放大到压过内容。

**关系描述**：导航深色却只有 216 宽、内容少、强调受控，所以它稳定边界而不抢主角；工作面浅色、面积最大、承载全部判断依据，所以它是重心。字间把"当前对象"从目录里取出放进一个有独立顶栏的大面板，尺度差本身就是"你正在看这一个"的说明。安静区不是空白装饰：索引的详情栏在未选中时仍解释这里会出现什么。

**联动变量**：主对象宽度变大 → 陪衬字阶要退一档而不是跟着涨 → 目录行高可以收紧 → 但目录里的对象名仍须可辨。反过来，若主对象材料本身不值得放大（一张模糊图、一个三位数字），先换材料或换主关系，不要靠加空白假装展陈。

**可试初值**（1440×960 中文桌面 Web）：主工作面占剩余宽度，常驻导航 192–224，检查器 280–340；页标题 26–28 而对象内容 14–21，让标题只比内容重一档。三栏不是必须，任务不需要常驻导航就去掉。

**另一个好方案**：[字间展陈](../assets/reference-evidence/studio-gallery-desktop.png)把集合做成约三倍于详情的面积，用 7:5、5:7 交替分配让浏览本身有节奏。它适合"先感受再挑选"，索引适合"先找到再检查"。两者都成立，选哪个取决于用户这一步在发现还是在处理。

**迁移**：换成照片、订单或波形时，保留"集合与单体如何争取注意"的比例关系，替换材料本身。把六个字样换成六个统计数字不会得到展陈感，因为数字需要比较而不是凝视。

**失效边界**：缩略整屏仍说不出主角时，问题在构图或材料，不在颜色；此时加渐变、加阴影、换字体都无效。

## 2. 字块与排印

**值得追求的画面**：文字像被编排过的内容——标题有轮廓，正文有纹理，旁注有轴线，数字有列位——而不是随机落在框里的字符串。

**实际画面**：[索引桌面](../assets/reference-evidence/workbench-desktop.png)的列表与详情，[间的阅读页](../assets/reference-evidence/editorial-article.png)。索引里对象名 14px/1.4、来源 12px/1.4 且只隔 4px，两行合成一个紧凑字块；详情标题 21px/1.55，摘要行高放到 1.85。同一份内容在列表里压紧、在详情里舒展。

**关系描述**：列表行的重量来自"名称比来源重一档＋两者贴近"，不来自把名称放大。来源用位置和 4px 的贴近说明归属，不用浅到读不清的灰。详情的 1.85 行高让连续中文段落形成可扫的横向纹理，而列表若也用 1.85 就会把 66px 的行撑散。字阶差是角色差，不是装饰差。

**联动变量**：行高从 1.4 改到 1.6，两行名称的总高就变，`min-height` 只是下限不是上限；同时来源的 4px 间距要重看，否则名称变松后来源显得漂。窄屏把名称从 `nowrap + ellipsis` 改成允许换行时，必须一起改行高（索引实际从 1.4 改到 1.6）并放弃固定行高，否则第三行会被裁掉。

**可试初值**：中文长正文每行约 24–36 字、行高 1.6–1.8；列表对象名 14–15、次要 12–13、行高 1.4–1.5；详情标题 20–24、行高 1.5–1.6。移动中文阅读另见[移动服务拆解](lessons/mobile-service.md)，不要把桌面密集值套给手机或年长受众。

**另一个好方案**：[间](../assets/reference-evidence/editorial-desktop.png)让展示字本身成为构图材料，正文退回受控行长。它适合刊物与专题；同一套大字放进高频表格会让每次扫读都付出代价。两种排印都好，差别在阅读是一次性的还是每天几百次的。

**迁移**：换语言先重测字面与断行，不继承英文紧字距；换字体先重排最长标题，再决定组件高度。字块关系可迁移，具体像素值不可直接迁移。

**失效边界**：只换字体名而没有改变字块宽度、断行与轻重时，画面不会变好。标题出现"一行很满、一行两个字"的尾巴，先调内容宽度与字重的相邻值，不插硬换行。

## 3. 密度与节奏

**值得追求的画面**：信息丰富但视线有秩序；密与疏各有原因，停顿在告诉用户"这里换了一组"。

**实际画面**：[索引桌面](../assets/reference-evidence/workbench-desktop.png)。表头 36px 的浅灰带把列名与数据分开；数据行 `min-height: 66px`、行内名称与来源只隔 4px、行与行之间靠 1px 分隔线而不是大间隙；详情里元信息组上下各 19px 内边距并由两条细线夹住，摘要再另给 24px。

**关系描述**：这里至少有三种停顿在同时工作——行内 4px 说"这两行属于同一个对象"，行间分隔线说"下一个对象"，详情里的 19/24px 说"换了一类信息"。精密感来自这套层级，而不是把字缩小。若把所有纵向间距都设成 12px，画面仍然整齐，但阅读节拍变平，用户要靠自己数行来分组。

**联动变量**：行高收紧 → 组间停顿必须相对变大，否则整页糊成一片；列数增加 → 先固定数值与日期的列位，再让名称列吸收剩余宽度；进入详情 → 行高与段距整体放开一档，因为任务从扫读变成阅读。密度模式切换要成套改，不能只改一个 `gap`。

**可试初值**（1440×960 中文桌面）：单行对象 40–48，两行对象 56–66；组内 4–10，组间 20–28；列间距 16 起步，数值列右对齐或按小数位对齐。边界频率宁少勿多：一条分隔线能说明归属时不要再加外框。

**另一个好方案**：独立可拖拽、需要强分组或多面状态的卡片列表。它牺牲一些扫读速度，换来对象的可操作感。[卡片与行的对照实验](visual-examples.md#一处常见错误如何具体改)给出同内容改法；结论取决于对象是否需要被当成"一件东西"拿起。

**迁移**：资料、订单、资产的选择检查任务都能借这套轴线与密疏；实时监控需要稳定的时间轴，移动社区需要更大的对象间停顿，不能照搬 66px 行。

**失效边界**：靠删字段、缩字号或巨大留白换来的"干净"不是密度设计。最长名称冲散列位时，先重排列宽与换行策略，不要截掉任务需要的信息。

## 4. 色彩与明暗

**值得追求的画面**：色彩既有情绪也有分工，整屏温度一致；一眼能看出哪块是材料、哪个是动作、哪个是状态。

**实际画面**：[索引桌面](../assets/reference-evidence/workbench-desktop.png)用 `#f7f8fa` 画布、`#fff` 纸面、`#20242d` 导航、`#252b36` 正文、`#626c7b` 次要、`#e3e6eb` 线，蓝色 `#2458d3` 只出现在操作与选择：选中行的 3px 内嵌边与 `#edf3ff` 底、已收藏图标、详情的主按钮。[字间工作面](../assets/reference-evidence/studio-instrument-desktop.png)则是近黑页底、稍亮面板、更亮选中行三级表面。

**关系描述**：索引的蓝不是"品牌点缀"，它始终回答"哪里可以操作、哪个是当前对象"。九条记录没有九种颜色，所以选中信号不会被稀释。明暗承担层级：画布比纸面暗一点，纸面比导航亮很多，线比两者都弱。字间的深色不是"专业"的证明，它靠三级近黑表面的明度差建立深度，文字角色随之重新校准。

**联动变量**：换品牌色 → 只换动作与选择角色，不自动换行高、圆角和图标重量；把浅色方案改深色 → 表面明度阶、文字对比、线的可见度全部重测，不是取反；引入语义色（成功/警告/危险）→ 先确认它和动作色不会在同一元素上打架，再决定面积。

**可试初值**：先定五个角色——画布、内容面、正文、次要、线——再定一个动作色和一个选择底。动作色覆盖面积宁小勿滥；语义色只在承载语义时出现，并保留文字说明，不让颜色单独编码信息。任何前景/背景组合都实测对比度，截图里的灰字不能当规范。

**另一个好方案**：[明快有序](visual-languages.md#明快有序)允许大片高饱和色承托真实材料，活力来自色彩面积与形状对照。它适合学习与活动类产品；同一套色放进长时间监控页会持续争夺注意。强色彩和安静都可以有品味，差别在颜色有没有职责。

**迁移**：可迁移的是"角色分工＋温度一致＋面积克制"，不是这六个 HEX。换题材先重定角色，再挑属于该题材的色相。

**失效边界**：每个对象随机一种色，或为了"高级"把所有颜色洗成灰，都是放弃了色彩的分工。选中、悬停、焦点、业务状态共用一个模糊色块时，先拆角色，再调颜色。

## 四种对照，别只看丑稿和美稿

- **缺陷修正**：同内容下明显的对齐/权重错误如何修，教基本工艺。
- **合格到讲究**：两边都完整可用，比字块、材料、整体节奏，教审美上限。[移动服务的 A/B 推演](lessons/mobile-service.md#一次可证伪的推演)是这一类。
- **好与好**：两种完整方向各自适合什么阶段，教选择。本文件每节的"另一个好方案"是这一类。
- **迁移与失配**：同一关系换任务后哪里必须改，教泛化。每节的"迁移/失效边界"是这一类。

做对照时不故意把旧稿做丑、不删内容、不减功能。切换局部变量就固定其它条件；比较完整方向就承认多变量一起变化，不把收益归给其中某一项。
