# 把记录做成可理解的产品对象

当用户说“不像产品”“只像统计表”“想对外展示”，或正在设计面向陌生访客的发现/目录/内容界面时阅读。它不要求所有界面改成营销页，也不把表格、密度或黑白配色当成低级。

## 先确认这次到底在服务谁

同一组数据可以服务不同阶段：陌生访客理解价值，回访者寻找变化，专业使用者批量比较。阶段不同，首页要回答的问题不同。保持成熟操作界面时不强塞宣传 Hero；转向对外展示时也不要只保留内部采集字段。

从当前用户反馈与项目事实判断，不凭空补出“只给自己用”“每天几分钟”“不回访”。若目标改变，在方向记录中标出旧约束的适用范围。短暂实验的墨白、禁色、固定布局不能自动继承为永久品牌规范。

## 从用户的问题反推呈现

挑一个真实对象，先完成它的信息与操作，再推广到集合。以项目发现页为例：

| 用户要理解的事 | 对象应呈现什么 | 数据的角色 |
|---|---|---|
| 它是什么，帮谁解决什么 | 可理解的名称、完整用途、必要的原文 | 原始简介用于提炼，不能只剩截断字段 |
| 为什么值得我打开 | 有出处的特点或明确标示的编辑观察 | 热度只是线索，不替用户虚构需求 |
| 我能相信到什么程度 | 原始来源、时间、证据与未知项 | 支付入口不升格为成交，关注不升格为收入 |
| 下一步能做什么 | 查看详情、比较、打开来源或保留对象 | 动作响应和返回路径构成最小体验 |

提炼不是删掉难排的内容。概要用于进入，原始描述与证据放在可达的详情层。对比任务仍可使用表格；页面应让用户理解列的意义，并能从某一行继续完成任务。

不要直接用数据字段生成页面区块顺序。先组织理解路径，再决定用列表、图形、卡片还是正文。覆盖率等系统说明应在需要判断可信度的位置可见，不默认占据首屏的最高权重。

## 视觉方向需要实际材料

为主角选择能帮助理解的材料：真实产品截图、内容样本、实物摄影、品牌资产、交互演示或准确的数据图形。说明材料承担的作用，再决定构图、比例与留白。纯文字产品也可以靠排印和内容建立辨识度，不必强行加图。

拿不到素材时，优先使用能证明的内容；示意图应说明是示意，不假冒实际界面。不能用通用图标、无关渐变或伪造的产品截图掩盖素材缺失。

看真实参考图，解释它的内容主角如何占据画面、主次如何相互支持、不同段落如何改变阅读节奏。参考中有哪些条件是自己的内容不具备的也要指出。只写参考品牌名、引用旧投票或抄 CSS 数字，不算完成这一步。

决定画面时同时看：文字和素材的比例、信息量与空间的关系、主内容与辅助信息的对比、边缘和空隙的精度。不要分别调好了标题、卡片和按钮就默认整体成立。

## 用一段真实体验检验

完成一个从进入页面到有意义结果的路径，例如“看到项目 → 理解用途 → 查看证据 → 收藏 → 找回收藏”。先做通这段，不用模拟的按钮和无响应的搜索框冒充产品体验。

检验原尺寸首屏和一个展开状态：

- 不看设计说明，画面是否已经表达产品价值和内容主角？
- 核心用途是否可读，还是被说明性文字、编号、排名和元数据挤掉？
- 滚动之后，信息密度和构图是否随任务变化，还是一直重复同一种容器？
- 对照匹配的成熟产品，素材、比例、排印、细节与操作反馈的具体差距是什么？
- 操作后是否产生有意义的结果，并能继续或返回？

答案必须指向可观察位置与行为。脚本负责检测缺陷；“用户会不会喜欢”需用户反馈。没有真实渲染或操作证据时，交付状态就是待验证原型，不能用方法论文档或安装测试充当设计验证。

## 此次案例的边界

仓库 `examples/project-radar/` 是对 r12 报表式页面的实验，使用同一数据快照完成一个公开浏览路径。它提供可运行产物与证据记录，不是全项目迁移，也不是所有界面的默认模板。不要复制其配色、曲线图或首页结构到不相干的产品。
