# 从数据记录到可理解的对象

只有产品对象、价值或下一步不清楚时读此页。不要把所有设计任务变成产品战略重写。

先确认阶段：初次了解、回访查找还是日常操作。同一内容可以有不同入口，但不能偷换产品要解决的问题；商业机会工具仍要支持商业判断，不能因旧报表难看就变成泛化的产品目录。

挑一个真实对象，回答四件事，再推广到集合：

| 用户的问题 | 需要的呈现 |
|---|---|
| 它是什么，适合谁？ | 可理解的名称、用途与必要原文，不只显示截断字段 |
| 为什么值得看？ | 具体特点或明确标示的编辑观察；热度不冒充需求 |
| 能相信到什么程度？ | 来源、时间、证据和未知项；支付入口不等于收入 |
| 看完能做什么？ | 阅读、比较、检查、保留或执行，以及可理解的结果 |

先确定理解顺序，再决定表格、列表、图形还是正文。概要用于进入，完整内容在可达详情；不能删掉难排信息，也不必将全部字段同时挤进首屏。系统统计、数据覆盖率等说明放在影响判断的位置，不自动抢最高权重。

材料必须有职责：截图用于识别或证明，准确图形用于解释，原创示意可以表达气氛。没有素材时重新组织画面；示意必须标清，真实图片也要看裁切与构图，不机械替换用户认可的图形。不能虚构客户、收入、价格、功能或来源。

最后走通“进入 → 理解一个对象 → 查看依据 → 下一步 → 返回/继续”。如果只有作者说明能解释价值，画面尚未完成。已有[项目雷达原型](../examples/project-radar/index.html)只是特定数据快照的实验，其历史截图不证明后续版本已改善，也不构成所有项目的模板。
