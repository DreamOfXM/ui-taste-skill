# 可选工具与旧流程兼容

仅在需要自动扫描、内容对照或旧工具兼容时阅读。核心设计流程不依赖这些工具；先核实当前路径、接口和环境，不把历史运行记录当本轮验证。

## 本机可选命令

反模式定位工具曾安装在：

```sh
~/.agents/skills/impeccable/scripts/impeccable detect --json <文件或目录或URL>
```

已知退出码为 0（未发现反模式）、2（发现反模式）、1（不可访问）。调用时核实当前版本约定；保存相关输出，区分未运行成功与真正检出。字体、色彩、卡片等风格命中只作为复查线索，不能自动否决设计；具体布局或交互缺陷需要修复并复验。

`impeccable` 的 `/craft`、`/critique` 等是 AI 要读取执行的指令，不是已证实的 CLI 子命令。文档型 skill 不需要自带脚本才有价值，按方法执行即可；不要编造不存在的工具接口。

内容对照工具曾安装在：

```sh
/usr/bin/python3 ~/.agents/skills/design-inspiration/scripts/check_style.py <候选.html> <基线.html>
```

用于帮助发现意外删改。其字面差异不等于内容损失：合理改写、合并或渐进披露需检查语义与功能可达性，用户授权的内容调整不受旧文本锁定。命令没跑成则不得报通过。

## 历史美感工具的边界

`design-inspiration/BEAUTY_RUBRIC.md` 与 `beauty_gate.py` 来自特定参考样本和历史项目。其风格阈值不构成本 skill 的交付条件，也不再承担通用审美裁决。需要研究出版风格时可读其历史观察，不默认加载。

若专门使用旧 `beauty_gate.py` 做诊断：先读当前源码确认输入语义。旧实现将所有 HTTP(S) 地址视作参考站，只打印读数而不判 FAIL；`localhost` 候选也会走这条分支，因此 URL 调用成功不能当成候选通过。字体采样和计算样式也无法证明整体关系好看。

旧 `check_round.py` 检查固定字段、文件时间和盲评票数量，与新版按任务选择方向数量的流程不兼容；不默认运行，也不为满足旧脚本补造方向或评审票。原协议在 Git 历史中保留。

## 参考和运行证据

优先使用当前可用的浏览器或平台工具看图和交互。网页用本地 HTTP 服务检查资源加载和控制台，不能把未运行的文件当成活体原型。原生 App 用其实际运行环境。

现有参考库可在 `~/.agents/skills/design-inspiration/vault/` 查找，使用前确认具体图像内容。首屏只能支持首屏判断，不能推断整页、内页或操作状态。不要自动批量抓库；按当前设计问题补足必要参考。

新产物放在项目可写目录，沿用项目已有证据组织方式。记录当前画面对应的入口、状态和版本，以便复查。不得为满足旧流程而把产物强制写入无权限的固定桌面目录。
