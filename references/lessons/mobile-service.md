# 拆解：中文移动服务经验列表（浏览并判断相关性）

原创教学样例，[可运行实现](../../examples/mobile-service/index.html)，390×844 中文移动 Web，内容虚构、领域为社区/公共办事（非医疗）。任务是"先判断这条经验是否与自己相关、来源可信到什么程度，再进入正文"。先看[列表 B](../../examples/mobile-service/evidence/list-b.png)与[对照 A](../../examples/mobile-service/evidence/list-a.png)，再读本节。

## 值得追求的画面

标题和摘要形成清楚、舒展的字块；不同经验之间有稳定停顿；作者、经历对象和核验说明靠近所属内容、直接可读。全屏的温和感来自中性底色、稳定字重和少量有职责的强调色，而不是把每块内容涂成糖果色。顶部只承担定位、搜索与分类，不加大型口号占首屏。

## 390 CSS px 的试排起点

| 元素 | 初值 | 目的与调整方法 |
|---|---|---|
| 页面左右留白 | 18px | 给字块明确边缘；长标题多时先查行宽，不先缩字 |
| 经验标题 | 19px / 1.45 / 600 | 支撑 1–3 行语义断行；完整标题在详情可读 |
| 摘要 | 16px / 1.65 | 形成可连续阅读的纹理 |
| 身份/核验文字 | 14px / 1.55 | 保证能辨，不把关键事实降为装饰微字 |
| 标题→摘要 | 7px | 内容内停顿 |
| 内容→身份组 | 13px | 依据前停顿 |
| 两条经验之间 | 24px＋1px 分隔线 | 对象间停顿，让视线重启 |
| 收藏点击区 | 44×44 | 图标可小，点击区不跟着缩 |

三种停顿（7 / 13 / 24）是这套节奏的核心，不是"留白越多越好"。见[密度与节奏](../taste-foundations.md#3-密度与节奏)。

## 一次可证伪的推演

两版保留完全相同的标题、摘要、作者、日期、来源句与操作，只改一组关系。实现里用顶栏"A 合格稿 / B 讲究候选"切换，可直接复跑。

- **A（合格稿）**：来源徽章放在标题右侧，标题被迫在更窄列换行；卡片内所有纵向间隔统一 12px；来源整句隐藏，只留角色徽章。
- **B（讲究候选）**：来源整句移到标题与摘要之后的身份信息组，仍直接可见；标题获得完整文本宽度；停顿分成内容内 7 / 依据前 13 / 对象间 24 三种角色。

**实际截图观察**（执行者看图，非用户偏好）：断行工艺（`line-break: strict`＋标题 `text-wrap: balance`、正文 `pretty`）作为共享下限同时加在 A/B 上，两版都不再出现孤字尾行或拆词——它是被固定的条件，不是对照变量。对照变量是布局关系：A 的徽章挤占标题列，第一条标题被迫两行、来源整句隐藏、间隔统一 12px；B 标题拿满行宽，第一条完整一行，来源整句在 14px 下常驻可读，停顿分成 7/13/24 三种角色。[大字转场](../../examples/mobile-service/evidence/large-text.png)下 chrome 一并放大（品牌 24、搜索 19、分类 15），内容重排为 22/19/16，无截断、收藏仍可达，`scrollWidth` 保持 390。[详情](../../examples/mobile-service/evidence/detail.png)左缘统一 18px、同类经验可点、收藏条吸底。代价：B 的来源句常驻使每条略高、首屏完整条数略少；A 省出高度但牺牲了来源可读性与标题字块。

若 B 的长标题仍出现"一行很满、一行很短"的尾巴，先试内容宽度与字重的相邻值（17.5–18.5px、字体实际支持的 500/600），不插跨设备失效的硬换行。实际截图之前不预设 B 必胜；本例的胜负只针对这组内容与视口。

## 独立盲评与修复台账

把截图与任务交给独立读图执行者（不看作者理由）后，得到的不是赞美而是缺陷清单。逐条记录，避免"自评优秀"：

| 盲评指出 | 处理 | 复验 |
|---|---|---|
| 标题孤字尾行/拆词 | 共享下限 `line-break: strict`＋`text-wrap: balance/pretty` | 重截图列表/大字，尾行成词 |
| 大字只放内容、chrome 不变 | 品牌/搜索/分类/计数/返回/收藏一并放大 | 计算样式 24/19/15px，无溢出 |
| 详情左缘不齐、收藏埋没 | 详情主区去外 padding、返回去负 margin；收藏改吸底条 | 三处左缘均 18px，吸底 position:sticky |
| 列表缺少产品色、调试控件抢色 | 分类选中用产品绿，A/B 调试段改中性 | 重截图确认 |
| 详情读完即死路 | 增加同类经验入口 | 点击跳转断言通过 |

修复后重跑流程与重截图，[运行记录](../../examples/mobile-service/evidence/report.json)已重绑定源码哈希。**但盲评同时裁定本例"合格但平庸"**：关系落地、状态齐全，却没有足够强的主张。因此它停在实现演示级（见[分级](../visual-examples.md#参考质量分级与准入)），只教关系与状态，不作审美上限；用户偏好仍未验证。

## 配色如何配套

画布 `#faf9f7`、内容面 `#fff`、正文 `#26221c`、次要 `#6b6459`、线 `#e7e2d9` 保持同一暖温度；一个动作色 `#1f6f5c` 贯穿链接、选中与主操作；提示用 `#8a5a17` 配文字"提示："，不让颜色单独编码语义。这些是候选关系值，每一对前景/背景都须实测对比度后再用于真实产品。

## 什么时候另一个好方案更合适

若任务是按地点、时间、类型高频筛选比较，紧凑稳定的列表比叙事卡片更直接：保留字号与核验信息，把摘要折叠为有明确入口的详情，为来源预留稳定列位（此时 A 的同排来源反而有效），不机械采用 B。卡片或分隔行都可能成立，取决于对象是否需要被当成独立单位拿起。

## 迁移与失效边界

从相邻题材迁移时保留"相关性 → 来源/条件 → 详情"的阅读次序与三种停顿，替换材料本身；不复制医学核验标签，也不沿用任何品牌颜色。元信息比正文多、标签围满标题时先重组信息角色；必须靠照片辨识对象时重排图文比例，不硬套纯文字列表；大字模式让内容重排，不为固定卡高截断重要文本。

## 运行与证据

本地起服务后打开 `index.html`；`#variant=a`、`#open=<id>`、`#large=1`、`#q=<词>` 可直接定位教学状态。截图与源码哈希、视口、流程断言由[运行记录](../../examples/mobile-service/evidence/report.json)绑定：筛选→选中→详情→返回、同类经验跳转、收藏持久化与吸底、详情左缘对齐、A/B 与大字（含 chrome）切换、无横向溢出、无控制台错误均已实际运行。报告通过只代表这些功能与布局检查；视觉观察是执行者判断，用户偏好尚未验证；本例是移动 Web，不是原生 App 验收。
