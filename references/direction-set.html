1# 方向清单与关键屏（G0 / S4 共用）
2 
3输出的文件是 `design/00-direction.md` 的方向清单部分，产物是 `design/v1.html … design/v6.html`。
4 
5这份文件管三件事：**开画前把 5–6 个方向钉住**、**关键屏画到哪为止**、**怎么证明它们真的不一样**。
6 
7## 为什么是 5–6 版
8 
9一版只能证明做得出来，不能让用户做选择。多于 6 版会开始重复（第 7 版几乎总是第 2 版的换色），所以 6 是上限，5 是下限。
10 
11**约束的作用是把每一版修到过，不是把版本筛掉。** 十一问里每条「不过」都自带修法：落点少 → 把强调色加到更多顶层区块；没有文字着色 → 给承担论断的数字或标签着色；跨度小 → 拉开 display 与正文；材质单一 → 补投影、渐变或真实图像。回读门同理：规矩说不出 → 回 S2/S3 成组落地配方；破例理由读不出 → 回 G0 重立破例或回 S3 换承载元素；全守规矩 → 回 G0 重立主张。所以看到「不过」的正确动作是改这一版，改到过为止；不是把它淘汰，也不是只交一版绿的。
12 
13## 方向清单格式
14 
155–6 套别用横排宽表（九列在终端里读不动，读不动就等于没写）。一套一块，九项齐全，空任何一项该套作废：
16 
17```markdown
18### 丁 · 借「仪表」这个已存在的类型，它自带的规矩是「读数等宽、按阈值着色、占固定栅格」
19- 对象（借的类型 → 它的规矩）：仪表 / 读数等宽、按阈值着色、占固定栅格
20- **破例清单**（可以多处，每处三字段；理由必须指向画面上的具体内容或文案）：
21  1. 破在哪：右缘常驻窄柱｜破了哪条：读数本该占中心栅格｜为什么该破：文案写的是「现在是什么状态」，这是用户每天唯一要看的信息，所以它常驻右缘、不随页面滚
22  2. 破在哪：__｜破了哪条：__｜为什么该破：__
23- 主关系落在哪几轴：对象表达 + 构图
24- 底面：`#0C1220`（S 45%，取自产品界面采样 + 同族说明）｜卡面 / 线 / 光：__
25- 按钮：圆角 __ / 高 __ / 字重 __ / 实心或描边
26- 字体：__，H1 __ / 行高 __ / 字距 __
27- 密度与首屏：__ 字 + __ 图，元素 __ 个（上限：桌面 7 / 移动 5）
28- 换来 / 放弃 / 证据级别：__ / __ / R2·R1·R0
29- 与 `01-content.md` 的 P0 是否兼容：__（不兼容要写明为什么仍保留这一套）
30```
31 
32- **甲案必须等于 S1 取出的品类默认家族**，不许偷偷换掉；其余各案是同品类合法变体、跨品类借用、换对象表达、整包换材料或极端档。
33- **「借的类型」要写得出一个真实存在的对象**：某个已存在的品类、某种印刷物、某类仪表、某个已上线产品。写「现代感」「科技感」「极简」不算，那是偏好陈述，不是类型。**还要写出它自带的规矩**——写不出规矩，后面就没有东西可破。
34- **破例可以多处，不设数量上限**，但每处必须三字段齐全：破在哪（具体元素 / 位置）/ 破了哪条规矩 / 为什么该破。**理由只准指向页面上的具体内容或文案**：「这个数字是全页唯一的结论」合格，「为了有层次」不合格。写不出理由的破例删掉，不许留着凑数。合格与不合格对照表见 `readback.md`。
35- **一处破例都没有的方向同样作废**：完全按类型默认走，就是没有自己的主张。S5 回读门读到「全守规矩」会判不过，退回 G0 重立主张——不是回 S4 加装饰。
36- 三列以下的对照表可以横排（给用户看前三个主要候选时用），见 `direction-gate.md` 的模板。
37 
38## 判同：三轴里有两轴不同才算两版
39 
40| 轴 | 问的是什么 | 举例 |
41|---|---|---|
42| 构图 | 什么东西占住哪块视野 | 产品界面占右半 / 时间轴横贯整页 / 一列巨型数字当主柱 |
43| 材料 | 底面、线、面、光之间的关系 | 1px 线分块 / 面代替线 / 真实截图当底 / 单一色块承重 |
44| 对象表达 | 把产品说成什么东西 | 工具、仪表、清单、杂志、账本、地图 |
45 
46只有配色不同、只有底面明暗不同、只有字号不同的——判为同一版。**换色不算方向**，这是本 skill 从 0.2.x 起反复栽的那个坑。
47 
48## 灰度并排测试（S4 必做，不靠自觉）
49 
501. 每版首屏各截一张同视口截图。
512. 全部转灰度、缩略并排成一张图。
523. **看**：去掉颜色之后还能不能一眼分出哪张是哪张。
534. 分不出 → 说明差异只活在颜色里 → 退回 G0 重钉主关系，不许在 S4 就地换配色交差。
54 
55```sh
56# 截图 + 转灰度 + 并排（本机 headless Chrome + python3/Pillow）
57"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
58  --headless=new --disable-gpu --no-sandbox --hide-scrollbars \
59  --force-device-scale-factor=1 --window-size=1440,900 \
60  --virtual-time-budget=9000 --screenshot=v1.png file:///abs/path/v1.html
61```

63## 关键屏的范围
64 
65每版只画**两屏**：
66 
671. **首屏**（1440×900，不滚动）：身份、P0、一条可复制的安装或获取动作。
682. **本产品最难的那一屏**：信息最密的那屏、或最需要材料撑起来的那屏。定价页选三档并排 + 最长项；工具页选状态最多那屏；内容站选图文最挤的一屏。
69 
70其余部分用一句话说明会怎么排，不画。**先证明 5–6 个主关系彼此成立且互不相同，再花整页预算**——整页画完才发现三版是同版，是最贵的一种返工。
71 
72用户挑定一版后，那一版才展开成整页（导航 / 证据 / 获取 / FAQ / 页脚齐备，不止一个 hero）。
73 
74## 对照页 `design/compare.html`
75 
76交付给用户的东西是这一页，不是一堆文件路径。要求：
77 
78- 同视口截图，一次看全（首屏 5–6 张并排；最难屏 5–6 张并排）。分屏来回看不算并排。
79- 每张下面三行：**这版把产品说成了什么** / **换来** / **放弃**。不写分数、不写排名、不写"推荐"——排序是用户的事。
80- 每行的图片指向对应 HTML（点开看真实页面，截图只是索引）。
81- 灰度并排测试用的那张图也放进来，作为"这几版确实不是一版换色"的证据。
82 
83## 两条必须机械核对的出口项
84 
85这两条都是实跑里栽过的，写进规则不算，要跑：
86 
87```sh
88# 图片是否真的加载（相对路径错、文件缺失都会在这里暴露；返回非 0 即有图没加载）
89python3 scripts/probe-assets.py design/v1.html
90 
91# 命令块 / 长 URL 是否溢出容器（溢出=读者复制到的是被裁断的命令）
92python3 scripts/probe-overflow.py design/v1.html
93```
94 
95两个脚本只要 python3 标准库加本机 Chrome，输出逐条列出元素与像素值。**图显示成 alt 文本还自称"已自查通过"，是流程事故，不是小疏漏。**

97## 预算
98 
99- 5–6 版关键屏 ≈ 1.5–2 倍单版整页成本。
100- 每版都要跑一次 `probe-energy.py`（地板）+ 一次上面两个脚本；这是每版各一遍，不是抽一版代表全部。
101- **每版还要跑一次回读门**（`readback.md`）：一个独立实例盲看三问 + 落点缺陷，原话照录。这是每版各一遍，不是抽一版代表全部。
102- 上下文不够时**减版不减门**：宁可交 5 版全过地板且都回读过，不交 6 版里有 2 版没跑过 probe 或没回读。
