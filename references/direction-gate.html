1# G0 方向确认门（direction gate）
2 
3S1 之后、S2 之前必过。**这是整个 skill 里唯一一个「用户必须有机会否决」的节点。**
4 
5输出：`design/00-direction.md`。它和 `00-brief.md` 并列，是 S2 立论的合法输入之一。

8 
9## 为什么要有这个门
10 
11`SOURCE.md` 借来的观念里有一条：「**不自己替用户选审美**（this is how you get slop）」。0.2.4 之前没有任何一处实现兑现它：
12 
13- `SKILL.md:28`（0.2.4）写「只有会改变任务方向或不可逆的问题才问用户」——**规则本身没错，错在把视觉方向归类成「不改变任务方向的细节」**。底色决定明暗系统、素材能不能用、品牌身份是否延续、对比度怎么算，它恰恰是会改变任务方向的那一类。
14- `brief-analysis.md:7`（0.2.4）写「不要在这一步谈视觉……颜色、字体、布局的想法都记到草稿区，不进文件」，brief 六字段里没有「视觉方向偏好」——所以方向**永远算不上「缺关键项」**，永远不触发提问。
15- 货架（register / pattern / type-recipe）的选择全部在模型内部完成；`SKILL.md:132`（0.2.4）的交付顺序是「两稿 HTML → 账本 → 自评 → 一段话」，用户第一次看到方向是在成品之后。
16- 多稿规则把「A 蓝 B 绿」判为表面轴不合格，这条判断对，但副作用是**颜色从此没有任何出口**：DiskWise 的两稿共用一份 `skin.css`，底色写在账本「共用」区。
17 
18结果：模型选了一个方向、写下代价、自己替用户接受，然后交付。用户看到的是「一个定死的成品」。

22## 什么时候必走 G0
23 
24按 `SKILL.md` 的分流表：
25 
26| 路径 | G0 | 理由 |
27|---|---|---|
28| 开放新设计、整体重做、「不好看但说不清」 | **必走** | 方向未定，没有人给过授权 |
29| 对象已有上线页面，incumbent 评级成立 → 校准 | **可跳过**，但 `00-direction.md` 仍要落盘 | 方向由 incumbent 实测结果给定；写明「照抄其明暗系统 + 证据文件路径」 |
30| 用户给了原稿或已认可方向 | **可跳过** | 原稿即规格，方向已由用户给出 |
31| 局部精修 | **跳过** | 不重跑五阶段；只重填受影响账本行 |
32 
33**「可跳过」指跳过提问动作，不跳过记录。** 三种跳过都要写 `00-direction.md`，注明方向来源（用户原话 / incumbent R2 实测 / 用户明确授权自主），否则 S5 第八问无法通过。

37## 组合卡：交给用户看的是这个，不是形容词
38 
39### 先写一行品类判定，再摆卡
40 
410.2.6 起，G0 的第一句话必须是品类，不是风格：
42 
43> 这是 **C1 开发工具**（依据：brief 说「给 Mac 用户清磁盘」，产品是 CLI + 图形界面，信任物是可核对的空间数字）。该品类默认家族：底面 `#08090A`、按钮圆角 8 / 高 36 / 字重 500、H1 64 / 字距 -0.02em、版心 1240、密度中高、首屏图文比 = 一张真实界面 + ≤300 字。
44 
45没有这一行，后面五到六套卡都是空中楼阁——用户没法判断"这套行不行"，因为他不知道基准在哪。
46 
47### 5–6 套，甲案必须是品类默认家族
48 
49| 卡 | 是什么 | 作用 |
50|---|---|---|
51| **甲 · 品类默认家族** | S1 从 `category-prototypes.md` 取的十二项，一个字不改 | 让用户看到"这个品类正常长什么样"，是最可辩护的基准 |
52| **乙 · 同品类次型** | 同类目的主型↔次型互换（C1a ↔ C1b、C2a ↔ C2b…） | 同一个品类内部的分化，风险最低 |
53| **丙 · 有意借用** | 借另一个品类的某一维（例：C1 的底面 + C4 的 0 圆角 + C9 的 pill 按钮） | 差异化选项，必须写明借了哪一维、付什么代价 |
54| **丁 · 换对象表达** | 同一品类、同一底面，把产品说成另一种东西（仪表 / 清单 / 杂志 / 说明书 / 时间轴） | 构图轴与阅读方式的差异，跟颜色无关 |
55| **戊 · 换材料系统** | 从 `surface-recipes.md` 六套里另取**一整包七项**（不是只换底色） | 明暗与质感的差异；只换 `#paper` 的算同一套 |
56| **己 · 极端一档**（可选） | 把某一维推到该品类的合法边界（最高密度 / 最大字级 / 完全无卡片） | 探边界用，帮用户看清中间档在哪 |
57 
58**套数与判同**：5–6 套；少于 5 套不算交付，多于 6 套是噪声。任意两套之间，**构图 / 材料 / 对象表达三轴至少有两轴不同**——只有配色、只有底面明暗、只有字号的判为同一套，必须重列。判同方法与灰度并排测试见 `direction-set.md`。

92每套都要写成这样一块：**主张句在前**（借了什么类型 + 它自带的规矩是什么），**破例清单紧随其后**（可以多处，每处写清破在哪 / 破了哪条 / 为什么该破），再是四项具体值 + 三轴定位 + 换来 / 放弃 / 证据级别。主张句写不出来、只能写成"深底版 / 浅底版 / 蓝底版"的，判为同一套，不许凑数。**破例理由写"为了层次 / 高级 / 呼吸感"的，该处作废**——理由必须指向页面上的具体内容或文案，对照表见 `readback.md`。一处破例都没有的方向同样作废：完全按类型默认走，就是没有自己的主张。

94### 一次真实可用的例子（DiskWise，0.2.6 重放，当时只列 3 套）
95

99|---|---|---|---|

107 
108这张卡的价值不是让用户再选一次颜色，而是**把「品类判错」这个错误暴露在 G0 阶段**，而不是等成品出来被说"很空洞"。

110### 提问的措辞
111 
112一次问完，不要挤牙膏：
113 
114> 这是 **C1 开发工具**。这个品类的默认长相是深底 + 紧凑字距 + 真实界面当主角（甲）。我一共列了 6 套：乙是同品类浅色版，丙借了服饰类的 0 圆角，丁把产品说成仪表，戊整包换了材料系统，己是密度极端档。
115> 这几套的差别在**谁占住首屏、用什么材料、把产品说成什么东西**，不是六个配色。去掉颜色并排看仍然分得清，我才敢摆给你。
116> 你可以现在挑一套、只反对其中一维，也可以说「都画出来我再挑」——默认我按 6 套各画一版关键屏给你并排看，那样比看菜单好判断。
117 
118**不许给自己偏好拉票**（`SOURCE.md` 借的观念之一）。可以写「我倾向乙，因为___」，但必须同时写清乙的代价，且不得把其余各套写成陪跑的劣质选项。**每一套都要是能成立的方案**——判「不过」也一样要改到过，不是删掉它的理由。

147## 用户没回 / 说「你定」怎么办
148 
1491. **「你定」是一次有效授权**，照录原话，写进 `00-direction.md`。**默认动作是把 5–6 套各画一版关键屏**，而不是模型替用户挑一套——"你定"授权的是方向归属，不是缩减候选数；交付时把假设单列给用户。不要因为没得到明确选项就停住不动。
1502. **完全没回但任务要继续**：视为已获自主授权是**不诚实的**。此时只能把状态写成「未确认，模型暂按 5–6 套全部画出」，并且：
151   - 交付物标注「方向未经确认」；
152   - `03-critique.md` 的第八问写「不过」；
153   - 已知短板里明确列出「用户未确认方向」这条。
154   不许把「没回」粉饰成「用户认可」。
1553. **用户中途改方向**：回到 S2 重立论、S3 重填受影响账本行、S4 重写受影响的区块。这属于「改账本再重拍」，不是「事后美化」。

159## 与多版规则的关系（重要，别改错地方）
160 
161G0 列出的每一套方向，S4 都要真的画成一版关键屏。方向不再是「用户选完就锁死、然后各版只在结构上取反」的地基——**方向本身进对照**，这是这次改的交付形态。
162 
163`SKILL.md` 多版规则（三轴判同）里那条真正的洞见不变：⛔ **只有换色的，不算一套新方向**，也不许让「哪版更好」退化成「哪个颜色顺眼」。所以：
164 
165- 合法的换材料 = 整包换七项（底面 / 卡面 / 墨色 / 次文字 / 线 / 纹理 / 明暗关系），且能说清这套餐具适合哪种信任物。
166- 合法的换构图 = 说得清什么东西占住哪块视野变了。
167- 合法的换对象表达 = 把产品说成另一种东西（仪表 / 清单 / 杂志 / 说明书 / 时间轴）。
168- 不合法：甲 `#08090A`、乙 `#0B1220`、丙 `#101820`；或只把 H1 从 56 换到 72。
169- 不合法：一版里同时用 1px 通高线和 24px 大圆角柔投影还不写理由——**一版内部混搭是 AI 味，跨版换配方才是差异**。
170 
171旧文在这里写的是「不要把『至少一稿换底色』写进多稿规则」。这句在 5–6 版形态下改写成：**不要把「换底色」当成「换材料」**。底色是材料系统的结果，不是杠杆——先决定这一版把产品说成什么对象、谁占住首屏，底色跟着整包配方一起换。
172 
173## 验收（S5 第八问）
174 
175`critique.md` 第八问检查四件事：
176 
1771. `00-direction.md` 存在，且候选 **5–6 套**、每套四项具体值齐备、每套有换来与放弃、每套有主关系主张句（借了什么类型 + 它的规矩）、**每套有破例清单且每处三字段齐全、理由指向画面内容或文案**。
1782. **判同成立**：任意两套三轴里有两轴不同，且已用去色并排测试确认（贴命令，不写自我声明）。
1793. 「用户选择」栏是**用户原话或明确授权**（含「都画出来我再挑」这种授权全画），不是模型代填的推断。
1804. 每一版的底面 / 卡面 / 墨色 / 线与它那套 `S_` 配方**成组一致**，不是只换了 `#paper`。
181 
182任一不满足 → 不过，退回 G0 补齐或重列那一套；**退回是补方向清单，不是删掉某一版**。
183 
184**第八问只查破例写没写，不查破例活没活到成稿里。** 后者由 S5 第二层回读门查（`readback.md`）：独立实例盲看画面，读不出规矩或读不出破例理由就判不过。**G0 写了、S5 没人回读，是 0.3.1 六版塌回同一个大数字的直接原因**——这两道检查必须都在。
