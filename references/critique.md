# S5 验收 · 第一层：地板（十一问）

输出的文件是 `design/03-critique.md`。

**这一份只管地板，不管好坏。** 十一问测的全是元素属性（字号几档、饱和度多少、落点几处、材质几类），全过只说明"这页没塌"。整体感（规矩站不站得住、破例有没有道理）是关系属性，量不出来，由**第二层回读门**取证，规程见 `readback.md`。优劣由**第三层同视口并排二选一**决定，结论归用户。三层不互相代替。

不是打分。每一问只有"过 / 不过"，不过的写清**回哪一步改**。

**这一问套几遍，取决于交付有几版。** 开放设计默认 5–6 版关键屏，十一问与三支探针**逐版各跑一遍**，`03-critique.md` 按版分节；只跑一版代表全部是不过。跑完不许把"不过"当淘汰理由：**门负责拦，不负责选**——某一版不过，按判据回对应阶段把那一版改到过；版与版之间谁更好，交给并排看图与独立评审，不交给探针数字。为什么这么定：实跑里出现过强调落点 16 处（判据要 ≥3）全部来自 1px 描边的一版，数字过门却比"不过"的那版更平；数字能拦下"平"，选不出"好"。

十一问的设计原则：前七问都能不看设计稿、只用一句话或一个操作回答；第八至第十一问要回读 `00-direction.md`、账本与 `01-content.md`。答不上来的，就是不过。

**0.2.5 从七问扩成九问**：第八问查「方向是不是用户定的」（补方向确认门），第九问查「空白有没有任务」（补 `05-whitespace-audit.md` 的密度缺口）。前七问全是否定式下限检查，能给出「通过」却仍留下满屏空洞和一个模型单方面定死的底色——这两问补的是**流程合法性与关系属性**，不是再加两条工艺。

**0.3.0 从九问扩成十问**：第十问查「首屏有没有主次」。0.2.6 三稿过了前九问中的四条，用户评价仍是「顶多不丑，多惊艳没有」——十问里原本没有任何一问在问这件事。第二问「最高饱和的是不是最重要的东西」看似相关，但它假设"最重要的东西"已经存在；位次没排，这一问无解。

**十问扩成十一问（同一次实测后补）**：第十问补的是"大小"，仍然没补"值不值得看"。实测证据：同一份冻结输入，不加载本技能的两跑里，基线一的首屏有 6 处强调级文字着色（标题着色、`LOGS`/`METRICS`/`TRACES`/`OTLP` 表头标签、面包屑），最大字号 42.7px；基线二只有 2 处（副标题第二行、开关上的「省 17%」），最大 46px。而加载本技能、认真跑完十问的稿 A，强调只剩一个深青按钮加一条 2px 竖线，首屏最大字号 38px——**用户的评价是"基线那一组比 skill 这一组好看"**。根因不在执行，在验收函数：第 1/4/5 问全是破坏式测试（去阴影、数档数、换灰），它们的共同最优解就是"手段最少、材质最平、颜色最省"。只跑否定式下限，产物必然向下限收敛，因为"不可批评"比"好看"容易达成。第十一问把后者变成有数字的硬指标。**后续修正：这道门是地板，不是美感判据**——它拦得住"平"，拦不出"好"；整体感另由回读门取证（`readback.md`）。

**改完之后重跑，同一份冻结输入**：按新规则生成的稿在匿名三稿并排里排第一（两位独立评审、两次不同打乱顺序，排名一致：新规则稿 > 基线一 > 基线二）。这不能证明技能从此稳定，只能证明这一处验收函数补上了；数字仍要在每次交付时现测。两位评审也独立指出同一处弱点：新规则稿里两枚虚线「未逐项列出」胶囊读起来像没做完的占位——**补能量不等于免细节**，第十一问过完，第九问和占位符检查照旧要过。

## 第零步之后：与天花板并排比（有参考 / 校准必做）

第一至第七问是**否定式**的（找缺陷），全过≠好。要逼近"好"，必须有一个**肯定式**的对照物：天花板参考或 incumbent。

**操作**：把成品与参考在**同视口**渲染截图，并排放在一起看（不是先后看、不是只看成品）。逐条列出差异，并归因到**关系**：顶部空带、字级/字重、留白节奏、材料取景、层级落点。

**判据**：每条差异要么修到持平/更好，要么明写"本版接受，原因是___"。归因写"规则没写这条"不算归因——要写到产生差异的那个系统（例如 nav 是 fixed 还是正常流，决定了 hero padding 是否已含 nav 高度）。

**校准特别注意**：继承的是**产生取值的系统**，不是源码字面值。抄 `pt-28` 而自己的 nav 在正常流，会把 nav 高度再叠一次（顶部空带翻倍）。对齐靠**测量渲染结果**（内容距视口顶的总距离），不靠抄 padding。

无参考的开放设计跳过此步，但下面的回读门仍必做。

## 第一问：剥掉装饰还剩几层

**操作**：在浏览器里给页面注入 `* { box-shadow: none !important; border-radius: 0 !important; background-image: none !important; }`，然后看层级是否还成立。

**判据**：去掉装饰后，视线仍能分出 ≥3 个层级（标题层 / 内容层 / 辅助层）。

**不过意味着**：结构靠阴影、圆角、渐变撑着，而不是靠字号、字重、留白、对齐。回 S3 改「层级」相关行。

**过之后不许把材质删光**：这一问测的是"结构能否独立承担层级"，不是"材质有没有罪"。通过之后，阴影、圆角、渐变、色块仍应留在页面上——只要每一类都能指到一个职责。把材质全数删掉换来的"过"，会在第十一问被判不过。

**为什么问这个**：AI 生成界面最典型的形态是"每个块都是白卡片 + 阴影"，层级全靠阴影深浅。这种页面一旦打印、截图压缩、或在低端屏上就糊成一片。

## 第二问：最高饱和的东西是不是最重要的东西

**操作**：截图后在图像编辑里降低饱和度看灰度值，或直接找页面上饱和度最高的那个色块。

**判据**：最高饱和/最高对比的物体 = brief 字段二的"唯一任务"所指的东西。

**不过意味着**：注意力被次要元素抢走。常见违规：推荐档的彩色背景比价格还抢眼；一个装饰性的渐变球比主按钮显眼。回 S3 改「强调色」行。

## 第三问：截 200×200 还认得出吗

**操作**：任选页面三个位置，各截 200×200 无损区域。

**判据**：三张截图都能看出"这是哪个产品、这是页面里的哪一类内容"。

**不过意味着**：页面没有可识别的视觉签名，去掉 logo 就与任何同类产品无异。回 S2 重写承诺（缺的是"可识别的特征"，不是细节）。

**这个测试对营销页尤其有效**：社交传播时，别人看到的就是一张 200×200 的缩略图。

## 第四问：每个数值都在刻度上吗

**操作**：在 DevTools 里把页面上所有 `padding`、`margin`、`gap`、`font-size`、`border-radius` 的值导出来去重。

**判据**：
- 间距值全部落在 `tokens/scale.md` 的刻度表上（4/8/12/16/24/32/48/64/96）
- 圆角 ≤2 档
- 字号 ≤6 档
- **下限同查**：首屏必须出现 `display` 一档，且首屏最大字号 ÷ 正文最小字号 ≥2.6；区块级间距（48/64/96）至少用到两个不同值

**不过意味着**：存在"随手值"（13px、5px、18px 这种）。随手值是"没有体系"的物证。回 S3 按刻度重填。

**刻度与品类打架时，改刻度**：`tokens/scale.md` 明确写了品类 register 的实测值优先——C1 要 H1 56–64 而 display 只有 48 时，正确动作是把 56/60/64 补进 display 并在账本记下来路，**不是把品类的字号压回 48**。这一问按补完之后的刻度判。把品类压进旧刻度换来的"全在刻度上"，是规则冲突导致的降级，第十一问会把它抓出来。

**上限不是这一问的目标**：`{38,24,17,15,12}` 五档全在刻度上，跨度却只有 3.2 且没有一档撑得起门面——档数少不等于体系好，把字号压到只剩三档同样能"过"这一问。数数之外还要看跨度，跨度由第十一问管。

**流式字号（`clamp()`）怎么算**：实测里排第二的无技能基线首屏有 15 个去重字号，`42.738`、`25.978` 这种值明显来自 `clamp()` 视口插值，不是随手敲的。判法分两支：
- 用**固定档位**写的页面：渲染值必须直接落在刻度上，出现 13.5px 这种就是随手值。
- 用**流式函数**写的页面：查 `clamp()` 的**两个端点**在不在刻度上、`vw` 系数是否成组，渲染出的中间值不作为违规。
两支都要能说出「这套字号是怎么生成的」。这一问查的是**体系存不存在**，不是字号少就好——上面那份基线 15 档、按旧写法直接判不过，可它在匿名并排里排第二；把它压到 6 档不会更好看，压到 3 档反而会被第十一问的跨度判据抓住。

**这一问是最客观的一问**，不需要审美判断，只需要数数。也是最能反映"是否真的定了体系"的一问。

## 第五问：把主色换成灰，页面垮不垮

**操作**：把强调色替换为 `#8A8E94`（中性灰），截图对比。

**判据**：页面仍然成立——层级、可点击性、重点仍然看得出来。

**不过意味着**：页面的一切都靠颜色区分，结构本身没有承担信息。

**典型垮法**：三档卡片靠背景色深浅区分（换灰后三档一样）；主次按钮靠颜色区分（换灰后分不出哪个是主操作）；选中态靠色块（换灰后看不出选没选）。

**修改方向**：给颜色承担的信息**补一个结构承载**——线宽、字重、留白、位置、图标、序号，任选其一叠上去。**不是把颜色撤掉**：这一问的正确终态是"彩色版和去色版都成立"，交付出去的仍然是彩色版。把推荐档的彩底换成一条 2px 竖线，是用弱手段替换强手段，页面因此丢掉强调——那种改法在第 5 问算过、在第十一问不过，属于改错方向。

**为什么这是前七问里最有价值的一问**：它同时测了三件事——层级是否结构化、无障碍是否达标（色盲用户看到的就是这个版本）、以及设计是否有"骨架"。一页靠颜色撑起来的界面，在色盲用户眼里就是垮的。

## 第八问：方向确认门过没过（0.2.5 新增，0.2.6 加品类检查）

**操作**：打开 `design/00-brief.md` 与 `design/00-direction.md`，逐条核四件事，再看一眼成品。

1. **品类是否判定**：`00-brief.md` 字段一有没有「品类：C_」+ 依据；有无抄下该品类的十一项版式与排印默认家族。**没有品类判定的，本问直接不过**——方向再"确认"过，品类错了整组取值都错。

1b. **底面是否可溯源（0.3.1 新增，最容易漏的一条）**：`00-brief.md` 字段零里有没有**产品界面截图的三个采样值**（界面底 / 卡面 / 主色，带十六进制）；**首屏实际渲染的主底色**与「界面底」色相是否同族（色相差 ≤ 12°）。明暗不强制同向。深色底额外查有没有纵深（色相 / 光晕 / 网格 / 对象投影）；中性黑且无纵深**直接判不过**。

   **量首屏，不量 `body`（0.3.2 改，第四轮再改）。** 旧写法量 `body` 的声明值，并允许「账本里写了反差原因」豁免。实跑里稿子把 `body` 写成产品界面的 `#F4F4F8`、首屏整块铺深蓝，判据全过而用户判「颜色太深」。现在：取首屏面积最大的那层背景色来比，**只比色相族**；明暗不强制同向。**改判地面与对象的关系**：地面有可见层次，或对象自身有足够体积，二者至少其一；平涂 + 平对象 = 不过。深色若让用户问「太深？」，先减地面压迫感 / 提高对象亮度，不是硬守层次。详见 `registers/surface-recipes.md` 判据 5。

   **这一条查的是「品类名能不能代替产品」这个偷懒。** 0.3.0 判了 C1a 深色仪表，取 `#08090A`；而同一份 brief 的 C10 写着产品界面 `#F4F4F8`、V5 写着「界面浅色 → 配浅底」。两条都在，一条没读，用户第一句就是「背景为什么用纯黑色」。品类给的是版式与排印，**底色只能从产品界面来**。
2. 候选是否 **5–6 套**（少于 5 套不过，多于 6 套算噪声），甲案是否**等于该品类的默认家族**（不是模型凭空另想的基准），其余各套是否写明属于「同品类次型 / 跨品类借用 / 换对象表达 / 整包换材料 / 极端档」中的哪一类，各有换来 / 放弃 / 证据级别，**并且每套有主关系主张**（「借了 ___ 这个类型，它自带的规矩是 ___」）**与破例清单**（每处三字段：破在哪 / 破了哪条规矩 / 为什么该破；可以多处，不设上限；**理由写"为了层次 / 高级 / 呼吸感"的一律判不过**，必须指向页面上的具体内容或文案）。破例清单的格式与合格理由对照表见 `readback.md`。
2b. **判同是否成立（新增，防"六版其实是一版"）**：任意两套之间，构图 / 材料 / 对象表达三轴至少两轴不同；去色并排测试跑过并贴了命令与结论。只有配色、只有底面明暗、只有字号的 → 判为同一套，本问不过。
3. 「用户选择」栏是不是**用户原话或明确授权**（「你定」「都画出来我再挑」都算授权，照录原话）。写成「按 brief 推定」「用户未反对」一律不合格；用户没回就写没回，不许粉饰成认可。
4. **每一版**的底面 / 卡面 / 墨色 / 次文字 / 线 / 曲率 / 字重 / 密度，是否与它那套 `C_` + `S_` + `P_` **成组一致**（不是只换了 `#paper`）；账本里是否有「品类与默认家族一致性」「表面配方编号」「方向确认状态」三行，且配方编号**逐版各有一条**。

**判据**：五条全过（含 1b、2b）。特别注意四种失败组合：**「成品是暖白、品类是开发工具」**（品类判错）、**「成品是暖白、R2 参考是深底、却查不到用户确认」**（方向没交出去）、**「底面查不到任何产品界面采样值」**（模型凭品类名猜的，0.3.1 新增）、**「五版去色后并排看不出区别」**（六版其实是一版，2b 新增）。

**不过意味着**：品类判错 → 退回 **S1** 重判品类；方向是模型单方面定死的 → 退回 **G0** 补方向清单与用户确认。**都不是退回 S4 改 CSS**。若确实无法取得用户回复，按 `direction-gate.md` 标「未确认，模型暂按 5–6 套全部画出」，本问写「不过」，并在已知短板里列出「方向未经确认」。

**为什么问这个**：0.2.4 及之前这里完全没有这一问。结果 `probe` 实测两条参考都是深底，交付三稿全是暖白，U5 自己写下「本版接受」，流程却一路绿灯。七问只检查页面，不检查「谁有权定方向」。

## 第九问：空白有没有任务（0.2.5 新增）

**操作**：在目标视口渲染，量四件事，对着账本的「密度契约」行读一遍。

1. 内容字数 × 版心宽度是否匹配：内容腰斩后有没有重算版心上限。
2. 两栏（或任意并列区）的内容高度差是否超过上限；差出来的空白写没写用途。
3. 每一块 ≥64px 的空白，能否说出它是**分组 / 呼吸 / 对齐 / 等待内容**中的哪一种；说不出用途的就是没有任务。
4. section / 栏的最小填充率是否达标（参考 `05-whitespace-audit.md` 实测：220px 左栏只有 45px 文字，填充率 9–15%，读作未完成）。**跑 `probe-energy.py` 的 ④ 段拿数字**：它按栏报最长空横带与填充率。整块横扫量不出两栏里单栏的死白——2026-11-11 母婴稿整块填充率 0.56 看着正常，左栏单独量是 0.35、最长空横带 144px，用户原话"大量的空白导致不舒适感"。

**判据**：每块大面积空白都能在账本里指到用途，且两栏内容量不失衡。

**不过意味着**：留白是结构挤出来的，不是设计出来的。回 **S3** 改「密度契约」与相关骨架行，再重拍；必要时撤掉为补空而新增的结构列（消融 E1 已验证：单撤「左科目栏」一行，三段空栏即归零）。

**为什么问这个**：上一轮并排比里，新稿页高 2733px / 1552 字、官网 5401px / 3289 字，首屏右下空 441px、三段左栏累计空 1045px，而七问 + 十态 + 功能底线**全部通过**。下限检查不保证「不空洞」。

## 第十问：首屏有没有一个 P0，而且只有一个（0.3.0 新增）

**操作**：打开 `design/01-content.md` 的位次表与首屏元素清单，对着目标视口截图，数三件事。

1. **数首屏元素。** 一句标题、一段说明、一个按钮、一张图、一个数字、一条命令、一条导航，各算一个。**成组的同类事实算一个**（一条事实带、一组并排数字、一张小表）。桌面 ≤7，移动 ≤5。
2. **填 P0 句式。** 遮住首屏其余部分，只看位次表标为 P0 的那一块，问「这一屏我只要你 ______」。填不出 → 没有 P0；能填出两个 → 有两个 P0，等于没有。
3. **查三个东西是不是同一个事实。** `01-content.md` 的 P0、`01-thesis.md` 的一句话主张、首屏截图里**视觉权重最大**的那一块（面积 × 对比 × 是否独占），三者指向同一个事实。
4. **查首屏最大的那个字属于谁（0.3.2 新增）。** 探针或 DevTools 取首屏 `font-size` 最大的那个元素，抄下它的文字。它必须是**用户能带走的东西**：可核对的数字、结果、画面、动作、对象身份。若它是立场句、免责声明、否定句、定位宣言或区块标签 → **不过**，回 S1.5 重选 P0（`content-architecture.md` 规则 1b）。
   实测依据：同一轮里美妆稿把 48px 给了「个体差异存在，本品不承诺见效时间」、产品名只有 36px，用户判「重点没那么突出」；母婴稿把 72px 给了「52 × 44 × 23」，用户选它。两稿的旧第十问都过。
5. **查首屏最大的那块图属于谁（0.3.2 新增）。** 跑 `python3 scripts/probe-structure.py <该版.html>`，读「主图形」和「首屏工具控件」两行。先答一句：**这块图画的是产品本身，还是一个用来看数据的界面？** 推广页 / 详情页 / 落地页的答案必须是前者。三条硬线：
   - 首屏主图形**不许是需要读坐标轴 / 刻度 / 图例的分析图表**（探针报「有坐标轴/网格」「有图例」即命中）。
   - 首屏**工具控件（滑块 / 开关 / 下拉 / 视图切换）= 0**，「导出 / 重置 / 随机」一类按钮也不许出现在推广页首屏。
   - 摘要卡合法：一个大数字 + 一条 bar + 一行说明 + 几个标签，不需要读轴就能看懂。
   - **例外只有一个**：页面本身就是数据工作台 / 监控台 / 编辑器，此时图表和控件就是对象，这一条不适用，但要在账本里写明页面类型。
   - **软件产品的对象是「它的界面」，不是「它的数据」。** App / 桌面软件的推广页，对象是一块被当作物件渲染的产品界面（有窗口边界、有投影、有材质，里面可以有图表）。**把里面的图表抽出来铺满首屏，就换错了对象**——那不再是"这个软件长什么样"，而是"一张分析图"。分界：图表在物件里面 = 对象的一部分；图表自己占住首屏 = 界面。

   实测依据（同一份冻结 brief，用户只看首屏就投票，2026-11-11 第二轮）：

   | 题 | 稿 | 首屏最大的那块图 | 工具控件 | 用户原话 |
   |---|---|---|---|---|
   | Relay | 不加载技能 | **没有图表**，右栏是摘要卡：`1,284` 大数字 + 一条比例条 + 最慢一条 + 五个失败类型标签 | 0 | **选它**，「重点突出，言简意赅，清新」 |
   | Relay | 加载技能 | **274 图元**的对数刻度时序图 | 0 | 「颜色太深、UI…分布不合理」 |

   | 推车 | 加载技能 | **81 图元的产品静物** | **0** | **选它** |

   **图元数不是判据，画的什么东西才是**：81 > 62，赢的那稿反而更复杂。274 之所以是缺陷，不是因为多，是因为它是一张要读轴的图。摘要卡与图表的分界就是**要不要读轴才能看懂**。探针只摆数字，判「对象还是界面」要人看图。

   **第 4、5 步合起来在这三对上复现了用户的选择（事后回测，不是新样本）**：

   | 稿 | 第 4 步·最大的字 | 第 5 步·最大的图 / 控件 | 新判据 | 用户 |

   | t3c | 「52×44×23cm」数字 ✓ | 81 图元产品静物 / 0 ✓ | 过 | **选** |
   | t3a | 「折叠婴儿推车 A2」对象身份 ✓ | **坐标轴 + 网格 / 7 控件 + 10 按钮** ✗ | **不过** | 未选 |

   **这是回测，不是验证**：阈值和形态是看着这三对定出来的，再用同一批数据检验，必然对得上。它只证明「这两条能说出用户为什么那样选」，不证明下一批也对。**下一次交付要在新题上现跑，对了才算数。**

6. **查首屏是不是一张画（0.3.3 新增，第四轮修订）。** 第 4、5 步认对了对象仍会输；但把画面手法做成硬门也会输。看四件事，每件在截图上指得出位置：
   - **地面托住对象**：有可见层次（点阵 / 细网格 / 剪影 / 光晕 / 斜向光带），或对象自身有足够体积；平涂 + 平对象 = 不过。明暗不限，深色不得压过对象。
   - **对象不被压扁**：产品 / 窗体默认浮置；若用容器，容器像材质的一部分，不是装饰性 1px 边框 / 直角底色矩形。圆角跟对象材质走。
   - **首屏完整**：底边留白必须有任务（聚焦对象 / 呼吸 / 滚动暗示）；无内容且无任务的死白 = 不过。不得为凑 88% 加无意义事实带 / chip / cue。
   - **标题有层级**：衬线 / marker 下划线 / 行内强调 / 字距眉题是候选手势；纯 sans 若字重 / 字距 / 层级成立可过。
   - 软件窗体默认**高宽比 ≥1.0**（竖于方），横屏工作台例外。

   实测依据（2026-11-11 第三轮，同一份冻结 brief，用户投票）：

   | 题 | 技能臂缺陷（截图可指） | 用户原话 | 基线赢在哪 |

7. **查内容表达与主操作克制（第四轮新增，先于画面手法）。** 把首屏截图给没看过 brief 的人（没有独立执行者就自看并标明非独立），问三句：这是什么产品？最关键的事实 / 结果是什么？多少钱或怎么买？三句答错 / 漏 / 被装饰文案带偏 = 不过，回去改文案与位次。再查视觉权重排序：对象 / 产品身份 / P0 > 次级事实 > 主操作 / 价签；按钮不得成为首屏最大字或最大色块，价签不得单独放大成 P0（brief 把价格列为唯一决策事实除外）。**画面手法只加分，不替代说得准。**

   第五轮补三查（布局已被认可「整体布局应该都可以了」，输的全是内容区语义）：
   - **裸数字**：首屏最大的数字，一眼能答「比谁、哪个维度」？答不出 = 不过。「比 87 键短约 60 mm」+ 虚影尺寸线是事实；单独放大「60mm」会被猜成厚度。改成带比较的句子或对比图，不靠字号。
   - **感官词占位**：风味 / 气味 / 手感词（柑橘 / 红茶 / 蔗糖）有没有占内容区独立展示位？有 = 不过，降回对象标签 / 图注 / 次级小字——它们回答不了「这是什么产品」。
   - **行距填充**：清单 / 账目 / 明细的行距有没有为撑开空间被拉大？有 = 不过，回到品类密度；空白先问「该不该存在」，不是「怎么填满」。

   第五轮用户原话：「为啥要在内容区展示柑橘、红茶和甘蔗呢，这能表达啥产品」「你直接展示60mm就是为了表达产品薄？」「内容区行间距反而被拉大了，不如乙图」。

   第六轮补：查文案表述（用户点明「我说的内容是文案表述啊，你一直都没理解我的意思」）。**「内容」指文案怎么写，不是放哪个事实。** 三查：
   - **标题是不是买家话**：把首屏标题单独抄出来，问「这句话在跟谁、说什么好处或处境」。答得出 = 过；只是「产品名 + 品类标签」（单品咖啡豆月度订阅 / 本地记账 APP）= 不过，回 S1.5 重写标题。结果句可当 P0。
   - **有没有接住来路的话**：首屏有没有一句点出目标读者处境 / 顾虑的句子（「喝惯了一种味道想换换，又怕踩雷」「给记过账、但每次都半途而废的人」）。没有 = 不过。
   - **用「你」还是「用户」、织句还是贴标签**：出现「用户自己的」、chip 堆叠、「01 / 02 / 03」编号说明书分段 = 不过，改成「你」+ 完整句子。

   **这是回测，不是验证**：判据看着已投的票定出来，再用同一批检验必然对得上。下一批新题现跑对了才算数。离线依据见 `references/taste-gallery.md`（两张用户认可首屏）。

**判据**：七条全过。**但 P0 是内容位次的第一，不是像素面积的第一**：产品名、产品图、购买入口是品类身份，不许为给 P0 让位被降成行内小字或挤出首屏。品类把视觉重量交给影像时，P0 与影像共同构成首屏主体即算过。元素数 ≤7 / ≤5 是上限不是目标——删到 5 个但删出死白，第九问不过。2026-11-11 实测：美妆稿把产品名压到 24px 行内小字（品类默认 28–36）、母婴稿把购买按钮缩成小色块，两稿都"过了"旧第十问，用户三组全选基线。

**上限不是删事实的许可证（0.3.2 补）。** 同一轮的美妆稿在 `01-content.md` 里写：三个浓度「首屏元素上限 7，已被 P0 + 回执 + 三无 + 购买占满」→ 移到第二屏。用户看到的首屏因此没有"里面到底有什么"，原话「产品信息不详细」。**数元素时，成组的事实算一个单元**：一条事实带（15 项 / 32 名 / 6 个月 / 7 天）、一组并排数字（烟酰胺 4% · 泛醇 2% · 积雪草苷 0.5%）、一张小表，各算 **1 个**，不是 4 个或 3 个。上限拦的是"互不相干的单元堆了八个"，不是"一个单元里放了四条数据"。

排不下时的正确顺序：① 先把同类事实合并成组；② 再把 P2 挪出首屏；③ 仍排不下才动 P1。**品类身份事实（产品是什么、里面有什么、多少钱、怎么买）永远不因上限被移出首屏**——它们是用户判断的对象本身，删掉它们等于让用户对着一个不知道是什么的东西做决定。赢的那一稿正是这么做的：三张卡（身份 / 尺寸 / 购买）+ 一张图版，四个单元装下全部决定性事实。

**不过意味着**，三种不同原因，回的地方不一样：
- 位次没排或排不出 P0 → 回 **S1.5**，不是改页面
- 排了但排版没执行（P0 在视觉上不是第一） → 回 **S3**，改面积 / 对比 / 独占三行
- **首屏被一张分析图表或一个工具面板占住** → 回 **S3**，把那块视野还给产品对象；图表降级成摘要卡或移到第二屏，控件移到真正的工作台页
- pattern 的模板顺序吃掉了 P0（比如先导航后标题、先 feature 后结论） → **改 pattern**，不许把 P0 挪去迁就模板

**为什么问这个**：0.2.6 三稿地板全过、九问过四条，用户评价「顶多不丑，多惊艳没有」。九问里没有一问在问"这一页有没有主次"。第二问查的是"最高饱和的是不是最重要的"，它假设"最重要的"已经存在——位次没排，这一问无从判断。**这一问要求页面必须有一处明显比别处大。**

## 第十一问：这一屏有没有塌到下限（肯定式，但仍是地板）

**操作**：对着首屏截图数四件事，全部要数字，不许写"还行"。**每版各跑一次** `python3 scripts/probe-energy.py <该版.html>`，输出原样贴进对应小节，不许一版代表全部、不许手抄约数。

1. **强调落点数**：全页最高饱和的那个色值，在首屏出现几处、分布在几个顶层区块——文字着色、描边、色块、图标、开关选中态都算，但**只数强调级颜色**（饱和度 ≥0.40 且绝对彩度 ≥0.18），正文的蓝灰/暖灰着色不算。
2. **尺度跨度**：首屏最大字号 ÷ 正文最小字号。
3. **材质职责数**：投影 / 描边 / 色块底 / 渐变 / 图像五类里，首屏实际用了几类，每类能否指到一个职责。
4. **体积载体**：投影 / 渐变 / 含渐变或滤镜的图像，三者至少一类。**单色 path 图标与平涂矢量不算体积**——探针的「图像」计数会把 15 个 16px 单色图标报成图像×15，旧判据据此判过，而页面 `box-shadow: 0`、通篇 1px 线。2026-11-11 三组实测里两稿正是这样过门的，用户三组全选不加载技能的基线，原话"到处是线框和死板""线条呆板、老登味重"。品类表写「无阴影」时（C1 / C4），体积由图像或渐变承担，不许用描边顶替。

   **⛔ 体积必须长在「这一页的对象」上（0.3.2 补，这是上面那条的必需限定）。** 只要求"有体积"、不规定"体积长在哪"，模型就会把它放在最省力的地方。实跑账本原话一行坐实：

   > `L-07 / L-08`｜浅底 + 1px 线 + 零阴影 + 一张平涂矢量插画 → **满幅品牌色域 + 含 `linearGradient`/`radialGradient`/`filter` 的玻璃示波屏**｜理由「默认方案没有连续明暗，撤掉照片就是线框；本页的体积来自数据本身」

   一次替换同时造出两个缺陷：**整屏变深**（用户判「颜色太深」）和**首屏多了一张 274 图元的对数刻度时序图**（用户判「UI 分布不合理」）。两项旧判据都过，因为"体积"确实有了。

   所以先认对象，再认体积：
   - **推广页 / 详情页 / 落地页的对象 = 产品本身。** 体积 = 产品材质的连续明暗（玻璃、金属、织物、塑料的受光面、投影、透光）。同一轮里赢的两稿正是这么做的：47 图元的琥珀玻璃瓶、81 图元的推车静物。
   - **满幅背景色域不算体积载体**——它是底，不是对象。
   - **数据图表不算体积载体**——它是分析界面，不是对象。给图表加辉光来凑这一项，等于用错对象换通过。
   - **只有当页面本身就是数据工作台 / 监控台时，图表才是对象**，此时体积长在图表上合法。
   - brief 禁照片时，替代物是**把产品对象画到有材质**，不是换成一张图表或一片色域。
5. **首屏空洞**：探针 ④ 段按栏报告最长空横带与网格填充率。**整块横扫量不出两栏布局里单栏的死白**，所以探针把内部任何深度的栏也当独立区域量。填充率 <0.50 的栏，每一块都要能说出「这块空白在干什么」；说不出回 S3 改密度契约。这一项是判断项，探针只摆数字不代答。
6. **一句"为什么是它"**：指认首屏上最值得看的那一块，一句话说清它凭什么值得看（"因为它是标题"不算）。

**判据**：① 强调落点 ≥3 处且分布在 ≥2 个顶层区块；② 跨度 ≥2.6；③ 材质 ≥2 类且各有职责；④ 体积载体 ≥1 类；⑤ 每块低填充率空白说得出用途；⑥ 那句话能在账本里找到对应行，或在 `registers/` 所选配方的标志手法里找到出处。

**落点只数强调级颜色**：`scripts/probe-energy.py` 的门槛是 HSL 饱和度 ≥0.40 **且**绝对彩度 ≥0.18。深色页的蓝灰正文（`#7E8CA6`：S 0.28）不算强调——按旧门槛实测一稿报出 42 处落点，全是正文色。这条门槛定错时，第十一问对任何深色稿都恒真。

**①b 文字着色 ≥1，且必须落在承担论断的数字或标签上**：只有色块和描边、颜色从不落在可读文字上时，强调多半在装饰而不是在论断上。这一项不设 ≥3，因为实测里排第一的稿只有 2 处文字着色（价目轨迹条上的「未调整 **10** 个月 · 调价 **0** 次」），两处都压在页面核心论断上——**要求的是位置对，不是数量多**。

**门槛按实测标定，但标定范围很窄**（同一视口 **838×1060**，`probe-energy.py`，两份无技能基线与一份新基线可比；旧 skill 两稿的 HTML 已不在本机，只有截图，故不参与这一轮标定）。**注意标定视口与交付视口不同**：关键屏默认交付在 1440×900，同一套阈值在更宽的视口上会偏松，必须在交付视口现测，不能沿用这张表的数字当结论。

| 稿 | 落点 / 区块 | 文字着色 | 跨度 | 材质 | 匿名排名 |
|---|---|---|---|---|---|
| 基线一（不加载技能） | 6 / 2 | 6 | 3.72 | 5 类（含投影、渐变、图像） | 2 |
| 基线二（不加载技能） | **2 / 1** | 2 | 3.68 | 2 类（含投影、渐变） | **3** |
| 新规则稿 pass-c | 9 / 3 | 2 | **5.00** | 3 类（含图像） | **1** |

三项判据各自能挑出的东西不同：① 挑出排名最后的基线二（整屏只有两处荧光绿文字）；② 跨度把新规则稿和另两稿拉开（60px 的 `$10` 对 42/46px）；③ 材质类数在这三稿上不分胜负，它管的是另一类失败——旧 skill 稿 B 只有描边一类材质，那种页面截图压缩后糊成一片。**不要指望单一数字代替判断**，这四问合起来才够用。

**这是地板标定，不是美感阈值（n=3，同一份定价页、同一个视口）。** 三条边界必须守住：换品类换视口要现测；不得拿这三个数当排名依据；**不得把"过了这道门"说成"这页好看"**。实跑里出现过落点 16 处全是 1px 描边、数字过门却比判"不过"那版更平的稿——数字拦得住"平"，拦不出"好"。好坏去第二层回读门（`readback.md`）取证，优劣去第三层并排二选一。

**不过意味着**：页面在向下限收敛，交付的是"没毛病"而不是"有吸引力"。回 S3，把强调、尺度、材质补到**所选配方规定的量**——补的依据是 `registers/` 那套配方的标志手法和品类默认家族，不是随手加颜色；随手加属于「不许事后美化」，要先进账本再落地。

**这一问不许靠撒颜色来凑数**：落点计的是同一个最高饱和色值出现几处，但第 2 问同时要求"最高饱和的东西 = 最重要的东西"。所以合法的形态是**强调成组**——主操作 + 承载 P0 的那一处（关键数字、当前选中项、推荐档标记），三处都各自有职责；把同一个高饱和色涂到装饰点、图标底色、页脚链接上凑到 3 处，第 2 问会判不过，两问一起算不过。材质类数同理：一类材质只为一处装饰服务，不算职责。

**与第 1、4、5 问必须一起读**（这四问合起来才是一个完整的判据）：

| 问 | 测什么 | 不测什么 |
|---|---|---|
| 第 1 问 | 结构能否独立于材质成立 | 不要求交付版没有材质 |
| 第 4 问 | 取值是否在刻度上 | 不奖励档数最少，跨度另查 |
| 第 5 问 | 信息是否**只**靠颜色 | 不要求把颜色撤掉 |
| 第十一问 | 这一屏有没有塌到下限 | 不管有无依据，依据仍由账本管；也不判好坏，好坏去回读门 |

一句话：**材质要有职责，职责不豁免材质。** 前三问的"过"只说明删掉它页面还成立，不说明删掉它页面更好看。

---

## 第二层：回读门（必做，规程在 `readback.md`）

十一问跑完只得到"这页没塌"。**整体感不在这一层判**——它由一个没看过账本与主张的独立实例盲看取证：

1. 这页自己的规矩是什么？
2. 哪几处不合这规矩？（逐条列，不设上限）
3. 每处为什么该破？（只准用画面上的东西回答，文案也算）

三种不过：规矩说不出 → 回 S2/S3；破例理由读不出 → 回 G0 或 S3；全守规矩 → 回 G0 重立主张。**记原话，不打分。**

原来的「独立看图」三问（第一眼落点 / 最拖累两处 / 下一步）已并进同一次盲看的第四问，**不另开一轮**。交接包给什么、不给什么、截图要求、记录格式与判据，全部见 `readback.md`。

没有独立执行者就按同一流程自看，并在报告标明"非独立"——非独立回读不构成整体感结论。

---

## 第三层：版间并排二选一（5–6 版形态下必做，与地板和回读门分开）

十一问逐版跑完只得到"每版都没塌"，回读门逐版跑完只得到"每版都有自己的道理"，**两者都得不到"该选哪版"**。选版这一步另有规程：

1. **同视口截图**：所有版用同一 `--window-size` 各截首屏与最难屏，拼成一张对照页（`design/compare.html`），一次看全。分屏来回看不算并排。
2. **匿名 + 打乱**：把版号换成 甲/乙/丙/丁/戊/己 并打乱顺序再交给评审者；第二轮换一种打乱。带版号的对照里，"第 1 版"天然占优——顺序本身是有内容的信息。
3. **只问三件事**：第一眼落到哪版、愿意用哪版、哪两版你觉得是同一个东西。**不问"哪版分数高"**，探针数字这轮不参与。
4. **回读**：出现「这俩不是一样吗」的时候，判同测试漏了——回去重列那一套，而不是把它删掉。
5. **结论归用户**：评审者的偏好是证据，不是授权。写进 `03-critique.md` 的是"几人各选哪版、理由原话"，不是"综合评分最高者为 v3"。

**为什么必须单独做这一节**：0.3.0 的实跑里，同一份冻结输入产出的三版共用 G0 锁定的方向，只差在栏目顺序；十一问逐条都过，用户看完的评价是"都一样"。门管不了方差，方差只能靠并排看图被抓出来——**而抓出来的处理方式是重列，不是淘汰**。

## 出口判据

- 十一问全部有结果和证据（不能只写"过"）
- 第八问的「用户选择」必须是可引用的原话或授权记录；第九问的空白用途必须能指到账本行；**第十问的首屏元素个数必须是数出来的数字，不是"看起来不多"**；**第十问第 4、5、6、7 步各抄一次原文**——最大的那个字写的是什么、最大的那块图画的是对象还是界面（附 `scripts/probe-structure.py` 的坐标轴/网格、图例、工具控件数）、第 6 步四件事各在截图的哪个位置（地面托住对象 / 对象不被压扁 / 首屏完整 / 标题层级，软件窗体另附高宽比）、第 7 步三问复述与视觉权重排序；**第十一问的四项必须全是数字（强调级落点几处 / 跨几个顶层区块、其中文字着色几处、跨度几倍、材质几类），"整体挺有质感"不算证据**。能跑 `scripts/probe-energy.py` 就直接贴它的输出，不要手抄一个约数。
- **回读门逐版各跑一次，三问原话照录**：执行者与独立性已标明；交接包不含账本 / 主张 / 破例清单；截图是交付视口的全分辨率图（文案读得清）；「与我的破例清单的差异」一栏已写。**没有回读记录的版，不算验收完成**——十一问全过也不能代替它。
- **回读门判不过的三种形态已按对应阶段退回改过**，改完由新实例重新盲看；不许用"我解释一下就懂了"代替修改。
- 状态矩阵空格数为 0
- 有参考/校准时：并排比的差异已逐条归因到关系，并修到持平或明写接受
- 已知短板 ≥1 条且具体
- 不过的项已经回到对应阶段修改，或明写"本版接受此缺陷，原因是___"
- 功能验证、审美判断、用户认可分开报告；未运行的不写通过，用户未反馈写未反馈

最后一条的措辞很重要：接受缺陷可以，但要**明写**。偷偷留着的问题会在用户那里变成"这个 skill 也就那样"。
