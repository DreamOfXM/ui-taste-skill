1# S5 验收：十问
2 
3输出的文件是 `design/03-critique.md`。
4 
5不是打分。每一问只有"过 / 不过"，不过的写清**回哪一步改**。
6 
7十问的设计原则：前七问都能不看设计稿、只用一句话或一个操作回答；第八、九、十问要回读 `00-direction.md`、账本与 `01-content.md`。答不上来的，就是不过。
8 
9**0.2.5 从七问扩成九问**：第八问查「方向是不是用户定的」（补方向确认门），第九问查「空白有没有任务」（补 `05-whitespace-audit.md` 的密度缺口）。前七问全是否定式下限检查，能给出「通过」却仍留下满屏空洞和一个模型单方面定死的底色——这两问补的是**流程合法性与关系属性**，不是再加两条工艺。
10 
11**0.3.0 从九问扩成十问**：第十问查「首屏有没有主次」。0.2.6 三稿过了前九问中的四条，用户评价仍是「顶多不丑，多惊艳没有」——十问里原本没有任何一问在问这件事。第二问「最高饱和的是不是最重要的东西」看似相关，但它假设"最重要的东西"已经存在；位次没排，这一问无解。

21## 第零步之后：与天花板并排比（有参考 / 校准必做）
22 
23第一至第七问是**否定式**的（找缺陷），全过≠好。要逼近"好"，必须有一个**肯定式**的对照物：天花板参考或 incumbent。
24 
25**操作**：把成品与参考在**同视口**渲染截图，并排放在一起看（不是先后看、不是只看成品）。逐条列出差异，并归因到**关系**：顶部空带、字级/字重、留白节奏、材料取景、层级落点。
26 
27**判据**：每条差异要么修到持平/更好，要么明写"本版接受，原因是___"。归因写"规则没写这条"不算归因——要写到产生差异的那个系统（例如 nav 是 fixed 还是正常流，决定了 hero padding 是否已含 nav 高度）。
28 
29**校准特别注意**：继承的是**产生取值的系统**，不是源码字面值。抄 `pt-28` 而自己的 nav 在正常流，会把 nav 高度再叠一次（顶部空带翻倍）。对齐靠**测量渲染结果**（内容距视口顶的总距离），不靠抄 padding。

31无参考的开放设计跳过此步，但下面的独立看图仍必做。

35## 第一问：剥掉装饰还剩几层
36 
37**操作**：在浏览器里给页面注入 `* { box-shadow: none !important; border-radius: 0 !important; background-image: none !important; }`，然后看层级是否还成立。
38 
39**判据**：去掉装饰后，视线仍能分出 ≥3 个层级（标题层 / 内容层 / 辅助层）。
40 
41**不过意味着**：结构靠阴影、圆角、渐变撑着，而不是靠字号、字重、留白、对齐。回 S3 改「层级」相关行。
42 
43**为什么问这个**：AI 生成界面最典型的形态是"每个块都是白卡片 + 阴影"，层级全靠阴影深浅。这种页面一旦打印、截图压缩、或在低端屏上就糊成一片。

47## 第二问：最高饱和的东西是不是最重要的东西
48 
49**操作**：截图后在图像编辑里降低饱和度看灰度值，或直接找页面上饱和度最高的那个色块。
50 
51**判据**：最高饱和/最高对比的物体 = brief 字段二的"唯一任务"所指的东西。
52 
53**不过意味着**：注意力被次要元素抢走。常见违规：推荐档的彩色背景比价格还抢眼；一个装饰性的渐变球比主按钮显眼。回 S3 改「强调色」行。

58 
59**操作**：任选页面三个位置，各截 200×200 无损区域。

69## 第四问：每个数值都在刻度上吗
70 
71**操作**：在 DevTools 里把页面上所有 `padding`、`margin`、`gap`、`font-size`、`border-radius` 的值导出来去重。
72 
73**判据**：
74- 间距值全部落在 `tokens/scale.md` 的刻度表上（4/8/12/16/24/32/48/64/96）
75- 圆角 ≤2 档
76- 字号 ≤6 档
77 
78**不过意味着**：存在"随手值"（13px、5px、18px 这种）。随手值是"没有体系"的物证。回 S3 按刻度重填。
79 
80**这一问是最客观的一问**，不需要审美判断，只需要数数。也是最能反映"是否真的定了体系"的一问。

84## 第五问：把主色换成灰，页面垮不垮
85 
86**操作**：把强调色替换为 `#8A8E94`（中性灰），截图对比。
87 
88**判据**：页面仍然成立——层级、可点击性、重点仍然看得出来。
89 
90**不过意味着**：页面的一切都靠颜色区分，结构本身没有承担信息。
91 
92**典型垮法**：三档卡片靠背景色深浅区分（换灰后三档一样）；主次按钮靠颜色区分（换灰后分不出哪个是主操作）；选中态靠色块（换灰后看不出选没选）。
93 
94**修改方向**：把颜色承担的信息转给结构——线宽、字重、留白、位置、图标、序号。回 S3。
95 
96**为什么这是前七问里最有价值的一问**：它同时测了三件事——层级是否结构化、无障碍是否达标（色盲用户看到的就是这个版本）、以及设计是否有"骨架"。一页靠颜色撑起来的界面，在色盲用户眼里就是垮的。

120## 第八问：方向确认门过没过（0.2.5 新增，0.2.6 加品类检查）
121 
122**操作**：打开 `design/00-brief.md` 与 `design/00-direction.md`，逐条核四件事，再看一眼成品。
123 
1241. **品类是否判定**：`00-brief.md` 字段一有没有「品类：C_」+ 依据；有无抄下该品类的十一项版式与排印默认家族。**没有品类判定的，本问直接不过**——方向再"确认"过，品类错了整组取值都错。
125 
1261b. **底面是否可溯源（0.3.1 新增，最容易漏的一条）**：`00-brief.md` 字段零里有没有**产品界面截图的三个采样值**（界面底 / 卡面 / 主色，带十六进制）；成品底面与「界面底」是否同族（`ΔL ≤ 6%`、色相差 ≤ 12°），若故意反差，账本里有没有写原因。深色底还要额外查一件事：`S ≥ 20%` 吗？`#08090A`（S 6%）这类中性黑**直接判不过**。
127 
128   **这一条查的是「品类名能不能代替产品」这个偷懒。** 0.3.0 判了 C1a 深色仪表，取 `#08090A`；而同一份 brief 的 C10 写着产品界面 `#F4F4F8`、V5 写着「界面浅色 → 配浅底」。两条都在，一条没读，用户第一句就是「背景为什么用纯黑色」。品类给的是版式与排印，**底色只能从产品界面来**。
1292. 候选是否 **≥3 套**，甲案是否**等于该品类的默认家族**（不是模型另想的三套），乙/丙是否写明是「同品类次型」还是「跨品类借用」，各有换来 / 放弃 / 证据级别。
1303. 「用户选择」栏是不是**用户原话或明确授权**（「你定」算授权，照录原话）。写成「按 brief 推定」「用户未反对」一律不合格；用户没回就写没回，不许粉饰成认可。
1314. 成品的底面 / 卡面 / 墨色 / 次文字 / 线 / 曲率 / 字重 / 密度，是否与选定 `C_` + `S_` **成组一致**；账本里是否有「品类与默认家族一致性」「表面配方编号」「方向确认状态」三行。
132 
133**判据**：四条全过（含 1b）。特别注意三种失败组合：**「成品是暖白、品类是开发工具」**（品类判错）、**「成品是暖白、R2 参考是深底、却查不到用户确认」**（方向没交出去）、**「底面查不到任何产品界面采样值」**（模型凭品类名猜的，0.3.1 新增）。
134 
135**不过意味着**：品类判错 → 退回 **S1** 重判品类；方向是模型单方面定死的 → 退回 **G0** 补组合卡与用户确认。**都不是退回 S4 改 CSS**。若确实无法取得用户回复，按 `direction-gate.md` 标「未确认，模型暂按组合 __ 推进」，本问写「不过」，并在已知短板里列出「方向未经确认」。
136 
137**为什么问这个**：0.2.4 及之前这里完全没有这一问。结果 `probe` 实测两条参考都是深底，交付三稿全是暖白，U5 自己写下「本版接受」，流程却一路绿灯。七问只检查页面，不检查「谁有权定方向」。

141## 第九问：空白有没有任务（0.2.5 新增）
142 
143**操作**：在目标视口渲染，量四件事，对着账本的「密度契约」行读一遍。
144 
1451. 内容字数 × 版心宽度是否匹配：内容腰斩后有没有重算版心上限。
1462. 两栏（或任意并列区）的内容高度差是否超过上限；差出来的空白写没写用途。
1473. 每一块 ≥64px 的空白，能否说出它是**分组 / 呼吸 / 对齐 / 等待内容**中的哪一种；说不出用途的就是没有任务。
1484. section / 栏的最小填充率是否达标（参考 `05-whitespace-audit.md` 实测：220px 左栏只有 45px 文字，填充率 9–15%，读作未完成）。
149 
150**判据**：每块大面积空白都能在账本里指到用途，且两栏内容量不失衡。
151 
152**不过意味着**：留白是结构挤出来的，不是设计出来的。回 **S3** 改「密度契约」与相关骨架行，再重拍；必要时撤掉为补空而新增的结构列（消融 E1 已验证：单撤「左科目栏」一行，三段空栏即归零）。
153 
154**为什么问这个**：上一轮并排比里，新稿页高 2733px / 1552 字、官网 5401px / 3289 字，首屏右下空 441px、三段左栏累计空 1045px，而七问 + 十态 + 功能底线**全部通过**。下限检查不保证「不空洞」。

158## 第十问：首屏有没有一个 P0，而且只有一个（0.3.0 新增）
159 
160**操作**：打开 `design/01-content.md` 的位次表与首屏元素清单，对着目标视口截图，数三件事。
161 
1621. **数首屏元素。** 一句标题、一段说明、一个按钮、一张图、一个数字、一条命令、一条导航，各算一个。桌面 ≤7，移动 ≤5。
1632. **填 P0 句式。** 遮住首屏其余部分，只看位次表标为 P0 的那一块，问「这一屏我只要你 ______」。填不出 → 没有 P0；能填出两个 → 有两个 P0，等于没有。
1643. **查三个东西是不是同一个事实。** `01-content.md` 的 P0、`01-thesis.md` 的一句话主张、首屏截图里**视觉权重最大**的那一块（面积 × 对比 × 是否独占），三者指向同一个事实。
165 
166**判据**：三条全过。
167 
168**不过意味着**，三种不同原因，回的地方不一样：
169- 位次没排或排不出 P0 → 回 **S1.5**，不是改页面
170- 排了但排版没执行（P0 在视觉上不是第一） → 回 **S3**，改面积 / 对比 / 独占三行
171- pattern 的模板顺序吃掉了 P0（比如先导航后标题、先 feature 后结论） → **改 pattern**，不许把 P0 挪去迁就模板
172 
173**为什么问这个**：0.2.6 三稿地板全过、九问过四条，用户评价「顶多不丑，多惊艳没有」。九问里没有一问在问"这一页有没有主次"。第二问查的是"最高饱和的是不是最重要的"，它假设"最重要的"已经存在——位次没排，这一问无从判断。**十问里只有这一问是肯定式的：它要求页面必须有一处明显比别处大。**

177## 独立看图（必做；缺独立执行者则自看并标明"非独立"）
178 
179有独立读图执行者时，把任务、约束与当前截图交给它，暂不给账本和你的设计理由——继承了你的理由，它就继承了你的辩护：
180 
181```text
182任务：用户要对什么对象完成什么动作；保留哪些事实与能力。
183图片：同视口关键屏 + 密集/窄屏状态；有原稿一并给出。
184请先读图：1) 第一眼落点与一处值得保留的关系；2) 最拖累画面的至多两处（位置→根因→改动→预期结果）；3) 下一步：保留方向 / 改局部 / 重做 / 证据不足。
185```
186 
187收到意见后再对照账本。没有独立执行者就按同样顺序自看，并在报告标明"非独立"。

216## 出口判据
217 
218- 十问全部有结果和证据（不能只写"过"）
219- 第八问的「用户选择」必须是可引用的原话或授权记录；第九问的空白用途必须能指到账本行；**第十问的首屏元素个数必须是数出来的数字，不是"看起来不多"**
220- 状态矩阵空格数为 0
221- 有参考/校准时：并排比的差异已逐条归因到关系，并修到持平或明写接受
222- 已知短板 ≥1 条且具体
223- 不过的项已经回到对应阶段修改，或明写"本版接受此缺陷，原因是___"
224- 功能验证、审美判断、用户认可分开报告；未运行的不写通过，用户未反馈写未反馈
225 
226最后一条的措辞很重要：接受缺陷可以，但要**明写**。偷偷留着的问题会在用户那里变成"这个 skill 也就那样"。
