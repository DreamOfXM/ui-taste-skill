# 内容优先级：先决定说什么，再决定怎么排

> **本文按推广面写**（落地页 / 详情 / 定价：来了解要不要用的人）。产品面（App 内页、内容流、工作台、设置）的位次表照样排，但「首屏最大的字给 P0」换成「首屏最大的面积给真实内容或工作对象」，口号与 lede 压成一行小字或不写；首屏三问里的「多少钱或怎么买」换成「我下一步能做什么」。用途怎么判见 SKILL.md「先判用途」。

输出的文件是 `design/01-content.md`。**这一步不做任何视觉决定**，只回答一个问题：这一页要按什么顺序、说什么、不说什么。

它排在读约束之后、**方向确认之前**。把这个阶段放在方向确认前面，是因为方向卡要给用户看的不只是色值，还包括「这套表面配这个主角事实会长什么样」；内容没排位次，方向卡就只能比颜色，用户也只能凭顺眼挑。排完位次再问方向，用户确认的是"你要给我看什么 + 用什么材质给我看"，一次问清。

---

## 为什么单独立一层

0.2.6 的字段三叫「内容事实」，它记录**有什么**（C1–C10 逐条带出处），但不做**排序**。于是到写页面时，模型能做的只有一件事：把十条事实平均铺开。

这不是模型的审美问题，是输入缺了一个维度。用户在 0.2.6 交付后的原话：

> 「顶多不丑，你说如果多惊艳，目前没有。」
>
> 「在分析问题时，我们一定要把我们要展示的 UI 的优先级，内容组织的优先级给排好，第一优先级是什么？第二是什么？第三是什么？用户最想看到的是什么，或者说我们应该给用户呈现的是什么。」

「不丑」是可以靠工艺清单达到的；「惊艳」的第一个必要条件，是**注意力有明确的主次**。而注意力主次在排颜色之前就已经决定了——它由内容的位次决定。

九问里原本没有一问能抓住这个缺口。第二问「最高饱和的是不是最重要的东西」看似相关，但它假设「最重要的东西」已经存在；优先级没排，这一问无从判断。

## 一、四级位次

| 位次 | 定义 | 数量上限 | 位置约束 |
|---|---|---|---|
| **P0** | 用户在这一屏**必须获得的那一个信息**，或必须做的那个动作；且必须是他能带走的（规则 1b） | 每屏 1 个；全页共 1 个"总 P0" | 首屏视觉重心，独占最大对比与最大字号 |
| **P1** | 支撑 P0 成立的证据。没有它，P0 会被当成吹牛 | 2–3 条 | 首屏下半，或紧接 P0 的第二屏 |
| **P2** | 补充与可信度：参数、资质、渠道、技术细节 | 5–8 条 | 首屏之外，可扫读，不要求读完 |
| **P3** | 折叠内容：FAQ、常见误解、法务、页脚 | 不限 | 允许用户永远不看 |

四级不是"重要 / 次要 / 更次要"的形容词分级，是**位置承诺**：P0 必须在折叠线以上且视觉权重第一，P3 必须不在首屏。位次和位置不一致，就是没排。

## 二、五条排序规则

### 规则 1：P0 必须能填进这个句式

> 这一屏我只要你 ______。

填不出来，说明这一屏是"该有的都有"，没有 P0。填出两个，说明这屏要拆，或者其中一个其实是 P1。

### 规则 1b：P0 必须是用户能**带走**的东西（0.3.2 补，这条以前是漏洞）

句式填得出来还不够。再问一句：**用户看完这一句，手里多了什么？**

| 能当 P0 | 不能当 P0 |
|---|---|
| 一个可核对的数字（收折后 52 × 44 × 23 cm、1,284 条已记录） | 一句立场（「我们不做『7 天见效』承诺」） |
| 一个结果或画面（你的盘被这五样吃了 84.4 GB） | 一句免责声明（「个体差异存在，本品不承诺见效时间」） |
| 一个能立刻做的动作（`brew install relay`、加入购物袋） | 一句否定句（「这不是清理工具」「不上传任何请求体」） |
| 对象本身的身份（产品名 + 产品图） | 一句定位宣言（「成分透明型护肤品的重新定义」） |

右边那一列**全部是 P1**：它们支撑信任，但用户带不走。它们可以醒目、可以独占一块、可以有自己的材质，**但不得占据首屏最大字号**。首屏最大的那个字必须属于左边那一列。

**为什么加这条（真实发生）**：同一份冻结 brief、同一套流程，两稿都认真跑完了 P0 选法，结果相反——

| 稿 | 选中的 P0 | 首屏最大字号给了谁 | 用户投票 |
|---|---|---|---|
| 母婴推车 | 「收折后 52 × 44 × 23 cm，可自立」 | 72px 三边读数 | **选它**，原话「图片本身已经把很多数据都呈现出来了」 |
| 美妆精华 | 「个体差异存在，本品不承诺见效时间」 | 48px 免责声明（产品名只有 36px） | 落选，原话「产品信息不详细，重点没那么突出」 |

根因在旧的 P0 找法「反常 + 具体 + 不可能被编造」：**免责声明在这三项上得分都很高**——美妆页写不承诺很反常、句子是法务级的具体、品牌不敢编。于是评分函数把一句态度选成了主角。美妆稿的 `01-content.md` 甚至专门写了一段论证「不是主张前置：P0 是一条产品事实（这瓶不承诺什么）」——它把"这句话是真的"当成了"这是一条产品事实"。**真的态度仍然是态度。**

**判断方法**：把 P0 抄在一张纸上递给用户，问他能拿它去做什么。拿去问航司、拿去比对、拿去装、拿去下单 → 是 P0。只能"记住我们的态度" → 是 P1。

### 规则 2：排序依据不是"重要性"，是**用户此刻的疑问顺序**

同一个页面，用户从不同地方来，第一疑问完全不同：

| 来路 | 第一疑问 | P0 应该是什么 |
|---|---|---|
| 搜索引擎（"Mac 磁盘满了怎么办"） | 这玩意能解决我的问题吗 | 结果 / 效果 |
| 社群帖子（V2EX、知乎、即刻） | 是不是广告？会不会动我文件 | 安全机制 + 一个具体到不像广告的事实 |
| 朋友直发链接 | 这是啥 | 一句话定义 + 一个画面 |
| 已知品牌、主动搜名字 | 多少钱、怎么装 | 价格 / 安装命令 |

**一页只服务一个主来路。** 四个都服务等于四个都没服务——这是首屏塞满的直接原因。必须选一个主来路写进文件，其余来路的疑问交给 P1/P2 兜。

### 规则 3：欲望做钩子，主张跟在后面

用户想看的（欲望）和我们要他记住的（主张）通常不是一回事。正确顺序是：**用他想看的把他拉住，再把主张递过去。**

- 反例（把主张当 P0）：首屏写「这不是清理工具，是诊断工具」。用户还没有理由关心你的定位，因为他的痛还没被承认。
- 正例（欲望做钩子）：首屏写「你的盘被这五样吃了 84.4 GB，还有 11.6 GB 没量到」。他想知道谁吃了盘（欲望），读完才发现这工具连"没量到"都单独记账——主张自己浮出来了，不需要喊。

**判断方法**：把 P0 念给一个没听过这产品的人，他会不会想接着往下看。会 → 是钩子；不会 → 是你的主张，往后退一层。

### 规则 4：每条内容都要能回答"删了它用户会怎样"

答「也没什么」或「会少一点信息」的，删。这条比"重要性排序"更狠，因为它逼出真实代价。

「删了会怎样」必须写成**用户侧的具体后果**，不能写"信息不完整"：
- 合格：删了他不知道这软件会不会删错文件，会关掉页面去搜评测
- 不合格：删了内容不够丰富

### 规则 5：内容少不是问题，平均铺才是

内容只有三条时，正确做法不是拉长文案凑满，是**把 P0 放大到占据首屏主体**——一个大数字、一句断言、一张图，配大量留白。

这一条直接回应「空洞」：**空洞不是内容少，是内容少还平均分配。** 三条内容各占三分之一屏，读作"没做完"；一条内容占七成屏，读作"有主张"。

## 三、怎么找到 P0：找"反常且具体"的那个事实

不要问"哪个功能最重要"——这个问题会得到功能清单，因为每个功能都重要。改问：

> **哪个事实最反常、最具体、最不可能被编造？**

三个条件同时满足的那个，就是 P0。因为：

| 条件 | 它解决什么 |
|---|---|
| 反常 | 有记忆点。正常的东西不会被记住 |
| 具体 | 可信。形容词不可信，数字可信 |
| 不可能被编造 | 它同时是信任物。编造的东西经不起追问 |

三者交集极窄，所以一页通常只有一个。找到它，P0、信任物、记忆点三件事一次解决——这是"惊艳"最省力的路径：**不是加设计，是找到一个同时干三件事的事实。**

DiskWise 的实例：`没量到 11.6 GB`。

- 反常：所有清理软件都说"全面扫描、精准识别"，这个软件承认有 11.6 GB 它量不到。
- 具体：11.6，不是"部分"。
- 不可能被编造：编造者不会给自己造一个缺点。

于是它同时是：首屏钩子（用户想知道谁吃了盘）、信任物（敢认怂的工具才可信）、记忆点（发到群里别人只看一眼就记住）。

**注意**：这条不是要求每个产品都有"自曝缺点"的事实。它要求的是**去找那个唯一性**。没有的话，用最具体的数字（金额、时长、条数、比例），同样成立。

## 四、优先级怎么变成像素

四级位次必须落成四个可测量的量，否则"排好优先级"只是文档里的一句话。

| 量 | P0 | P1 | P2 | P3 |
|---|---|---|---|---|
| **位置** | 折叠线以上，首屏视觉重心 | 首屏下沿或第二屏首 | 首屏以下 | 折叠 / 页尾 |
| **面积** | 首屏面积 ≥25%，或独占一栏 | 合计 ≤35% | 不占首屏 | 不占 |
| **对比** | 首屏最强对比（最大字号或最重字重或唯一彩色） | 中等 | 弱 | 最弱 |
| **独占** | 四周留白 ≥1 个基准间距 | 可并排 | 可密集 | 可密集 |

**硬上限：首屏信息单元数量。** 桌面 ≤7 个，移动 ≤5 个。数得出来、可验收。

一个"信息单元"= 一个用户会单独看一眼的东西：一句标题、一段说明、一个按钮、一张图、一个数字、一条命令、一个 logo 条。超过上限，说明还没排优先级，只是把 P2 挪进了首屏。

**成组的同类事实算一个单元（0.3.2 补）。** 一条事实带（15 项 / 32 名 / 6 个月 / 7 天）、一组并排数字（烟酰胺 4% · 泛醇 2% · 积雪草苷 0.5%）、一张小表，各算 **1 个**。上限拦的是"互不相干的单元堆了八个"，不是"一个单元里放了四条数据"。

**这条上限不是删事实的许可证。** 实跑里美妆稿写「三个浓度：首屏元素上限 7，已被 P0 + 回执 + 三无 + 购买占满」→ 把它们移到第二屏，用户看到的首屏没有"里面到底有什么"，判词是「产品信息不详细」。排不下时的顺序是：① 先把同类事实合并成组；② 再把 P2 挪出首屏；③ 仍排不下才动 P1。**品类身份事实（产品是什么、里面有什么、多少钱、怎么买）永远不因上限被移出首屏。** 同一轮赢的那稿用三张卡（身份 / 尺寸 / 购买）+ 一张图版，四个单元装下了全部决定性事实。

这条上限是 0.3.0 最重要的一条可数判据。0.2.6 的 A 稿首屏 336 字、七个以上单元，全是"该有的都有"，读起来自然平。

### 事实怎么成句：一条事实一句话，一组事实一条带（0.3.2 补）

排完位次、数完单元，还差一步：**同一条事实不许拆成几行小字**。这是"页面清新"的第二层——第一层是首屏放什么（对象还是界面），这一层是同一件事怎么读。

| 形态 | 什么时候用 | 例 |
|---|---|---|
| **一句话** | 一条事实带 2–3 个限定（是什么 / 多少 / 凭什么信） | 「第三方人体斑贴试验报告编号 **SW-PT-0417** 可查」 |
| **一段话** | 3–5 条同类事实，彼此是并列关系 | 「成分表**全公开，共 15 项**，前三项标注含量：**烟酰胺 4%、泛醇 2%、积雪草苷 0.5%**。无香精、无酒精、无色素。」 |
| **一条带** | 3–6 个同量纲的数字，要能横向比 | `15 项｜32 名｜6 个月｜7 天`，四格并排，上下各一条线 |
| **一行一条** | 只用于**不同类**、且每条都要单独动作的项（导航、步骤、清单） | 收折三步、四条导航 |

**分隔线画在组的外面，不是每一行上面。** 一条事实带用 `border-top` + `border-bottom` 各一条圈住整组；给每一行都加一条上边线，读者看到的是六张独立的小票，不是一组事实。

**实测出处（2026-11-11 第二轮，同一份冻结 brief，用户只看首屏）**：

| | 输的那稿 | 赢的那稿 |
|---|---|---|
| 斑贴试验 | 拆成三个堆叠元素：`.rlabel` 13px「第三方人体斑贴试验」/ `.rline` 20px「32 名…0 例刺激反应」/ `.rno` 16px「报告编号 SW-PT-0417」，各带自己的 `margin-top` | 一句话：`.cta-note` 12px「第三方人体斑贴试验报告编号 **SW-PT-0417** 可查」 |
| 成分与三无 | `.free` 15px 一行（带自己的 `border-top`）+ `.actives` 15px 又一行 | 一段话：`.lede` 15.5px 把 15 项 + 三个浓度 + 三无写进同一句 |
| 四个数字 | 无（移到第二屏了） | `.facts` 四格横带，整组只有上下两条线 |
| 用户判词 | 「产品信息不详细，重点没那么突出」 | 「重点突出，页面清新」 |

**注意赢的那稿首屏文字块反而更多**（51 个 vs 33 个）。所以这一条**没有可靠的数字判据**：块数、小字占比、"连续几行小字"都试过量过，全都会把导航条和合法的事实带一起误报。**只能读**——把首屏每一块小字念一遍，问「这几行说的是不是同一件事」，是就合起来。

**合并不会撞上限**：成组的同类事实算 1 个单元（见上）。合并是同时解决"读起来碎"和"排不下"两个问题的同一个动作，不是取舍。

### 内容表达准确：首屏三问与主操作克制（第四轮补）

排完位次、合成句，还差一道：**首屏能不能被没看过 brief 的人复述准确**。问三句：

1. 这是什么产品？
2. 最关键的事实 / 结果是什么？
3. 多少钱，或怎么买 / 怎么用？

三句答错、答漏、被装饰文案带偏 = 不过，回位次表改文案与承载元素，不是回去加材质。**事实都在页面上 ≠ 表达准确**：拆成碎片、埋进眉题、被大数字抢走，都会让用户复述错。

**主操作与价签克制。** 首屏视觉权重排序必须是：对象 / 产品身份 / P0 > 次级事实 > 购买按钮 / 价签。按钮可以醒目，但不得成为首屏最大字或最大色块；价签不得单独放大成 P0，除非 brief 把价格列为唯一决策事实。第四轮用户原话：「内容不如乙，乙的整体内容表达更准确，更合适」「产品的展示，内容表达不如乙」「购买按钮和价签有必要这么大吗？」。**画面手法只加分，不替代说得准。**

### 数字、感官词、行距（第五轮补）

第五轮布局已被认可（「整体布局应该都可以了」），三处内容区语义仍输，各立一条：

1. **数字必须带比较对象和轴向，裸数字不许放大当主角。** 「60mm」单独放大，读者猜它是厚度；「比 87 键短约 60 mm」才是事实。首屏最大的数字要一眼答得出「比谁、哪个维度」；答不出就改成带比较的句子，或用对比图（虚影 / 尺寸线 / 并排放）让事实自己说话。判法：把数字抄给没看过 brief 的人，问他这个数字在说什么——答错 = 回位次表改承载元素。原话：「你直接展示60mm就是为了表达产品薄？」
2. **感官词是 P2 证据，不是产品身份。** 风味 / 气味 / 手感词（柑橘 / 红茶 / 蔗糖）回答不了「这是什么产品」，只能小字长在对象上（包装标签、图注）或作次级支撑句，不得占内容区独立展示位。brief 把感官体验本身列为购买决策（如香水选香调）时除外。原话：「这能表达啥产品。」
3. **行距按阅读任务定，不得当填充。** 清单 / 账目 / 明细用紧凑行距（品类密度表取值）；只有长文阅读才放宽。不得为撑开内容区拉大行距或行间距——空了先问「这块空间该不该存在」，该删就删，不是填满。原话：「行间距反而被拉大了，不如乙图。」

### 文案表述：把事实说成看的人的话（第六轮补）

用户第四到六轮反复说「内容表达不如乙」，第六轮点明：「我说的内容是文案表述啊，你一直都没理解我的意思。」**「内容」在这套反馈里指文案怎么写，不是放哪个事实、摆哪里、多大字号。** 选对 P0 之后还有一层：把事实写成看的人读得进去的句子。

逐句对照（同一份 brief，基线 vs 技能臂）：

| 位置 | 基线（用户选） | 技能臂（用户否） | 差在哪 |
|---|---|---|---|
| 咖啡标题 | 换一种豆子，不用赌上一个月。 | 单品咖啡豆月度订阅 | 处境句 vs 品类名 |
| 咖啡来路句 | 喝惯了一种味道想换换，又怕踩雷——先喝一袋，合不合口味，你说了算。 | （无，直接报产地参数） | 接住顾虑 vs 对空气报参数 |
| 键盘标题 | 比 87 键短约 60 mm，把桌面右侧还给鼠标。 | 比 87 键键盘短约 60 mm | 事实 + 结果 vs 只有事实 |
| 记账标题 | 看清钱花在哪，账单不出这台机器。 | 这个月花在哪，一眼看完 | 两个结果 vs 一个 |
| 记账来路句 | 给记过账、但每次都半途而废的人。 | （无，01/02/03 编号分段） | 点出读者 vs 说明书目录 |
| 记账隐私 | 你自己的 iCloud | 用户自己的 iCloud | 「你」vs「用户」 |

三条写法：

1. **标题 = 一句对看的人有意义的话。** 写之前问「这句话在跟谁、说什么好处或处境」，答得出才落笔。命名式标题（产品名 + 品类）一律重写。结果句（给用户一个能带走的结果）可以当 P0，别把「P0 要具体」误读成「标题必须是数字或品类名」。
2. **首屏有一句接住来路的话。** 点出目标读者的处境 / 顾虑 / 身份，再给事实。这句来自「主来路 + 第一疑问」——来路假设写了就要兑现成文案，不是只写在记录里。
3. **用「你」，事实写成人话。** 不写「用户」；不把首屏写成「01 / 02 / 03」编号说明书。事实织进句子还是排成胶囊行/小表，看哪种读得快——不堆互不相干的标签，也不硬塞进密段落。规格表可以留在第二屏，首屏的话要像人说的。

**边界**：这是文案层，不改 P0 选哪个事实、不改布局与字号层级。标题变长后按既有层级自然换行，不为句子另起一套版式。

## 六、常见失败（都有真实出处）

| 失败形态 | 症状 | 根因 |
|---|---|---|
| **功能平铺** | 六宫格 feature，每格一样大 | 把"有什么"当成了"先说什么" |
| **答错题** | 首屏讲"我们很安全"，用户第一疑问是"谁吃了我盘" | 没写来路假设，P0 按产品视角而非用户疑问排序 |
| **主张前置** | 首屏写定位句，用户看不懂为什么要在乎 | 用主张当钩子，跳过了欲望层 |
| **信任物堆首屏** | 首屏塞 logo 墙 + 三个数字 + 两句话 | 不知道 P1/P2 该退到哪，全部塞进第一屏 |
| **平均分配** | 每块内容高度接近，没有一处明显更大 | 没有 P0，或 P0 不敢做大 |
| **空洞** | 内容少，还三等分铺开 | 见规则 5：应该把 P0 放大到占主体 |

四个失败里有三个会同时导致"不丑但不惊艳"。因为它们共同的特征是：**页面没有一处敢比别处大**。

## 七、出口判据

- [ ] 主来路只写了一个，第一疑问是一句具体的话
- [ ] 位次表里 P0 只有一条，能填进「这一屏我只要你 ___」
- [ ] 每条 P1 都能说出"没有它 P0 会被当成吹牛"的理由
- [ ] 删除清单 ≥3 条，每条三个字段都填了（尤其"移到哪"）
- [ ] 每屏都有唯一动作，没有"这一屏只是过渡"
- [ ] 首屏元素逐个点数，桌面 ≤7 / 移动 ≤5
- [ ] 首屏最大的那块图是**对象**不是**界面**：推广页放产品本身，不放要读坐标轴的分析图表，不放滑块/开关/导出一类工具面板（摘要卡可以）
- [ ] 首屏每一块小字念过一遍，同一条事实已合成一句话 / 一段话 / 一条带，没有「标签行 + 数字行 + 编号行」的堆叠
- [ ] 分隔线圈的是组，不是每一行
- [ ] 首屏三问（是什么 / 关键事实 / 多少钱或怎么买）能被没看过 brief 的人复述准确
- [ ] 视觉权重排序：对象/产品身份/P0 > 次级事实 > 主操作/价签；按钮/价签未压过产品身份
- [ ] 首屏最大的数字带比较对象和轴向，裸数字未放大当主角
- [ ] 感官词（风味/气味/手感）未占内容区独立展示位，只作对象标签或次级支撑
- [ ] 清单/明细行距按品类密度，未被拉大来填充空间
- [ ] 标题是一句对看的人有意义的话（处境/结果），不是「产品名 + 品类标签」；字号按用途定，产品面不用巨字
- [ ] 推广面首屏有一句接住来路的话，点出目标读者的处境或顾虑；产品面压成一行小字或省掉
- [ ] 用「你」不用「用户」；首屏事实一眼可扫（句子/胶囊行/小表随内容选），无编号说明书分段
- [ ] P0 与 S1 字段二的唯一任务是**同一件事**，不是"相关"
- [ ] 若 P0 是产品视角而非用户疑问，已写明用什么钩子把用户带过来

任一条不满足，不许进方向确认。因为一句话主张必须从主角事实推出来——主角事实是"给他看的"，主张是"我为什么这样给他看"，顺序不能倒。
