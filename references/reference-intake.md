# 参考准入：怎么判断一份参考能不能用

这份文件回答一个问题：**凭什么认为一份参考值得学？**

它不回答"这份参考好不好看"——那是判断，不是准入。它只回答"能不能从它身上提取出可用于账本的东西"，以及"提取时会不会编数"。

---

## 一、一个不能回答的问题

**"这个网页是不是 AI 产的？"——从像素判断不了。**

任何声称能看出来的，都是猜。AI 生成的页面可以极其像人做的，人做的页面也可以处处是模板默认值。以"是否 AI 产"做准入标准，会得到两个错误：把做得好的 AI 页扔掉，把人工做的平庸页收下。

所以**不要问来源，问支撑**。同一个检测换个问法：

> 这个页面的每一处取值，背后有没有一个可陈述的条件？

有条件的取值，不管是人是 AI 做的，都值得学；没有条件的取值，哪怕出自名家手笔，学到手也只是抄了个数字。

---

## 二、真实性的三个可测代理

问不出"是不是 AI 产的"，但能测出**"有没有被真实业务碾压过"**。被真实业务碾压过的页面，会留下模板不会长的东西。

### 代理 1：多余的具体

真实产品有大量"不需要存在、但存在"的细节，因为它们被真实客户逼出来的：

| 页面 | 多余的具体 | 实测 |
|---|---|---|
| Linear | 58 行功能对比表；4 个 SKU（不是"三档"） | `最大表行=58` |
| Ramp | 页面高 12,297px；110 行对比表；34 个折叠项；Enterprise 不标价只写 Custom | `docH=12297`、`折叠项=34` |
| Raycast | 每档都标年付价与实付额（`$120 $96 billed annually`） | 出现在三档中的两档 |

**模板不会长这些。** 模板生成的是"三档、中间推荐、四列功能、五条 FAQ"——每一处都通用，所以每一处都没有信息。

⚠️ 这一条只能证明"有人在这里花过力气"，不能证明"做得好"。它是**必要条件，不是充分条件**。

### 代理 2：内部一致性

真实页面的取值彼此咬合，模板页面的取值彼此无关。可查的三处：

- **字号层级是否成体系**：Ramp 的价格 28px 与档名 28px 同级，最大 48px 给"Compare Features"和"FAQ"——说明它的层级是按"信息重要性"排的，不是按"什么好看"排的。
- **留白是否与结构同步**：Linear 四列 padding 全部 `0 32px`、列间距 0（32px 内含），四列严格 336px。差 1px 就不成立。
- **重复元素是否真的相同**：三档的 padding 完全相同，只有一处不同（Ramp 推荐档 border 3px vs 1px）。**只有一处不同**本身就是一致性的证据。

### 代理 3：敢露短板

真实产品会写"Beyond 200 employees? Contact sales"、会写"Custom"而不编个价格、会在 FAQ 里回答具体到难看的边界问题。模板页倾向于所有档位都有漂亮的价格数字。

## 三、可信度分级：R0 到 R3

不同来源能支撑的结论强度差一个量级。**账本里的 V 编号必须标级别**，否则下游无法判断这条观察有多硬。

| 级别 | 来源形态 | 能支撑什么 | 不能支撑什么 |
|---|---|---|---|
| **R3** | 源码 / 官方设计文档 / 设计系统规范 | 取值与意图。可以引用具体规则 | 仍然不能证明"好"，只能证明"它是这样想的" |
| **R2** | **DOM 实测**（`scripts/probe.mjs`）：字号、间距、边框、颜色、盒模型 | 关系的精确值。"价格 16px""列间距 0，padding 内含 32px" | 测不出动机。测不出动效与滚动行为 |
| **R1** | 截图 + 人眼描述 | 布局关系、明暗、大致层级 | **具体数值一律不可信**。像素级比例、字号、间距都会被看错 |
| **R0** | 记忆 / 二手转述 / "我印象里某站是…" | 只能用来提出假设 | 不能进账本 |

**规则：R0 与 R1 不得产生数值。** 需要数值就去测，测不了就写"未测"，不许估。

这条规则的由来见本节末尾的「一次真实失败」。

## 四、提取纪律

### 1. 每条观察必须写成「关系 + 条件 + 代价」

不合格（裸数值 / 裸结论）：

```
Linear 价格 16px，不放大。
```

合格：

```
Linear 四档并列，价格 16px 与档名同级（价格/最大字号 = 0.22×）。
条件：受众是工程团队，横向比的是能力差异，价格不是决策依据；
      且页脚有 72px 的品牌语承担视觉记忆点，价格不必兼任主角。
代价：首次访客需要多花一步找价格；不适合按席位快速估算预算的买家。
```

**写不出"条件"的观察，本质上是偏好陈述，不能进账本。**

### 2. n < 3 不许归纳

一张页面上的做法是**一个样本点**，不是规律。想写"通常""一般都"，至少三个独立来源，且来源之间不能同源（见第六节）。

单来源结论必须显式标注 `n=1`，并且只能用于"这里有一种解法"，不能用于"应该这样做"。

### 3. 区分「分隔」与「强调」

这是最容易看错的一处，会直接导致设计做错。判据在盒模型上，肉眼分不出：

- **分隔线**：多档共有、同侧、同粗细。Linear 是"首列无左边框，其余各 1px `rgba(255,255,255,0.05)`"，容器高 551px = 整列通高。
- **推荐档强调**：**只有一档**偏离其它档。Ramp 是三档都 1px、只有中间档 3px。

两者的视觉后果完全不同：分隔线要**通高、与区块边界对齐**才成立；强调只需要"一处不同"。把 Linear 的分隔线误读成"零容器"，会得出"留白也能承担边界"的错误结论——而这个结论在多数场景下是错的。

## 五、反例的正确用法

坏参考有用，但**只能当反例，且必须写明它在什么条件下失败**。

不合格的提取：

```
紫色渐变横幅 = AI 味，禁止。
```

合格的提取：

```
某定价页首屏用紫渐变 + 倒计时 + "5000+ 团队选择"横幅。
失败条件：受众是工程团队、正在评估技术方案，此时促销语气与"我们在讲事实"冲突，
          横幅使首屏可信度下降。若受众是促销敏感的价格买家，同一手法可能有效。
可迁移结论：横幅本身无罪；罪在"语气与受众的信任建立方式不匹配"。
```

**差别在于：前者给出的是黑名单，后者给出的是判据。** 黑名单会把好产品一起禁掉（见 SKILL.md 硬纪律四条）。

反例入库时，记两件事：`在什么条件下它是对的`、`在什么条件下它失效`。只记后者，下次会在前一条件下误伤。

## 六、样本同源性：比"抓到 AI 垃圾"更常见的偏差

用户担心的是"抓到坏页"。实际更高频的偏差是：**三份参考其实是同一个东西**。

Linear / Ramp / Raycast 三张实测放在一起，共性很明显：

| 维度 | 三张的共同点 |
|---|---|
| 品类 | 全是 SaaS / 开发者工具 |
| 受众 | 全是英文、技术或财务决策者 |
| 明暗 | 两张深色、一张白底极简 |
| 语言 | 全英文 |
| 版式 | 全是单栏纵向 + 分档并列 |

**用这三张做参考，做出来的东西一定像 Linear。** 哪怕每一张都测得准。

所以选参考时要检查**覆盖缺口**，不是检查"每张都好吗"：

- 有没有一张是**中文**的？中文的字符密度、行高、标点、断行规则与英文完全不同。
- 有没有一张是**高密度**的（后台、控制台、数据表）？三张都是营销页。
- 有没有一张是**消费级**的（电商、内容、社区）？三张都是 B 端。
- 有没有一张是**移动优先**的？三张都只测了 1440 桌面。

有缺口就明写"本次参考在 X 维度上缺失"，并在账本里把相关决定标为"无参考支撑，属假设"。**承认缺失比假装覆盖安全。**

## 七、准入清单（逐条打勾，缺一条就降级）

一份参考能用，需要同时满足：

- [ ] **来源可溯**：有 URL、有抓取日期、有视口尺寸。截图存在本地可复核
- [ ] **有业务压力痕迹**：至少一处"多余的具体"（超额 SKU、超长对比表、年付切换、Custom 不标价、具体到难看的边界问答）
- [ ] **提取出了条件**：每条观察都写得出"在什么条件下成立"。写不出的不算观察
- [ ] **数值有出处**：所有数字来自 R2/R3，或显式标"未测"。没有 R0/R1 数字
- [ ] **标了级别**：`V-n` 后注明 R2 / R3
- [ ] **有覆盖缺口说明**：本次参考缺哪一维度

降级处理：

- 缺「提取出了条件」→ **不可用**。它只是壁纸，看一眼可以，不能进账本
- 缺「数值有出处」→ 降为 R1，只能定性描述，禁止写数字
- 缺「来源可溯」→ 降为 R0，只能用来提假设

---

## 八、与账本、与 brief 的接口

- **V 编号**写在 `00-brief.md` 字段六，格式：`V-a1 (R2) Linear：四档价格均 16px…`
- 账本「依据」列引用 `V-a1`，不重复描述。这样改参考时只需改一处
- **一条 V 只能支撑一条账本行**。若一条观察被三行引用，说明这三行其实是同一个决定，应合并
- brief 字段六必须回答："本次参考缺什么"。不写视为未完成

## 附录：一次真实失败（本文件的由来）

2026-11-10，三张定价页参考入库时，基于**截图 + 读图描述**写了六条观察。次日在同一 URL、同一视口做 DOM 实测，四处被推翻：

| 当时写的 | 实测 | 误差性质 |
|---|---|---|
| Linear「四档零容器，无边框无底色无阴影」 | 首列无左边框，**其余各 1px** `rgba(255,255,255,.05)`，容器通高 551px | **结论反向**——它是有线的，且靠"通高 + 严格共轴"成立 |
| Linear「价格 16px **与档名同级**（约 20/20）」 | 价格 16px，档名字号未测；价格/最大 = 0.22× | 半对：16px 对，"同级"是补出来的 |
| Raycast「价格 `$8` 约 **44px**，档名 18px，2.4×」 | 价格 **64px** w600；除价格外全页无 ≥26px 文本 | 数值错，倍数错 |
| Ramp「上面两行 **64px** 的标题才是主角」 | 最大 **48px**，且是页面中段 "Compare Features" 与 "FAQ"，不是首屏标题 | 数值错，位置错 |
| Ramp「列间距 ≈ 行距 2.4 倍」 | 列间距 **0**，32px 是 padding 内含 | **凭空生成** |

三张参考本身没错，都是真实上线页。**错在提取：把"看"当成了"量"。**

这就是本文件存在的理由：**参考的可靠性不由"选得好"保证，由"能否复核"保证。** 无法复核的观察，无论写得多专业，都是印象——而印象会被自动补全成看起来很精确的假数字。

工具：`scripts/probe.mjs`（R2 取证）。测不了的，写"未测"。
