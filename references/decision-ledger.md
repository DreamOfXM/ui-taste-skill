# S3 记账：六列决策账本

输出的文件是 `design/02-ledger.md`。

这是整个 skill 的核心机制。宝玉那套是把「画什么、写哪几个字」提前定死（structured-content schema），这里把**"为什么这么定、付了什么"**提前定死。

区别在于：schema 只管"填了没有"，账本管"填的东西站不站得住"。

---

## 表结构

```markdown
| # | 决定 | 取值 | 依据 | 换来 | 放弃 |
|---|------|------|------|------|------|
```

### 列定义

**决定**——被决定的东西，粒度到"一处视觉属性对一个元素的作用"。粒度太粗（"整体风格"）无法检验，太细（"第二个按钮的左边距"）会淹没重点。合适的粒度：一页 8–15 行。

**取值**——具体到可写进代码的值。颜色给 hex 或 oklch，尺寸给 px/rem，字体给字族+字重+字号。禁止"柔和一些""稍微大点"。

**依据**——必须回指上游编号：
- `T1` `T2` `T3` — thesis 的三条承诺
- `R1`–`R3` — register 的标志手法/禁忌
- `C1`–`Cn` — brief 的内容事实
- `V1`–`Vn` — brief 字段六的视觉观察（外部依据，必须真实看过）
- `F1`–`Fn` — craft-floor 的地板项（这类行"放弃"列可写"无，此为地板"，是唯一例外）

只有内部编号时，账本可以完全自洽而平庸——模型最擅长在自己的想象里闭环。`V` 行是把外部优秀画面拉进来的通道。

写"更好看""更现代""更协调""符合审美趋势"→ 该行作废。

**换来**——用户可感知的结果。合格的词：对齐、层级、可扫读、可印刷、手指不误触、首屏信息量、加载更快、眼睛不累、截图能独立成图。

**放弃**——牺牲了什么具体体验。必须有主语。

---

## 判定：什么叫"有效行"

一行有效，需要同时满足：

1. 依据是编号引用
2. 换来是可感知结果
3. 放弃有具体主语（或属于地板项）
4. 与同维度其它行不冲突

**任一不满足 → 该行作废，从账本里删掉重填。** 不要保留"待改进"的行，那会让整本账失去约束力。

---

## 示例一：有效行

**0.2.5 更正**：0.2.4 及之前这里给的是 `| 3 | 页面底色 | #FBFAF7（暖白，非纯白） | … |`，并附了整段「为什么有效」。它是全 skill 里唯一一条现成的有效行示例，于是被反复照抄：定价页 `#FBFAF7`、DiskWise `#F4F3EF`，而同期两条 R2 实测参考都是深底。**一条示例值被当成全站默认值，是模板层的机制缺陷。** 现在示例不写死色值，改成指向用户选定的配方：

```markdown
| 3 | 表面配方 | **S1 暗夜仪表**（G0 组合甲，用户选）：底面 `#0D1016` / 卡面 +6% 白 / 墨 `#E8EAF0` / 线 `rgba(255,255,255,.10)` / 无纹理；七项成组 | `00-direction.md` 用户原话 + V1(R2) 实测 `rgb(13,16,22)` | 与官网及产品深色截图同一世界，接缝消失；暗底上 1px 线仍能分块 | 放弃 S3 暖纸的长文亲和；手上浅色截图必须重做取景，否则出现白补丁 |
```

为什么有效：
- 依据指向 **G0 的用户选择**与 R2 实测，不是「这样比较好看」
- 七项成组落地，不是只改一个 `--paper`
- 换来可感知（接缝、分块），放弃有主语且承认了新风险（白补丁、长文亲和）
- **不预设色值**：换成 S2/S4/S6 时同一行照样成立，只要指回 `00-direction.md`

最后半句"承认风险"很重要——**账本不是辩护词，是记录。** 一行只写好处不写风险的记录，是广告。

## 示例二：作废行（这是最常见的失败形态）

```markdown
| 7 | 卡片圆角 | 12px | 看起来更现代 | 更柔和 | 无 |
```

三个问题：
- 依据"看起来更现代"不是编号引用，也无法反驳
- 换来"更柔和"不是可感知结果，是形容词
- 放弃"无"——**说不出代价，说明这不是选择，是默认值**

12px 圆角是组件库的默认值。写这一行的真实过程是"没想过，顺手拿了默认"。作废之后必须重填，重填的正确形态例如：

```markdown
| 7 | 圆角体系 | 全站两档：6px（控件）/ 999px（头像、标签） | T2 | 曲率家族统一后，按钮、输入框、卡片属于同一套语言，用户不用靠颜色区分"可点"与"不可点" | 放弃 12–16px 大圆角带来的柔和产品感；在消费类语境里会显得偏硬 |
```

区别不在数值，在于第二行**知道自己放弃了什么**。这就是 skill 存在的意义：把"顺手拿默认"变成"我选了这个，代价是这个"。

## 示例三：地板行（唯一允许"放弃"写无的形态）

```markdown
| 11 | 正文对比度 | ≥4.5:1，正文色 #2B2A26 on #FBFAF7 = 13.76:1 | F1 | 强光下、低质量屏上仍可读 | 无，此为地板（F1） |
```

地板项不参与取舍，不占"品味"额度。它们单独放在 `craft-floor.md`，理由见该文件开头。

## 维度清单（防止漏项）

一页至少覆盖这些维度，每维度 1 行：

底色 / 文字主色 / 次要文字 / 强调色 / 字体家族 / 字号层级 / 间距节奏 / 圆角体系 / 边框与分隔 / 阴影或替代手段 / 首屏构图 / 主操作样式 / 状态反馈方式
**+ 0.2.5 新增：表面配方编号 `S_`（含七项成组值）/ 方向确认状态（指向 `00-direction.md`）/ 密度契约（版心上限、两栏内容高度差上限、每块空白的用途、section 最小填充率）**
**+ 0.2.6 新增：品类 `C_` 与默认家族一致性（十二项逐项比对）/ 文案组织（栏目顺序，写实际顺序，标明偏离项）/ 按钮形状与字重 / 字体字距 / 首屏图文比（文字量 : 图片数）**

漏掉的维度会自动落回默认值，而默认值是这个 skill 最想消灭的东西。**没写进账本的维度，等于把决定权交给了组件库。**

### 0.2.6 加这几维的原因

上一轮交付被说「跟预期差距很大」，用户点名的六个具体项——**背景色、文字组织、按钮形状（矩形还是圆角）、字体颜色/大小/样式、线框、排版样式**——在 0.2.5 的账本维度清单里只覆盖了两个半。缺的一半（文案组织、按钮形状、字距、图文比）全靠默认值，而默认值就是「通用模板」的另一个名字。

- **品类与默认家族一致性**：不是「写个 C1 就算过」，是十二项逐项比对——底面、卡面、墨色、字体族、字号、行距、按钮、曲率、线宽、版心、密度、图文比。哪一项偏离了，那一行必须在「放弃」列写代价。
- **文案组织**：写实际栏目顺序（「首屏 → 成分 → 质地 → 引用 → 规格 → 提示」），不是写「结构清晰」。品类决定了栏目顺序，换品类必须换顺序。
- **按钮形状与字重**：一个值 `r8 / 高 36 / w500 / 实心`。美妆是 `r0 / 高 36 / w400`，母婴是 `r12–32 / 高 40–48 / w600`，C9 是 `pill / 高 44 / w400`。这四个品类放一起，按钮差一眼就能认出。
- **首屏图文比**：`≤300 字 : 1 张真实界面`（C1）与 `≥700 字 : 7 张商品图`（C2）是两套完全不同的页面，不写进账本就一定会写成同一个。

### 新增三维为什么要单列（两轮实测的教训）

- **表面配方 / 方向确认**：0.2.4 之前底色既没有货架也没有出口，模型用 `scale.md` 的暖色相纪律 + 这里的示例值直接定死，用户到交付才第一次看到。
- **密度契约**：`05-whitespace-audit.md` 实测，内容从 3289 字砍到 1552 字后，版心仍是 1240px、两栏内容高度差 377px，三段左栏填充率只有 9% / 11% / 15%。**没有任何一步有权决定「减完内容后版心该多宽、空白有没有任务」**——S2 骨架只管顺序、S3 刻度只管数值落在格子上。所以这一维必须显式写进账本，每块空白都要写用途（分组 / 呼吸 / 对齐 / 等待内容），写不出用途就删掉。

## 出口判据

- ≥8 行有效行（复杂页面 12–15 行）
- 维度清单全覆盖，或明写"本页无此项"
- 「放弃」列无空值（地板行除外）
- ≥2 行的取值与"裸默认"不同，并在文件末尾单列一段说明差在哪
- **0.2.5**：`表面配方编号 S_` 与 `方向确认状态` 两行必填；后者写「用户原话 / 明确授权 / incumbent 实测来源」，**不许写「按 brief 推定」**
- **0.2.5**：`密度契约` 一行必填；选 S3 暖纸时额外写一句「不是因为它是默认」

最后一条是自查：如果全部取值都和默认差不多，说明 S2 的主张没落地，回 S2。
