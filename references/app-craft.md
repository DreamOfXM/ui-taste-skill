# 软件工艺：让工作界面本身好看

只读当前平台与待解决问题。构图、参考选择和复查预算遵循主入口，不再重跑一套流程。

## 精密与愉悦，也是一种强表达

让真实工作对象成为画面主角，不拿营销页缩小充数。软件的美感可以来自精密列位与舒展检查器的对照、细分表面上的清楚字阶、漂亮的真实缩略图或图形，以及对象切换时的连续反馈；不是只能做到不杂乱。

先选一个值得打磨的完整关系，例如“选中资料后，列表稳定，预览获得更大空间，标题、状态与工具共同围绕它组织”。把默认、选中和展开做成同一套语言；高级感来自这些细小决定共同成立，不是逐个控件贴品牌色。

前沿技术只是实现手段：可变字体、容器查询、共享元素过渡、原生新材质等，应解决确切的字形、密度、连续性或层次问题。先核实目标平台支持与项目性能预算；不为使用新API引入整套依赖，也不把不支持的环境留成空白。静态与减少动态状态必须仍完整可用。

## 平台与尺度

| 平台 | 设计依据 | 验证重点 |
|---|---|---|
| 桌面原生 | 窗口、工具栏、菜单、键鼠、列表与检查器；系统逻辑点 | 窗口缩放、快捷键、焦点、原生状态与辅助功能 |
| 移动原生 | 安全区、触达、返回/手势、键盘与文字缩放 | 对象到详情再返回；键盘不遮操作；目标设备实际运行 |
| Web 工作台 | 路由、浏览器历史、加载与网络状态；CSS布局 | 不同窗口宽度、键盘、滚动、展开面板 |

原生控件是好起点，不是必须重写的阻碍；项目组件妨碍任务时才替换。核实系统版本和 API 后再使用新材质。HTML 模仿外观不证明原生可用。

### 同一个产品，分别组织桌面与手机

先写“选中谁、正在做什么、完成后回到哪里”，再选容器。同一对象、状态与材料可以跨平台，区域排布和操作姿势不必相同：

| 任务关系 | macOS 起点 | iOS 起点 | 必须实看的一组画面 |
|---|---|---|---|
| 在集合中反复切换对象 | 导航、集合与内容同时可见；选择驱动内容，工具栏归属当前窗口 | 集合进入详情；返回恢复对象位置，不把桌面三栏挤进手机 | 默认、另一对象、返回；主对象与选中反馈是否对应 |
| 调整对象属性 | 可收起检查器，尽量保留工作对象可见 | 少量属性就地改；需要专注输入时才开编辑面板 | 编辑前、键盘或检查器打开、保存后；对象是否仍可辨 |
| 深入观看或阅读 | 让工作内容得到连续空间；导航退后但仍可达 | 内容随滚动展开，系统返回与局部动作稳定 | 正文或画布、局部操作、返回；不只检查封面 |

这不是要求每个应用都三栏。SwiftUI 可从 `NavigationSplitView` / `NavigationStack`、`List(selection:)`、`toolbar`、`sheet` 等平台容器出发；AppKit/UIKit 沿用等价导航与选择语义。先运行一条最短真实流程，再定制表面与排印，避免完成整套皮肤后才发现容器破坏布局。

### 原生的精致落在内容与系统边界上

- **桌面**：窗口标题、工具栏与内容只保留必要层级，避免另画一条网页式巨型页头。用普通、选中与长名称三行一起校准图标轴、文本轴和状态轴；内容面比导航更舒展，但不把空面板当留白。缩窗时明确哪个区退场，保留正在处理的对象。
- **手机**：在真实安全区里排第一项对象与详情，按内容而非设备框决定图像裁切。正文用可缩放的语义字阶；自定义字号与空间随文字尺度校准。大字时让横向元信息转行，不能靠缩字、截断正文或固定行高维持截图。
- **编辑**：批注、命名等临时输入与已保存内容分开。键盘打开时，标题、输入与提交形成同一工作区；保存后把新内容放回原对象，取消不偷偷保存。不要让确认提示遮住刚产生的结果。
- **材料**：系统图标、原生控件和自定义图像需要相同的视觉重量；看选中态，而不只看默认态。材质按目标平台与层次职责选择，不把所有透明与阴影限制为导航或浮层；长正文和密集数字需要稳定的阅读表面。没有支持背景变化的实拍，不用静态色块声称验证了材质效果。

这些是设计起点，不是固定皮肤；用实际窗口、系统大字与输入状态淘汰不成立的组合。

### 把控件做成有表现力的原生样片

先在真实关键屏里选一组高频控件：工具栏或按钮组、普通与选中列表项、输入及提交。为它们确定共同的图标重量、形状、材质层次与强调色；同时看默认、按下、选中、禁用和键盘打开后的关系。不要另造一个脱离产品的控件展板，也不要把“原生”理解成不加判断地接受全部默认值。

- **让颜色有主次**：从内容或品牌选有辨识度的强调色，先落实在主要动作和选择反馈；用中性表面衬托，不让所有按钮同样抢眼。选中状态还要有形状、图标或标记，不能只换色。想更有表现力时，比较同一组控件的中性材质与着色材质，不靠增加颜色数量证明美感。
- **按平台兑现玻璃**：用户要求 Liquid Glass 且目标 Apple 系统支持时，先核对当前 SDK 的原生控件与材质 API，在真实工具栏、按钮或浮层中试用；系统已提供材质的容器不重复包玻璃。其他平台不冒用同名效果；旧系统沿用可用的原生表面。正文和密集数据保持稳定阅读层，不把整页透明当作精致。
- **用背景变化验证材质**：让同一控件分别经过真实图片与文字背景，保留滚动前后画面，检查透射、边缘、文字和图标是否仍清楚。空白底上的半透明填色不能单独证明液态玻璃；按压、过渡与打断要实际操作，静态截图不证明动态效果。减少透明度、减少动态和明暗外观未实测就标待验证。
- **让状态转换也漂亮**：点击收藏后，按钮表达与收藏集合一起变化；保存后，批注回到原对象；取消后，草稿不污染已保存内容。分别看操作前、操作中、完成后，检查控件是否跳位、反馈是否遮挡结果、返回是否丢失位置。验证辅助功能树实际暴露的名称、状态和结果，不把测试脚本预想的某个属性当平台事实。

先回答“这组控件哪种可见关系比默认拼装更出色”，再推广其余页面；若只能说测试通过或用了新 API，审美目标仍未得到证明。保留用户认可的内容与构图，把精修预算花在真实可见的差距，而非不断加装饰。

## 工作面比例

先分配导航、对象集合、当前对象、局部操作与临时反馈的位置，只保留任务需要的区。壳层帮助定位，内容承担工作；重复统计和第二条巨大标题带需要证明其作用。

以下是约1120×760中文桌面列表的起始实验，不是平台标准：

```text
导航192–224；工具栏44–52；可收起的检查器260–320。
页标题20–24；对象名13–14；辅助信息12–13。
普通行40–48；对象内间距约8；组间20–24。
```

用实际字体、长名与缩窗修正初值。展示首屏、密集列表、设置页不必同密度；统一的是文字角色、对齐逻辑和状态语义。Web px 与原生逻辑点不机械互抄。

检查器打开时保留当前选择与列表上下文；窄窗明确选择收起、转详情页或局部滚动，不挤到不可读。能合理横向滚动的数据表不必为避免滚动而删列；避免无意的双层滚动。

## 先把一个对象做好

- 对象名优先，说明次之；完整长名可达，中文与混排都检查。
- 同类数值对齐，适用时用等宽数字；单位、缺值、数量级分工清楚。
- 图标视觉尺寸与笔画一致，不给每个图标加彩色底块掩盖重量差。
- 名称、格式、状态不重复讲同一件事；标签与值要靠近。
- 对象间用行距、轻分隔与分组建立节奏，外框不是默认容器。

列表先验普通行、选中行和长内容行；画布先验对象与检查器；移动先验一条详情及返回。具体排布可看[索引示范](../assets/reference-workbench.html)，局部关系对照可看[Fold实验室](../assets/app-craft-lab.html)，两者都是HTML教学而非原生标准。

## 状态与表面

默认、悬停、焦点、选中、禁用含义不同；悬停不能抹掉选中，焦点必须可辨。关键语义由文字或形状共同承载，不只靠颜色。常用操作位置稳定，不依赖悬停才能发现。

底层、工作面、浮层分清，不让所有东西同时浮起。深色界面尤其检查次要文字与相邻表面对比；浅色界面不要用不可见边界和灰字假装安静。品牌、操作与危险状态各有职责。材质可以丰富，但要给内容留下安静区域，并适配减少透明度等平台设置。

## 动作与迁移

选一次有意义的动作打磨，如展开对象、收藏、完成任务。先确定起点、终点和反馈，再决定动效；过渡可从120–220ms试起，按距离与平台调整。高频工作页直接进入可用状态，不逐卡入场；尊重减少动态，测试打断与重复操作。

长任务显示真实状态；取消只在底层支持安全中断时出现。没有真实进度就不要画假百分比。

焦点跟随完成后的状态，而非点击时的旧节点。路由或列表重绘后再恢复目标；实际点选、返回，等待重绘稳定后核对活动元素仍是可见、可用的目标，不能只看一次 `focus()` 调用或瞬时截图。先验证平台原生行为；会替换内容的对话框逐阶段实按 Tab 与 Shift+Tab，检查循环边界、Escape/取消语义及关闭后的触发点恢复，不因用了原生 dialog 就跳过，也不默认重写所有原生焦点管理。

关键屏成立后检验最密集工作页、详情和设置等实际相关页面。空数据、错误、长名称、极值、窄窗与输入状态按范围覆盖。先看整组缩略图判断一致性，再逐页原尺寸查看；不能把同一张卡片复制给所有任务。
