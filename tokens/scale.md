# tokens/scale：数值刻度

> **0.2.4 起：这张表是「所选配方内部」的格子，不是全站唯一一套。**
> **0.2.5 起：颜色段同理——色值来自 G0 选定的 `registers/surface-recipes.md`（S1–S6），本表不再规定全站底色。**
> S2 先从 `registers/type-recipes.md` 选一套配方（P1–P6），再用本表把该配方的取值收进格子。
> 下方「字号」表里的行高是 **P1 图纸配方**的基准（display 1.05–1.1 / body 1.6）；选 P2 书卷用 1.80–1.90、选 P4 终端用 1.40、选 P3 柔光用 1.55，**并在账本写明为什么这套节奏适合本场合**。
> 拿 P1 的行高表去套所有配方 = 没选配方，所有页面会继续长成同一副脸。

S3 记账时查这张表。它的作用是**把"随手值"变成"体系值"**。

随手值（13px、5px、18px、1.5px 边框）是"没有体系"的物证。它们单独看都合理，放在一起就让页面显得"说不上哪里不对"——因为人眼对节奏的偏差极其敏感，却说不出来。

---

## 间距

基准 4。允许值只有八档：

```
4  8  12  16  24  32  48  64  96
```

**禁用**：5、6、7、10、14、18、20、28、36、40、56。这些值不构成节奏，只构成噪音。

用法约定：
- 组件内间距：4 / 8 / 12
- 组件间间距：16 / 24
- 区块间间距：48 / 64 / 96
- 同一层级用同一个值。**区块间距只有两种值时，页面就有节奏；有五种值时，页面就散。**

---

## 字号

十一档，命名为用途而非尺寸：

| 用途 | 值 | 行高 |
|---|---|---|
| display | 48 / 38 | 1.05–1.1 |
| h1 | 30 / 24 | 1.15–1.25 |
| h2 | 20 | 1.3 |
| body-lg | 16 | 1.55 |
| body | 14 / 15 | 1.6 |
| caption | 12 | 1.5 |
| micro | 11 | 1.4（仅用于标签，不用于句子） |

**禁用**：13、17、19、22、26、28——这些值会让层级变得"半级半级"地模糊，用户分不清哪两级是同一层。

**规则**：一页最多 6 档字号。超过 6 档说明层级没想清楚，是靠字号大小硬撑。

---

## 字重

只用 400 / 500 / 600 / 700。中文尤其要注意：**中文的 500 和 600 常常渲染成同一个字重**，所以中文界面里"用字重区分层级"最多只有 3 档可用（400 / 600 / 700）。

这是中文 UI 与英文 UI 的一个实质差异，也是照抄英文设计系统会翻车的地方。

---

## 圆角

八档：`0 / 2 / 4 / 6 / 8 / 12 / 16 / 999`

**规则：一页最多 2 档 + 999（用于头像、标签、胶囊按钮）。**

超过 2 档，页面就失去了"曲率家族"的统一感——用户会下意识觉得"这些控件不是一套的"。

常见错误：按钮 6px、输入框 4px、卡片 12px、弹窗 16px、标签 999px。五档。看起来每处都合理，整体是散的。

---

## 边框

- 常规：`1px`
- 强调/分隔：`2px`
- **禁用 1.5px**：非 Retina 屏上会渲染成 1px 或 2px 不均匀

颜色：`rgba(0,0,0,0.08)` 一类的低不透明度，不要用纯灰 hex——纯灰在不同底色上会显得脏。

---

## 阴影

只允许三档，且必须有明确的光源叙事（"东西浮在纸上方 2mm"）：

```css
--shadow-1: 0 1px 2px rgba(0,0,0,0.04);                                  /* 贴地 */
--shadow-2: 0 2px 8px rgba(0,0,0,0.06), 0 1px 2px rgba(0,0,0,0.04);      /* 浮起 */
--shadow-3: 0 8px 24px rgba(0,0,0,0.08), 0 2px 6px rgba(0,0,0,0.04);     /* 模态 */
```

**禁用彩色阴影**（`0 4px 14px rgba(99,102,241,0.4)` 一类）。它是 AI 味的头号标志：既没有物理依据（光源很少是紫的），又会让元素边缘发脏。

如果需要一个元素"跳出来"，优先用**描边 + 留白 + 底色差**，而不是加深阴影。

## 颜色

**0.2.6 更正（再往前一步）**：0.2.5 把色板交给「六套表面配方」，仍然跳过了「这是什么产品」。色板的**第一来源是品类**：先由 `registers/category-prototypes.md` 判定 C1–C9，取该品类的底面 / 卡面 / 墨色 / 曲率 / 密度，再由 `registers/surface-recipes.md` 的 `S1–S6` 把这些落到具体手法。

因此本段只给三条**跨品类通用**的纪律：

1. **同一页的材质做法必须同族**。底面、卡面、墨色、线、曲率五项一起换。只改一个 `--paper` 变量会产生白补丁（留白诊断消融 E2 已验证）。品类之间可以完全不同（C4 美妆 `#FFFFFF` + r0，C5 母婴 `#F8F5F1` + r32），页内不许混。
2. **强调色只用一个色相**。需要多级时，在同一个 oklch 色相上改明度/彩度，不要换色相。换色相 = 两套品牌。C8 食品允许高饱和品牌色占大面积，C1 开发工具只许一处强调。
3. **主色能不能当文字色，必须实测对比度**，不能看感觉。见 craft-floor F1 的脚本。换品类或换配方后**必须重算**：暗底上的低饱和浅灰、彩底上的白字、纯白上的 `#9CA3AF` 最容易翻车。

**不在这里给默认色值。** 任何具体色值都必须能在 `00-direction.md` 里指回一套用户见过（或明确授权自主）的组合，并且能指回一个品类。

## 动效时长

| 类型 | 时长 | 缓动 |
|---|---|---|
| 状态反馈（hover、按下） | 120–160ms | ease-out |
| 元素出现（tooltip、下拉） | 160–200ms | ease-out |
| 区块入场 | 300–420ms | cubic-bezier(.２, .8, .2, 1) |
| 页面切换 | 400–500ms | 同上 |

**禁用 linear**。线性缓动让所有动效"发木"，是"有动效但显得廉价"的主因。

---

## 在账本里怎么引用

账本「取值」列直接写刻度值，不写"大一点"：

```markdown
| 5 | 区块间距 | 96 / 64 两档（首屏 96，其余 64） | T1 | 首屏呼吸感强于后续区块，视线上移有节奏 | 放弃统一间距带来的整齐感；滚动时节奏会有一次突变 |
```

如果某处确实需要刻度外的值，必须在账本里单列一行说明为什么，并计入"与默认不同"的行数。
